# Java KB: правила для агентов

База для подготовки к собеседованиям на Java backend, уровень middle+ с выходом на senior. Пользователь изучает по ней темы и повторяет вопросы. Всё в базе меняется через агента: пользователь просит обычными словами, агент правит файлы.

**Главное — качество.** Тема должна объяснять механизм глубже хорошей статьи, показывать его на настоящих схемах и готовить к вопросам собеседования, включая уточнения senior-уровня. Страница, формально собранная из правильных блоков, но поверхностная, — брак, даже если проверки проходят. Что считается хорошей темой и как к ней прийти — в `docs/authoring/quality.md`.

## Где что лежит

- `assets/topics.js` — реестр: дерево папок и тем, порядок, `scope`, частота, статус.
- `topics/<id>.html` — заполненная тема; `topics/_template.html` — заготовка со всеми блоками.
- `assets/search.js` — поисковый индекс, генерируется, руками не править.
- `assets/kb.js`, `assets/kb.css` — движок: колонки, поиск, оглавление, прогресс, схемы. При работе с содержимым не трогай.
- `tools/build_search.py` — сборка индекса; `tools/check_kb.py` — проверка связей и предупреждения о качестве.
- `docs/authoring/` — гайды для авторов.

## Что читать

| Задача | Читать |
|---|---|
| Добавить, убрать, перенести, переименовать тему или папку; перестроить папку | `workflow.md` |
| Заполнить или переписать тему | `workflow.md` → `quality.md` → `types.md` → `illustrations.md` → `blocks.md` → `review.md`, плюс эталон своего типа целиком |
| Дописать шаг, вопрос, задачу, схему | `quality.md`, `blocks.md`, `illustrations.md` для схем, `review.md` |
| Ответить на вопрос пользователя по теме | `workflow.md`, раздел «Пользователь спрашивает по теме» |

Все файлы — в `docs/authoring/`. Читай их целиком, а не выборочно: планка и признаки брака описаны именно там.

## Неподвижные правила

- У заполненной темы не меняй `id`: по нему хранятся прогресс и ссылки. Существующие `id` шагов и карточек тоже сохраняй.
- `status: 'ready'` ставит только пользователь или агент по его прямой просьбе.
- Структура — решение пользователя. Перестройку папки или разбиение большой темы сначала покажи в чате вместе с судьбой старых тем и дождись согласия.
- Одна тема за раз: исследуй, напиши, проверь, закоммить — и только потом следующая.
- Не отдавай тему, пока не прошёл `review.md` целиком: код запущен, схемы отрисованы и просмотрены по шагам, чек-лист выполнен. Что проверить не удалось — назови пользователю.
- После любой правки: собери поиск, запусти `check_kb.py`, сделай один коммит на одну тему или перестройку.
