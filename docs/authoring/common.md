# Общие правила работы с базой

Общий сценарий выбирай по просьбе пользователя. Маршрут чтения остальных файлов описан в корневом `AGENTS.md`.

## Сценарии

Найди сценарий, похожий на просьбу, и выполни его шаги. После любой правки выполни проверки из `validation.md`.

### Добавить, убрать, перенести или переименовать тему или папку

Правится только реестр.

- **Добавить тему** — строка в нужной папке, `status: 'empty'`. Файл не нужен, пока тему не заполняют.
- **Добавить папку** — `{ id, title, items: [...] }` в нужном месте.
- **Перенести** — вырезать строку и вставить в другую папку. `id` не меняется, файл остаётся на месте.
- **Переименовать** — поменять `title`. У заполненной темы поправь и `<h1>` в файле.
- **Убрать** — удалить строку. Файл заполненной темы не удаляй без прямой просьбы: в нём материал и к нему привязан прогресс.

`id` заполненной темы (`status` не `empty`) не меняй никогда: по нему хранится прогресс пользователя.

### Перестроить папку по курсу, книге или роадмапу

Например: «разбей многопоточность, как в курсе X».

1. Найди оглавление источника: открой страницу курса, книги, роадмапа. Не получилось — попроси пользователя прислать оглавление или ссылку.
2. Предложи новое дерево в чате: папки, темы, что в каждую входит (`scope`). Отдельно покажи, что происходит со старыми темами: какая куда переехала, какая объединена, какая удалена.
3. Дождись согласия. Структура — решение пользователя.
4. Примени. Заполненные темы сохраняют `id`: их можно переименовать и перенести, но не пересоздать. Пустые темы можно свободно переименовывать, склеивать и удалять.
5. Запиши у папки, откуда структура: `{ id, title, source: 'Курс X, модули 1–8', items }`. Поле `source` ни на что не влияет в интерфейсе, это заметка для следующих правок.

### Заполнить тему

1. Определи тип темы (нужный файл типа темы в этой папке) и прочитай эталон этого типа целиком.
2. Если пользователь назвал источник — курс, книгу, статью, свои заметки, — строй урок по нему: его порядок, его примеры, его акценты, пересказанные своими словами. Источник поставь первым пунктом в `.refs` с пометкой «основа урока». Если источника нет — выбери сам и тоже укажи.
3. Скопируй `topics/_template.html` в `topics/<id>.html`, поставь `data-topic`, `<title>`, `<h1>`. В реестре смени `status` на `'draft'`.
4. Собери страницу из блоков. Шаблон показывает все блоки, но обязательны только урок из шагов и вторая часть. Ненужные блоки удали, а не оставляй пустыми.
5. Проверь всё проверяемое (раздел «Язык и точность» ниже).

### Дописать тему

«Добавь вопрос про …», «добавь шаг про …», «сделай схему для …», «добавь задачу».

- Новый шаг урока — `section.step` в нужное место `.lesson`. Номера и оглавление пересчитаются сами.
- Новый вопрос или задача — `article.q` в `section.interview`. Не повторяй вопросы, которые уже есть. Если для ответа не хватает материала в уроке, допиши и урок.
- Схема, ловушка, «Под капотом» — внутрь того шага, к которому относятся.
- Существующие `id` шагов и карточек не меняй: на них ведут ссылки и завязан прогресс.

### Пользователь читает тему и задаёт вопросы

Вопросы приходят обычным сообщением в чат, часто со ссылкой на тему или цитатой. Ответь в чате.

Если пользователь просит сохранить ответ («допиши», «сохрани в тему»), реши, куда он лучше ляжет, и скажи, куда положил:

- **В урок**, если ответ проясняет основную линию: абзац в шаге, новая ловушка, раздел «Под капотом», иногда новый шаг. Это лучший вариант: в следующий раз ответ будет прямо в тексте.
- **В «Твои вопросы»**, если вопрос боковой и в линию урока не встраивается. Запись в конец `<div class="qa">` перед `.refs`:
  ```html
  <details class="qa-item">
    <summary>Вопрос, сформулированный ясно <time datetime="2026-09-25">25.09.2026</time></summary>
    <p>Ответ: 3–10 предложений, можно список, код или схему.</p>
  </details>
  ```
  Если блока `.qa` в файле нет, добавь его. Пустой блок на странице не показывается.
- **В вопросы для собеседования**, если это вопрос, который реально зададут, — новая карточка.

Если вопрос вскрыл ошибку в тексте, исправь и её.

### Статус «готово»

`status: 'ready'` ставит только пользователь или ты по его прямой просьбе.

## Реестр

```js
window.KB_TREE = [
  { id: 'java', title: 'Java', items: [                        // раздел — тоже папка
    { id: 'concurrency', title: 'Многопоточность', source: '…', items: [
      { id: 'jmm', freq: 3, status: 'draft', title: 'Java Memory Model',
        scope: 'happens-before, volatile, безопасная публикация' },
    ] },
  ] },
];
```

- Дерево любой глубины. Есть `items` — папка, нет — тема. В папке могут лежать и темы, и папки.
- `id` темы — имя файла, уникален во всём реестре. `id` папки — часть адреса на главной (`index.html#java/concurrency/jmm`), уникален среди соседей.
- `title` темы короткий, папка уже задаёт контекст: в папке Kafka тема называется «Основы», а `<h1>` страницы — «Kafka: основы».
- `scope` — что входит в тему, через запятую. Видно в превью и участвует в поиске.
- `freq` — как часто спрашивают: 3 часто, 2 иногда, 1 редко.
- `status` — `'empty'` файла нет, `'draft'` написано, `'ready'` пользователь проверил.
- Порядок строк — порядок изучения.
- Большую область, как Kafka, делай папкой с темами, а не одной темой.

## Урок

Урок объясняет, а не перечисляет. После него читатель должен понимать, зачем эта вещь существует, как работает и где ломается, и отвечать на вопросы из второй части своими словами.

- 3–6 шагов, каждый — одна мысль. Первый шаг — конкретная ситуация, в которой без темы плохо, а не определение. Последний — границы: когда не работает и чем заменить.
- Заголовок шага — мысль, которую он доказывает: «Код, который знает обо всех», а не рубрика «Проблема».
- Абзацы по 2–4 предложения. Каждое утверждение с причиной: не «так нельзя», а «так нельзя, потому что…».
- Один сквозной пример на весь урок, лучше из банковского домена: платежи, счета, лимиты.
- Код минимальный и запускаемый, вывод — настоящий.
- Если механизм — процесс во времени (сообщение идёт через систему, окно двигается по массиву, партиции переходят между консьюмерами), объясняй пошаговой схемой. Для технологий и алгоритмов это главный инструмент.
- Схемы: цвета только через классы `dg-*`, чтобы работала тёмная тема. Шрифт моноширинный: закладывай 7,5 px на символ для `dg-t` и 7 px для `dg-s`.

## Источники

Источник может быть любым: курс, книга, документация, статья, доклад, заметки пользователя. В `.refs` 2–5 пунктов, у каждого — что именно там смотреть: глава, раздел, минута доклада. Источник, по которому построен урок, идёт первым с пометкой «основа урока». Книги и курсы пересказывай своими словами, не копируй.

## Язык и точность

- Русский, простой, на «ты». Термины — как говорят разработчики: hashCode, JPA, rebalance, без перевода.
- Короткие предложения. Без вводных вроде «В этом уроке мы разберём» и без выводов вроде «Таким образом».
- Проверяй всё проверяемое: запускай код (`java Example.java`, JDK 21), пересчитывай числа на схемах, сверяй поведение с javadoc, документацией, исходниками. Если проверить нельзя — например, нужен брокер, — сверь с документацией и скажи пользователю, что код не запускался.
