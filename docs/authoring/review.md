# Проверка перед коммитом

Пройди все четыре части по порядку. Нельзя коммитить тему, пока хоть один пункт не выполнен или не объяснён пользователю.

## 1. Автоматические проверки

```bash
python3 tools/build_search.py
```

```bash
python3 tools/check_kb.py
```

`check_kb.py` падает на ошибках связей: реестр, файлы, `id`, поисковый индекс. Кроме того, он печатает **предупреждения о качестве**: нет схем, «схема» похожа на список текста, одни «уточнения» в проверках, короткая страница, сжатый HTML. Предупреждение по своей теме исправь. Если уверен, что оно ложное, объясни почему в отчёте пользователю. Предупреждения — сигнал, а не цель: страница без предупреждений ещё не хорошая.

## 2. Содержание

Перечитай тему глазами человека, который готовится к собеседованию.

- [ ] Каждый пункт карты покрытия попал в шаг, карточку, «Под капотом» или явно отдан соседней теме.
- [ ] Заголовки шагов, прочитанные подряд, складываются в связную историю от боли к механизму и границам.
- [ ] Первый шаг — конкретная ситуация из сквозного примера, последний — границы.
- [ ] Механизм показан, а не назван: по уроку можно нарисовать его самому и предсказать поведение.
- [ ] Глубина — уровень senior-вопросов из карты покрытия.
- [ ] Числа, значения по умолчанию, флаги и версии проверены: запуском, `-XX:+PrintFlagsFinal`, javadoc, исходниками.
- [ ] Весь Java-код запущен на JDK 21, вывод в `pre.out` скопирован из запуска.
- [ ] Каждый пример доказывает утверждение своего шага, и в его выводе можно ошибиться.
- [ ] Не меньше двух настоящих схем, у процесса во времени — пошаговая (`illustrations.md`).
- [ ] Карточек 4–6 для `freq: 3`, 3–4 для остальных. В проверках темы есть хотя бы одна `задача` и одно `ревью`. В темах с задачами вместо этого: заготовки и решения прогнаны, все проверки печатают OK.
- [ ] Ответы middle звучат как живая речь, senior добавляет новое, а не повторяет.
- [ ] Текст без лишних оговорок, каждое утверждение с причиной.
- [ ] Ни одного пункта из «Признаков брака» в `quality.md`.

## 3. Браузер

Запусти сервер из корня проекта:

```bash
python3 -m http.server 8791 --directory .
```

Открой `http://localhost:8791/topics/<id>.html` и проверь:

- [ ] Шаги пронумерованы и есть в оглавлении, вывод кода спрятан под «Что выведет?», карточки свёрнуты и открываются, переключатель Senior работает.
- [ ] Каждая схема: сделан скриншот, текст не вылезает и не наезжает, стрелки касаются блоков.
- [ ] Каждая пошаговая схема пролистана до конца, скриншот каждого шага, на каждом шаге видно только то, что правда в этот момент.
- [ ] Тёмная тема (кнопка в шапке): схемы и текст читаются.
- [ ] Ширина 375 px: страница не разъезжается, схемы прокручиваются внутри рамки.
- [ ] Консоль браузера без ошибок.
- [ ] Эталон своего типа открыт рядом: твоя тема не беднее по глубине, схемам и примерам.
- [ ] На главной тема видна в своей папке, поиск находит её шаги и вопросы.

Страницы работают и без сервера, через `file://`, но проверку делай через сервер.

## 4. Коммит и отчёт

Коммит: одна тема или одна перестройка — один коммит. В сообщении — что и где изменилось.

Отчёт пользователю — коротко:

- где найти: «Java › JVM › Memory Areas»;
- что покрыто, и что сознательно отдано соседним темам;
- что проверить не удалось и почему, например код, которому нужен брокер;
- предупреждения валидатора, которые остались, и почему.
