# Banking Basics: учебные модели учёта

JDK 21, без зависимостей. Из корня репозитория:

```bash
java -version # Нужен JDK 21.
java -ea examples/banking/LedgerDemo.java
java -ea examples/banking/MoneyDemo.java
java -ea examples/banking/HoldDemo.java
java -ea examples/banking/ReconcileDemo.java
```

- `LedgerDemo`: частичная запись, типы счетов, три строки перевода с комиссией,
  отказ несбалансированной операции, повтор с тем же и новым ключом, сторно.
- `MoneyDemo`: двоичное значение, округление комиссии по каждой операции и пачке,
  минимальные единицы RUB, лишняя дробная точность, валюта и переполнение.
- `HoldDemo`: один резерв кошелька, окончательное списание части суммы,
  снятие резерва и отказ позднего локального capture.
- `ReconcileDemo`: равные итоги с разными операциями, несовпадение суммы,
  обнаружение дубликата до сопоставления.

Все суммы целочисленных демо — в копейках, все данные вымышлены.
Вывод детерминированный; модели выполняются в одном потоке и памяти.
В `LedgerDemo` копия остатков защищает от ошибки проверки, но публикация Java-полей
не реализует транзакцию БД, устойчивое хранение, конкурентную проверку расхода
или восстановление после аварии. Регистрация операции в настоящей системе
требует общей транзакционной границы с журналом и зависимыми итогами.

`HoldDemo` показывает локальную доступность, без парной проводки получателя.
Это один окончательный capture, а не несколько частичных проведений.
Сверка работает по контракту с уникальным ref, исходящими RUB-строками и одним
законченным периодом. Реальные источники могут иметь несколько видов движения
одного платежа; их ключи и правила сопоставления определяются отдельно.

Это примеры механизмов из главы, не интеграция с реальным банком или TigerBeetle.
