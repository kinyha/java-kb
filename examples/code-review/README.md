# Code Review

JDK 21, без сборки, внешнего банка и БД. Из корня репозитория:

```bash
java examples/code-review/PaymentReviewDemo.java
java examples/code-review/ConcurrentReviewDemo.java
```

PaymentReviewDemo — локальная модель одного последовательного обработчика.
charged — накопленный эффект в минимальных единицах, не настоящие деньги.
TemporaryFailure возникает до эффекта; ReplyLost — после него.
Map accepted в Bank моделирует атомарное сохранение ключа с эффектом только
в этом однопоточном запуске. В реальном провайдере эту гарантию нужно проверить
по API и поведению. Память демо не переживает перезапуск.
done сохраняет только ID и не является полноценной реализацией идемпотентности.
Сценарий changedPayload проверяет отказ самого Bank, обходя Handler: локальный
SKIPPED без проверки payload тоже требовал бы исправления в настоящем сервисе.
Все Request содержат ненулевой ключ k7 и положительную сумму.

ConcurrentReviewDemo использует два реальных потока. Барьер гарантирует,
что обе containsKey завершатся до любой put. Поэтому гонка воспроизводится
без sleep и вывода порядка потоков. putIfAbsent даёт одного победителя
в одной карте при успешном выполнении эффекта. Сбой после захвата, два разных
процесса и перезапуск этой демонстрацией не решаются.

Всего 6 блоков вывода. Последний блок PaymentReviewDemo намеренно показывает
FAIL бизнес-проверки на сломанной версии; это ожидаемый результат опыта.
Вывод снят на JBR 21.0.11, команды поддерживают -ea. Таймауты 5/10 секунд
ограничивают ожидание сбоя барьера/задач, а не задержку платежного API.
