# Linked List · JDK 21

Из этой папки, без сборки и зависимостей:

```bash
java ReverseDemo.java
java RunnerDemo.java
java MergeDemo.java
java ReverseList.java
java CycleEntry.java
java MergeLists.java
java RemoveNth.java
```

Проверено на JBR 21.0.11. Все файлы самостоятельные, каждый содержит свой вложенный Node. Это собственная учебная односвязная структура; её next не является частью публичного API java.util.LinkedList. Имена A/B/C и A1/B2 нужны для трассы, не заменяют сравнение ссылок.

`ReverseDemo`: локальное присваивание и запись поля дают разный эффект; разворот переиспользует исходные объекты, прежние ссылки видят новые хвосты; чтение next после перезаписи теряет остаток. Пустой вход и один узел обрабатываются тем же циклом.

`RunnerDemo`: выбранная форма fast/slow возвращает вторую середину при чётной длине. Цикл A→B→C→D→E→C даёт встречу в D и вход в C после возврата одного указателя в голову. Сравнение value даёт ложный цикл на трёх разных узлах со значением 7. Отрыв n+1 от dummy и остановка fast=null находят предшественника удаляемого; старые ссылки на обойдённый узел остаются допустимыми.

`MergeDemo`: стабильное слияние перенаправляет исходные next; равный узел первого входа выбирается раньше. У tail до следующего шага остаётся ссылка в ещё не обработанный остаток. Пустой остаток не создаёт новых копий. Последний опыт намеренно нарушает условие отдельных входов: общий S превращается в самопетлю S.next=S.

Четыре остальных файла — решения задач с проверками из заготовок страницы. Ошибка завершается `AssertionError`. Проверки сравнивают объекты через ==, требуют правильный конец цепочки; CycleEntry дополнительно проверяет сохранение каждого next. Длинные проверки печатают только длину или имя узла.

У разворота и удаления вход ациклический; n при удалении допустимо, список непустой. Слияние получает два отсортированных ациклических списка без общих объектов и меняет их связи. CycleEntry только читает вход; он допускает цикл и пустую голову. Структура стабильна в течение операции, совместного изменения другими потоками нет.

Метод show ограничивает печать при повторном посещении узла и использует множество личностей. Эта диагностическая память и обвязка тестов не входят в O(1) памяти самих алгоритмов. Версии для произвольного неверного входа, совместного владения и параллельных изменений здесь не реализованы.
