# LLM Risks: границы приложения

Тема: [AI Engineering › Safety › LLM Risks](../../topics/llm-risks.html).
Демо проверены на JBR 21.0.11; сторонних Java-зависимостей нет.

Из корня проекта:

    python3 examples/llm-risks/verify.py

Компиляция идёт во временный каталог. Исходники репозитория не меняются.
Каждый main проверяет результат через AssertionError, вывод сравнивается драйвером.
ToolBoundaryDemo проверяет формат, trusted context, tenant ACL, границу задачи,
точное подтверждение действия и версию объекта. Все деньги и approvals в памяти;
в реальном сервисе их чтение, проверка и расходование требуют одной атомарной границы.
RetrievalDemo показывает утечку через общий cache hit, который обходит loader с ACL,
и отдельно tenant/principal/policy namespace. BudgetDemo резервирует учебные единицы
до вызова, включая неудачные попытки; это не точная оценка токенов или счёта провайдера.

render-fixture.html содержит искусственный ответ модели с dummy URL. Браузерная
проверка через локальный HTTP-сервер подтверждает: строка отображена целиком,
элемент img не создан, JS из строки не выполняется, запроса к dummy sink нет.
Фикстура проверяет только textContent, не Markdown renderer или HTML sanitizer.

LLM API, банк и внешние инструменты не вызываются. Вредный запрос задан явно;
демо не измеряет вероятность, что конкретная модель поддастся prompt injection.
Исторические EchoLeak/GitHub MCP воспроизведения не выполнялись; случаи разобраны
по первичным публикациям исследователей. Параллельные транзакции, истечение approval,
distributed quotas, реальные DNS/redirect/SSRF ограничения и DLP не проверялись.
