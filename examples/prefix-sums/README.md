# Prefix Sums · JDK 21

Из этой папки, без сборки и зависимостей:

```bash
java RangeDemo.java
java CountingDemo.java
java KeyDemo.java
java RangeQueries.java
java CountTarget.java
java BalancedRange.java
java DivisibleRanges.java
```

Проверено на JBR 21.0.11. Три демо дают вывод из урока; четыре остальных файла содержат решения задач и проверки из заготовок. Ошибка проверки завершает запуск с `AssertionError`. Проверки также подтверждают сохранение входных массивов.

`RangeDemo`: префиксы на n + 1 границах, полуинтервалы, пустые и отрицательные суммы; позднее приведение к long не исправляет переполнение int; исправление платежа делает прежний снимок неактуальным. Счётчик чтений показывает стоимость предобработки и двух обращений на запрос, а не измеряет время работы.

`CountingDemo`: подсчёт по частотам предыдущих префиксов; множество теряет кратность, отсутствие P[0] теряет участок от начала, запись до поиска считает пустой участок при target = 0. Демонстрация неправильного окна предназначена для входа с возвратом и не является алгоритмом подсчёта для всех неотрицательных массивов. Для 100 000 нулей число участков превышает int.

`KeyDemo`: максимальная длина требует первого индекса, перезапись оставляет только короткие участки. У отрицательных префиксов Java % не даёт единого представления класса остатка; Math.floorMod с положительным делителем даёт значение в [0, divisor).

Задачи: длина массива ≤ 200 000, элементы int, ссылки не null. Запросы `RangeQueries` содержат допустимые границы [left, right); `CountTarget` получает |target| ≤ 10¹²; `BalancedRange` принимает только 0 и 1; `DivisibleRanges` требует положительный divisor. Суммы и разности по этим ограничениям помещаются в long. Демо соблюдают те же ограничения.

Оценки времени не учитывают диагностическую печать. Для HashMap ожидаемое линейное время предполагает амортизированную постоянную стоимость операций. Публикация не требует Docker, Maven или Spring.
