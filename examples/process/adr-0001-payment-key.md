# ADR 0001: ключ операции при повторе платежа

Учебный пример; команда, дата принятия и конкретный провайдер не утверждаются.

## Статус

Предложено. Принятие зависит от подтверждения гарантии реального провайдера.

## Контекст

После потери ответа клиент не знает, произошёл ли внешний эффект.
Локальная запись до вызова может потерять платёж при отказе до эффекта.
Запись после вызова допускает новый эффект при потере ответа.
Несколько экземпляров сервиса должны распознавать одну и ту же операцию.

## Варианты

1. Локальный Set обработанных ID. Прост, но не переживает перезапуск,
   не связывает внешний эффект с записью и не общий между процессами.
2. Стабильный ключ операции, передаваемый провайдеру, плюс долговременное
   локальное состояние результата и существенного payload.

## Предлагаемое решение

Выбрать вариант 2, если провайдер подтверждает защиту повторного эффекта
для того же ключа в требуемом режиме. Источник ключа и срок использования
зафиксировать в API-контракте. Новая попытка сохраняет прежний ключ.

## Последствия

- Требуются проверка конфликта payload и сохранённый результат операции.
- Нужны проверка неопределённого результата, стратегия восстановления и
  подтверждение ограничения срока у провайдера.
- Дополнительный retry нельзя включать до проверки предпосылок.
- При другой гарантии провайдера понадобится другой протокол.

При замене решения новый ADR ссылается на этот и объясняет изменившиеся
условия; исходная причина остаётся в истории.
