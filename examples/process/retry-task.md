# Учебная задача: безопасный повтор платежа

Команда и задача вымышлены. Документ показывает объём договорённости,
а не описывает проект пользователя.

## Результат

После временного сбоя уведомление можно повторить с тем же ключом операции.
Допустимый повтор возвращает результат той же операции без второго эффекта.

## Проверяемые условия приёмки

- Отказ до эффекта допускает повтор, который завершает платёж.
- Потеря ответа после эффекта не создаёт второго списания при повторе.
- Тот же ключ с иной существенной суммой возвращает конфликт.
- Две копии сервиса не выполняют операцию как независимые платежи.

## Предпосылки и неизвестное

- Один ключ операции сохраняется между попытками; его источник согласован.
- Гарантии, срок хранения ключа и ограничения реального провайдера ещё нужно
  проверить на его контракте и интеграционным опытом.
- До подтверждения этих условий дополнительные автоматические повторы выключены.

## Рабочее разбиение

1. Ограниченное по времени исследование: проверить гарантию провайдера и
   получить воспроизводимый опыт потери ответа. Результат — ответ и данные,
   не обещание готового продуктового кода.
2. Вертикальная часть: стабильный ключ, адаптер, бизнес-проверки и наблюдение.
3. Проверка конкуренции и совместимого включения.

## Готовность и ссылки

Критерии задачи проверяются вместе с общим Definition of Done команды.
Переход помечается Done после выполнения согласованных требований качества;
слияние кода само по себе не заменяет их.

Причина решения: [ADR 0001](adr-0001-payment-key.md).
Владелец поддержки и ссылка на актуальные тесты указываются в настоящей задаче.
