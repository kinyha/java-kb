# Heap & Top-K · JDK 21

Из этой папки, без сборки и зависимостей:

```bash
java TopDemo.java
java MergeDemo.java
java MedianDemo.java
java KthLargest.java
java MergeStreams.java
java MedianPrefixes.java
```

Проверено на JBR 21.0.11. TopDemo выбирает K наибольших значений с учётом повторов, k=0 даёт пустую очередь, k за пределами [0,n] отвергается. В KthLargest условие уже гарантирует 1<=k<=n. Порядок значений в трассе kept специально сортируется; это не внутренний массив PriorityQueue.

MergeDemo и MergeStreams принимают отсортированные по неубыванию массивы без null. Пустые источники допустимы. Cursor хранит значение, номер источника и индекс; ties упорядочены по номеру источника. Диагностическая копия heads сортируется отдельно. Последний опыт MergeDemo намеренно нарушает условие сортировки источника: [5,1] прячет меньшую1 за5 и делает результат неотсортированным.

MedianDemo хранит все значения префикса в двух кучах: нижняя max-heap, верхняя min-heap; нижняя равна верхней по размеру либо больше на1. Пустой поток не имеет медианы. Сумма двух корней вычисляется как long до деления на2.0. Вход int гарантирует точное представление полученной целой или половинной медианы в double. MedianPrefixes возвращает медиану каждого префикса, пустой массив даёт пустой результат.

Все файлы задач содержат решения и проверки страницы. Ошибка завершает запуск AssertionError. Проверяется результат и сохранение входа. В трассах не измеряется время, диагностическое копирование и сортировка не входят в асимптотику самих алгоритмов.
