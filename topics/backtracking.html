Backtracking

Поиск с откатом строит ответ по одному выбору. path хранит текущую ветку, а параметры задают, чем её ещё разрешено продолжать. Перед соседним выбором все изменения предыдущей ветки отменяются; найденный ответ сохраняется отдельным снимком. Граница индекса убирает лишние порядки, used запрещает повтор позиции, а доказанное отсечение останавливает ветки без продолжения. Эти правила определяют результат точнее, чем общий шаблон рекурсии.

Откат возвращает родителю состояние до выбора

В тестах платёжного сервиса нужно прогнать все наборы необязательных проверок: 4, 7 и 9. Пустой набор, одна проверка и все проверки вместе — разные сценарии. Три вложенных цикла не обобщаются на произвольное число проверок. А перебор всех последовательностей добавит лишние варианты: набор [4,7] совпадает с [7,4], если порядок не важен.

Строим один ответ постепенно. path хранит уже выбранные значения, start задаёт первую ещё доступную позицию. Взяли элемент i, перешли в ребёнка с start=i+1, закончили его ветку и удалили свой элемент. После возврата path должен выглядеть ровно так, как до выбора: иначе соседняя ветка начнётся с чужого префикса.

Это backtracking: выбрать, углубиться, отменить выбор. Его удобно видеть как DFS по дереву решений. Вершина дерева здесь — состояние частичного ответа, а не элемент исходного массива. Мы сохраняем каждый префикс, потому что каждый из них уже является подмножеством; продолжения дают его расширения.

Фрагмент StateDemo.java, команда java examples/backtracking/StateDemo.java на JDK 21. Сначала различные значения, исходный массив сохраняется. Параметр snapshot позволит отдельно увидеть ошибку сохранения ссылки:

static List<List<Integer>> subsets(int[] values, boolean snapshot, boolean trace) {
    List<List<Integer>> result = new ArrayList<>();
    List<Integer> path = new ArrayList<>();
    visit(values, 0, path, result, snapshot, trace);
    return result;
}
static void visit(int[] values, int start, List<Integer> path,
                  List<List<Integer>> result, boolean snapshot, boolean trace) {
    result.add(snapshot ? List.copyOf(path) : path); // Копия состояния или одна общая ссылка.
    if (trace) System.out.println("save=" + path + " start=" + start);
    for (int i = start; i < values.length; i++) {
        path.add(values[i]);                        // Сделали выбор.
        visit(values, i + 1, path, result, snapshot, trace);
        path.remove(path.size() - 1);               // Вернули состояние родителя.
    }
}

При result.add(path) все ответы ссылаются на один объект. После последнего отката он пуст: исчезли сразу все четыре результата. List.copyOf сохраняет самостоятельный неизменяемый список. Копия неглубокая: для Integer этого достаточно, а изменяемые объекты внутри списка потребуют собственной политики снимка. Для изменяемых ответов можно взять new ArrayList<>(path), тоже отдельный список.

У пустого входа один вариант — ничего не выбрать. У n различных значений 2ⁿ подмножеств; всего они содержат n·2ⁿ⁻¹ элементов при n≥1. Поэтому сохранить все списки быстрее O(n·2ⁿ) нельзя уже из-за размера ответа. Откат экономит временные копии состояния и делает ограничения явными; число необходимых ответов он не уменьшает.

Следующий ход определяет, получишь набор или перестановку

Теперь сценарий зависит от порядка: сначала проверка 4, затем 7 — иной сценарий, чем сначала 7, затем 4. Граница start=i+1 потеряет второй порядок. Для перестановки нужны все ещё не занятые позиции, где бы они ни стояли во входе.

used[i] означает «позиция i входит в текущий path». Перед входом в ребёнка ставим true, после выхода возвращаем false вместе с удалением последнего значения. Это локальная отметка пути. Глобальная отметка на весь поиск разрешила бы каждой позиции появиться только в первой пройденной ветке и уничтожила бы остальные перестановки.

ChoicesDemo.java, запуск java examples/backtracking/ChoicesDemo.java. Значения различны. В этом варианте ответ сохраняется только при длине n: короткий префикс ещё не перестановка всего входа.

static List<List<Integer>> permutations(int[] values) {
    List<List<Integer>> answers = new ArrayList<>();
    permute(values, new boolean[values.length], new ArrayList<>(), answers);
    return answers;
}
static void permute(int[] values, boolean[] used, List<Integer> path,
                    List<List<Integer>> answers) {
    if (path.size() == values.length) {
        answers.add(List.copyOf(path));
        return;
    }
    for (int i = 0; i < values.length; i++) {
        if (used[i]) continue;           // Запрещена позиция только в текущей ветке.
        used[i] = true;
        path.add(values[i]);
        permute(values, used, path, answers);
        path.remove(path.size() - 1);
        used[i] = false;                 // Следующая ветка опять вправе выбрать i.
    }
}

System.out.println("empty=" + permutations(new int[0]));

На глубине d заняты ровно d позиций, путь содержит каждую из них один раз. Любая перестановка имеет единственный порядок выбора этих позиций, поэтому алгоритм выдаёт все n! ответов без повторов. Время с копированием O((n+1)·n!), дополнительный путь, used и стек O(n); память результата O(n·n!) при n≥1. Пустая перестановка снова одна.

У сочетания порядок не важен и размер задан: выбрать ровно k элементов. Оставляем возрастающий индекс, но сохраняем только path длины k. Из 1..4 пары [1,2] и [2,1] не считаются двумя ответами. У подмножества каждый префикс готов; у сочетания и перестановки критерий готовности другой. Эта строка часто важнее названия паттерна.

used и start — взаимозаменяемые способы избежать повторов.

start запрещает возвращаться к более ранним позициям и тем самым убирает порядок. used запрещает повтор одной позиции в текущем ответе, но сохраняет все её допустимые места в разных порядках.

Отсечение убирает префиксы, которые невозможно закончить

Нужно выбрать семь проверок из восьми. Наивный перебор сочетаний углубляется, пока выбранных элементов не станет семь или позиции не закончатся. Ветка, начинающаяся с проверки 8, уже обречена: справа нет шести других проверок. Это известно до рекурсивного вызова.

Пусть need=k−path.size(). После выбора i должно остаться ещё need−1 чисел из i+1..n. Их n−i, поэтому безопасны только i≤n−need+1. Эта граница сразу убирает неполные тупики. Если даже первая доступная позиция start больше границы, цикл не начнётся.

Продолжение ChoicesDemo.java. Счётчик visited считает входы в combine, включая корень и листья. Он сравнивает алгоритмы независимо от прогрева JVM. Параметр bounded меняет только верхнюю границу цикла:

record Run(List<List<Integer>> answers, long visited) {}
static Run combinations(int n, int k, boolean bounded) {
    List<List<Integer>> answers = new ArrayList<>();
    long[] visited = {0};
    if (k >= 0 && k <= n) combine(n, k, 1, new ArrayList<>(), answers, visited, bounded);
    return new Run(answers, visited[0]);
}
static void combine(int n, int k, int start, List<Integer> path,
                    List<List<Integer>> answers, long[] visited, boolean bounded) {
    visited[0]++;
    int need = k - path.size();
    if (need == 0) {
        answers.add(List.copyOf(path));
        return;
    }
    int last = bounded ? n - need + 1 : n; // После выбора i должно хватить ещё need-1 чисел.
    for (int i = start; i <= last; i++) {
        path.add(i);
        combine(n, k, i + 1, path, answers, visited, bounded);
        path.remove(path.size() - 1);
    }
}

Ответы совпали, а число посещённых состояний сократилось с 255 до 36. Отсечение доказано условием невозможности: позднему выбору просто не хватит элементов. Проверка «мне кажется, эта ветка даст мало интересных ответов» такого доказательства не имеет и может удалить правильное решение.

Для полного вывода сочетаний остаются C(n,k) ответов длины k. В ограниченном дереве каждый посещённый префикс можно дополнить до ответа; общее число узлов не больше (k+1)·C(n,k). С копированием время O((k+1)·C(n,k)), состояние поиска O(k), результат O((k+1)·C(n,k)). Для k вне 0..n ответ пуст; k=0 даёт один пустой набор. Эффект отсечения особенно заметен, когда невозможность обнаружена высоко в дереве.

Повторный выбор требует убывающего остатка

Новый сценарий: платёжную сумму 7 нужно набрать номиналами 2, 3 и 7. Номинал можно использовать несколько раз, порядок номиналов не важен. Готовые ответы — [2,2,3] и [7]. Чтобы повторить текущий номинал, ребёнок начинает с i, а не с i+1. Чтобы не породить [3,2,2], к более ранним позициям всё равно не возвращаемся.

remaining — ещё не набранная часть суммы. При выборе положительного v она уменьшается на v. Ноль означает готовый ответ; кандидат больше remaining не подходит. На отсортированном суффиксе все следующие ещё больше, поэтому break отсекает их разом. Без сортировки этот вывод ложен: за большой цифрой может стоять подходящая маленькая.

SumDemo.java, команда java examples/backtracking/SumDemo.java. Кандидаты различны. Сортируем копию массива; sorted=false — намеренно ошибочный опыт, reuse=false запрещает повтор позиции:

static List<List<Integer>> sum(int[] candidates, int target, boolean sorted, boolean reuse) {
    int[] values = candidates.clone();
    for (int v : values) if (v <= 0) throw new IllegalArgumentException("positive values required");
    if (sorted) Arrays.sort(values);    // Исходный массив сохраняется.
    List<List<Integer>> answers = new ArrayList<>();
    if (target >= 0) search(values, target, 0, new ArrayList<>(), answers, reuse);
    return answers;
}
static void search(int[] values, int remaining, int start, List<Integer> path,
                   List<List<Integer>> answers, boolean reuse) {
    if (remaining == 0) {
        answers.add(List.copyOf(path));
        return;
    }
    for (int i = start; i < values.length; i++) {
        if (values[i] > remaining) break; // break верен только на отсортированном суффиксе.
        path.add(values[i]);
        search(values, remaining - values[i], reuse ? i : i + 1, path, answers, reuse);
        path.remove(path.size() - 1);
    }
}

Положительность обеспечивает завершение: для минимального кандидата m глубина не больше D=⌊target/m⌋. Повторный ноль оставляет remaining прежним и создаёт бесконечную ветку; отрицательное значение увеличивает остаток. Их нужно ограничивать числом использований или менять модель задачи. Здесь они отклоняются до поиска, а вычитание выполняется только для 0<v≤remaining, поэтому отрицательный результат и переполнение не возникают.

Обозначим P число посещённых префиксов, Z суммарное количество элементов в сохранённых ответах, c число кандидатов. После сортировки время не больше O(c log(c+1)+c·P+Z), состояние O(c+D) без результата. Грубая граница по дереву — O((D+1)·(c+1)D+1), а не O(target): поиск перечисляет варианты, многие остатки возникают заново. Эта оценка намеренно не обещает полиномиального времени; для одного числа ответов или минимальной длины пригодится DP.

Повторы значений убираются на одном уровне выбора

До этого позиция и значение различались только формально: все значения были разными. Теперь вход [1,1,2], а ответы должны быть уникальными по значениям. Выбор первой единицы и выбор второй единицы в корне дают одинаковые [1] и [1,2]. Но выбрать обе единицы вместе нужно: [1,1] — новый допустимый набор.

Отсортируем копию входа, чтобы равные значения стояли рядом. В цикле с данным start пропускаем i, когда i>start и values[i]==values[i−1]. Первая равная альтернатива на этом уровне уже создала все такие продолжения. На следующем уровне start меняется: вторая единица оказывается первым доступным элементом и разрешается.

DuplicatesDemo.java, запуск java examples/backtracking/DuplicatesDemo.java. mode=0 различает позиции, mode=1 убирает эквивалентные ветки, mode=2 показывает ошибку пропуска всех повторных значений:

static List<List<Integer>> subsets(int[] input, int mode) {
    int[] values = input.clone();
    Arrays.sort(values);
    List<List<Integer>> answers = new ArrayList<>();
    walk(values, 0, new ArrayList<>(), answers, mode);
    return answers;
}
static void walk(int[] values, int start, List<Integer> path,
                 List<List<Integer>> answers, int mode) {
    answers.add(List.copyOf(path));
    for (int i = start; i < values.length; i++) {
        boolean repeated = i > 0 && values[i] == values[i - 1];
        if (mode == 1 && i > start && repeated) continue; // Пропускаем равную альтернативу на этом уровне.
        if (mode == 2 && repeated) continue;             // Ошибка: запрещает вторую 1 и на следующем уровне.
        path.add(values[i]);
        walk(values, i + 1, path, answers, mode);
        path.remove(path.size() - 1);
    }
}

В перестановках проверка другая: при отсортированном входе пропускают равное values[i], если i>0 и предыдущая равная позиция ещё не used. Тогда равные позиции берутся в одном закреплённом порядке, но обе могут войти в ответ. Для разбиения суммы с одноразовыми позициями применяется правило i>start. Идентичные формулы нельзя переносить между моделями без понимания текущего уровня.

HashSet готовых ответов уберёт повторы после построения, но одинаковые поддеревья всё равно будут пройдены и снимки созданы. Выбрасывать симметричные ветки до рекурсивного вызова выгоднее. Ключ множества также должен быть стабильным: изменяемый path, положенный в HashSet без копии, меняет собственные equals и hashCode при следующем выборе.

Размер вывода и состояние поиска считаются отдельно

У backtracking нет одной общей сложности «экспонента». Назови пространство ответов, глубину и цену каждого шага. Для подмножеств это 2ⁿ наборов, для перестановок n! порядков, для сочетаний C(n,k) наборов длины k. Отсечение может убрать тупики; если просят все ответы, оно не может убрать работу записи самих ответов.

Рекурсивная глубина занимает стек вызовов. Длинная ветка зависит от доступного стека, даже если найден всего один ответ. Явный стек кадров убирает эту зависимость, но каждый кадр всё равно хранит место продолжения и сведения для отката. Готовые ответы часто занимают больше памяти, чем весь путь и стек вместе.

Если ответы обрабатываются сразу, их можно отдавать получателю по одному и убрать накопленный список результатов. Снимок нужен и здесь: получатель вправе сохранить ссылку. Передавать общий path допустимо только при ясном условии «прочитать синхронно и не удерживать». Прерывание по первому результату и исключение получателя требуют внимания: при повторном использовании состояния откат должен выполняться в finally, даже если ветка выходит раньше.

Если задача спрашивает только существование, количество или минимальную стоимость, перечисление часто лишнее. В задаче суммы один remaining может встречаться через разные префиксы. Подсчёт продолжений можно запомнить, но ключ должен включать start: доступный суффикс меняет варианты. При перестановке состояние определяется набором использованных позиций. Как построить такое повторно используемое состояние — Dynamic Programming.

Для subset sum с несколькими десятками элементов и большим диапазоном сумм бывает полезно разделить вход пополам, перечислить суммы половин и искать дополнения: meet in the middle. Для заранее известных жадных задач нужен отдельный аргумент, что локальный выбор сохраняет оптимум. Откат даёт корректный полный перебор, но не подменяет эти доказательства и не ускоряет бесконтрольно растущий вывод.

На собеседовании скажи, что хранится в path, какие ходы допустимы, когда сохраняется ответ и почему ветка закончится. Затем покажи сохранение и откат каждой изменённой переменной. Отдельно прогони пустой вход, повторные значения, отсутствие ответа и первую соседнюю ветку. Глобальный visited из Graph Search здесь обычно потеряет разные ответы: для перечисления важен текущий путь, а не факт прежнего прихода.

  • После ребёнка состояние должно стать ровно таким, каким было до текущего выбора. Ответ сохраняется снимком, а не общей ссылкой на path.
  • Возрастающий индекс строит наборы; локальный used строит все порядки. Повтор текущего кандидата разрешается переходом к i вместо i+1.
  • Отсечение должно доказывать невозможность продолжения. Для сочетания нужна достаточная длина суффикса, для положительной суммы — кандидат не больше остатка.
  • Равные значения пропускаются среди альтернатив одного уровня. На следующем уровне ещё один экземпляр может быть частью нового ответа.
  • Память пути и стека отличается от памяти всех ответов. При вопросе о количестве или минимуме сначала проверь, можно ли заменить перечисление DP.

static List<List<Integer>> solve(int[] values) {
        List<List<Integer>> answers = new ArrayList<>();
        walk(values, new boolean[values.length], new ArrayList<>(), answers);
        return answers;
    }
    static void walk(int[] values, boolean[] used, List<Integer> path, List<List<Integer>> answers) {
        if (path.size() == values.length) {
            answers.add(List.copyOf(path));
            return;
        }
        for (int i = 0; i < values.length; i++) {
            if (used[i]) continue;
            used[i] = true;                   // used относится к текущему пути, не ко всему поиску.
            path.add(values[i]);
            walk(values, used, path, answers);
            path.remove(path.size() - 1);
            used[i] = false;
        }
    }

static List<List<Integer>> solve(int n, int k) {

        int need = k - path.size();

            walk(n, k, i + 1, path, answers);
            path.remove(path.size() - 1);
        }

static List<List<Integer>> solve(int[] candidates, int target) {
        int[] values = candidates.clone();
        Arrays.sort(values);
        List<List<Integer>> answers = new ArrayList<>();
        if (target >= 0) walk(values, target, 0, new ArrayList<>(), answers);
        return answers;
    }
    static void walk(int[] values, int remaining, int start, List<Integer> path,
                     List<List<Integer>> answers) {
        if (remaining == 0) {
            answers.add(List.copyOf(path));
            return;
        }
        for (int i = start; i < values.length; i++) {
            if (values[i] > remaining) break; // Дальше только большие значения.
            path.add(values[i]);
            walk(values, remaining - values[i], i, path, answers); // i разрешает повтор этого числа.
            path.remove(path.size() - 1);
        }
    }

Пусть c — число кандидатов, D=⌊target/min⌋ для непустого входа, P — число посещённых префиксов, Z — суммарная длина ответов. Время O(c log(c+1)+c·P+Z), состояние O(c+D), ответ O(Z+число ответов). Для пустого входа работа O(1). Полное решение: CombinationSum.java. Проверки сравнивают набор ответов независимо от их порядка и отдельно отвергают повторы.

Как изменить решение, если каждая позиция доступна только один раз и во входе есть повторы?

После выбора переходи к i+1, а равную альтернативу на одном уровне пропускай условием i>start && values[i]==values[i−1]. Сортировка копии остаётся. Положительность по-прежнему нужна для break по remaining. Это модель Combination Sum II, а не запрет повторных значений вообще.
