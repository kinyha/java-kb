Dynamic Programming

Динамическое программирование хранит ответ на состояние, к которому можно прийти разными путями. Если остаток задачи полностью описан, повторный приход использует готовое значение вместо нового перебора. Сначала определяются смысл ячейки, база и переход, затем порядок расчёта. Память сокращается только после проверки, какие старые значения ещё нужны. Одна и та же формула с другим порядком прохода может начать считать другие объекты.

Одинаковый остаток задачи не нужно решать заново

После платежа сервис отправляет n уведомлений из фиксированной очереди. За один шаг отправляется одно или два; нужно посчитать способы разбить очередь на такие пачки. Для трёх уведомлений варианты [1,1,1], [1,2] и [2,1]. Это та же задача, что подъём по лестнице шагами 1 или 2, поэтому методы ниже называются ways.

Перебор ветвится после каждого выбора: отправить одно или два, затем решить остаток. Но остаток 2 возникнет после многих разных историй, а продолжения у него одинаковые. Количество способов определяется числом оставшихся уведомлений, а не всем предыдущим маршрутом. Сохраним ответ на каждый остаток один раз.

Состояние ways(n) — число способов закончить n оставшихся шагов. Первый шаг 1 оставляет n−1, первый шаг 2 — n−2. Группы различаются первым шагом и не пересекаются, поэтому ways(n)=ways(n−1)+ways(n−2). Базы ways(0)=1, ways(1)=1: пустое продолжение одно, единственная ступень проходится единицей.

StairsDemo.java, команда java examples/dp/StairsDemo.java на JDK 21. Счётчик calls считает все входы в метод, включая попадания в готовую ячейку. Ready отделён от значения: во многих других задачах нулевой ответ законен.

static long plain(int n, long[] calls) {
    calls[0]++;
    if (n <= 1) return 1; // До нулевой ступени один способ: ничего не делать.
    return plain(n-1, calls) + plain(n-2, calls);
}
static long memo(int n, long[] values, boolean[] ready, long[] calls) {
    calls[0]++;
    if (ready[n]) return values[n];
    values[n] = Math.addExact(memo(n-1, values, ready, calls), memo(n-2, values, ready, calls));
    ready[n] = true;      // Значение становится готовым после вычисления, не при входе.
    return values[n];
}

Ответ 233 сохранился, вызовы сократились с 465 до 23. Это мемоизация, или top-down DP: рекурсия вычисляет нужные состояния и хранит готовые значения. Для n ступеней состояний n+1, у каждого два перехода: время O(n), значения и ready занимают O(n), стек рекурсии тоже до O(n).

Главное условие повторного использования — полностью описанное продолжение. Если на следующих шагах разрешения зависят от предыдущей пачки, одного n мало: в ключ добавится её размер. Запоминание неверного состояния ускорит неправильный ответ. Если состояния не повторяются, одна память результатов не уберёт работу перебора.

Таблица вычисляется в порядке готовности зависимостей

У лестницы зависимости идут к меньшим индексам. Их можно вычислить без рекурсии: сначала базы, затем 2, 3 и так до n. Это табуляция, или bottom-up DP. Она строит тот же ответ по той же формуле, только порядок расчёта задан циклом.

Полная таблица позволяет спросить любой промежуточный результат. Если нужен только последний, достаточно двух предыдущих чисел. Но оба должны оставаться старыми до вычисления следующего. Сначала сохраняем next, затем сдвигаем пару; присваивание previous=current до сложения потеряет нужное состояние.

static long[] table(int n) {
    long[] dp = new long[n+1];
    dp[0] = 1;
    if (n > 0) dp[1] = 1;
    for (int i = 2; i <= n; i++) dp[i] = Math.addExact(dp[i-1], dp[i-2]);
    return dp;
}
static long rolling(int n) {
    long previous = 1, current = 1;
    for (int i = 2; i <= n; i++) {
        long next = Math.addExact(previous, current); // Оба старых значения нужны до сдвига.
        previous = current;
        current = next;
    }
    return current;
}
static long wrongOrder(int n) {
    long previous = 1, current = 1;
    for (int i = 2; i <= n; i++) {
        previous = current;
        current = previous + current; // Ошибка: предыдущая ступень уже потеряна.
    }
    return current;
}

Сжатие памяти — доказательство, какие значения больше не понадобятся, а не механическая замена массива парой переменных. В рюкзаке и LCS это различие станет ещё заметнее.

static int intWays(int n) {
    int previous = 1, current = 1;
    for (int i = 2; i <= n; i++) {
        int next = previous + current; // Намеренно без защиты от переполнения.
        previous = current;
        current = next;
    }
    return current;
}

Количество способов растёт быстрее индекса. При n=46 верный ответ 2 971 215 073 уже не помещается в int; число становится отрицательным без исключения. Long хватает до n=91, а Math.addExact выявляет следующий выход за диапазон. Для точных больших чисел используют BigInteger; тогда цена сложения зависит от числа бит. Если условие просит ответ по модулю, модуль применяется в каждом переходе, но это уже другой формат результата.

При обычной арифметике фиксированного размера обе формы DP имеют O(n) времени. Мемоизация может пропустить недостижимые состояния и удобна для разреженного пространства, но хранит активную рекурсию. Таблица убирает стек и хорошо подходит плотным индексам. У лестницы все остатки нужны, поэтому экономии посещений между этими двумя формами нет.

Смысл значения задаёт минимум, число вариантов или достижимость

Теперь ту же идею применим к сумме платежа. Монеты 1, 3 и 4 разрешены неограниченно; нужно набрать ровно 6 с минимальным количеством. Самый большой номинал сначала даёт 4+1+1, три монеты. Но 3+3 использует две. Чтобы обосновать ответ, проверим все возможные последние монеты через уже решённый остаток.

dp[s] — минимум монет для точной суммы s. Для последней монеты c предыдущая сумма s−c, а количество dp[s−c]+1. Берём минимум таких кандидатов. В оптимальном наборе остаток тоже должен иметь минимальное число монет: иначе его можно заменить лучшим и улучшить весь набор. Это причина, по которой достаточно хранить одно число на сумму.

CoinsDemo.java, запуск java examples/dp/CoinsDemo.java. Номиналы положительны, amount неотрицателен. Sentinel amount+1 больше любого достижимого ответа: положительная монета добавляет хотя бы единицу суммы. Символ ∞ в выводе — это sentinel, а не особое значение Java.

record Minimum(int answer, int[] dp, List<Integer> used, int infinity) {}
static Minimum minimum(int[] coins, int amount) {
    int infinity = Math.addExact(amount, 1); // Любая достижимая сумма требует не больше amount монет.
    int[] dp = new int[amount+1], last = new int[amount+1];
    Arrays.fill(dp, infinity);
    dp[0] = 0;
    for (int sum = 1; sum <= amount; sum++) {
        for (int coin : coins) {
            if (coin > sum || dp[sum-coin] == infinity) continue;
            int candidate = dp[sum-coin] + 1;
            if (candidate < dp[sum]) {
                dp[sum] = candidate;
                last[sum] = coin; // Свидетельство улучшения, а не просто последний проверенный coin.
            }
        }
    }
    List<Integer> used = new ArrayList<>();
    int answer = dp[amount] == infinity ? -1 : dp[amount];
    if (answer != -1) {
        for (int sum = amount; sum > 0; sum -= last[sum]) used.add(last[sum]);
    }
    return new Minimum(answer, dp, used, infinity);
}
static String show(Minimum result) {
    String[] cells = new String[result.dp().length];
    for (int i = 0; i < cells.length; i++)
        cells[i] = result.dp()[i] == result.infinity() ? "∞" : Integer.toString(result.dp()[i]);
    return Arrays.toString(cells);
}
static int greedy(int[] coins, int amount) {
    int[] sorted = coins.clone();
    Arrays.sort(sorted);
    int count = 0;
    for (int i = sorted.length-1; i >= 0; i--) {
        count += amount / sorted[i];
        amount %= sorted[i]; // Выбор самого большого номинала без возврата.
    }
    return amount == 0 ? count : -1;
}

Получить только минимум можно за O(c·A+A) времени и O(A) памяти для c номиналов и суммы A; last добавляет ещё O(A), сам ответ требует O(K) для K выбранных монет.

Пустая сумма требует ноль монет, недостижимая сумма требует отдельного признака. Инициализация всех dp нулями выдумала бы бесплатное решение для каждого остатка. Переход от sentinel пропускается до прибавления: математическая «бесконечность» не должна превратиться в маленькое число из-за переполнения.

При подсчёте перестановка циклов меняет ответ

Если нужен не минимум, а количество вариантов, начальная база dp[0]=1: один пустой способ. При внешнем цикле по сумме и внутреннем по последней монете считаются последовательности, где [1,2,1] и [2,1,1] разные. При внешнем цикле по номиналу считаются наборы: состояние неявно включает префикс разрешённых типов монет. Внутренний проход вверх разрешает повтор текущего типа.

static long count(int[] coins, int amount, boolean ordered) {
    long[] dp = new long[amount+1];
    dp[0] = 1; // Пустая последовательность или пустой набор — один способ.
    if (ordered) {
        for (int sum = 1; sum <= amount; sum++) {
            for (int coin : coins) {
                if (coin <= sum) dp[sum] = Math.addExact(dp[sum], dp[sum-coin]);
            }
        }
    } else {
        for (int coin : coins) { // После этого прохода разрешены только уже обработанные номиналы.
            for (int sum = coin; sum <= amount; sum++)
                dp[sum] = Math.addExact(dp[sum], dp[sum-coin]);
        }
    }
    return dp[amount];
}

System.out.println("zero combinations=" + count(new int[]{1,2}, 0, false));

Для суммы 4 наборы [1,1,1,1], [1,1,2] и [2,2] дают 3. Перестановки смешанного набора добавляют два порядка и дают 5. В минимуме одинаковые варианты можно объединить через min; при сложении они увеличивают ответ. Для подсчёта номиналы должны быть различными или предварительно объединены, иначе одинаковое значение станет несколькими типами выбора.

Направление прохода сохраняет предыдущий слой предметов

Пусть у проверок платежа есть стоимость запуска и полезность. На один пакет выделен ограниченный бюджет, каждую проверку разрешено взять один раз. Это рюкзак 0/1: предмет либо входит, либо нет. Остатка бюджета недостаточно для состояния, потому что продолжение зависит ещё и от того, какие предметы доступны.

dp[i][c] — максимальная ценность из первых i предметов при суммарном весе не больше c. Не берём предмет i−1: остаётся dp[i−1][c]. Берём: получаем value[i−1]+dp[i−1][c−weight[i−1]]. В обоих случаях читаем предыдущую строку, чтобы предмет не появился в своём же остатке второй раз.

Можно хранить одну строку, если проходить ёмкость вниз. Значение dp[c−weight] находится левее и ещё не изменено текущим предметом. При проходе вверх оно уже может включать этот же предмет. Формула внешне та же, а задача становится рюкзаком с неограниченным повтором.

KnapsackDemo.java, команда java examples/dp/KnapsackDemo.java. Веса положительны, ценности неотрицательны, рассматриваемые суммы ценностей помещаются в int:

static int[] compressed(int[] weights, int[] values, int capacity, boolean ascending) {
    int[] dp = new int[capacity+1]; // Максимум при весе НЕ БОЛЬШЕ c, пустой набор разрешён.
    for (int i = 0; i < weights.length; i++) {
        if (ascending) {
            for (int c = weights[i]; c <= capacity; c++)
                dp[c] = Math.max(dp[c], Math.addExact(dp[c-weights[i]], values[i]));
        } else {
            for (int c = capacity; c >= weights[i]; c--)
                dp[c] = Math.max(dp[c], Math.addExact(dp[c-weights[i]], values[i]));
        }
    }
    return dp;
}

System.out.println("ascending=" + Arrays.toString(compressed(new int[]{2}, new int[]{3}, 4, true)));

Для выбранных предметов нужны сохранённые слои

record Result(int value, List<Integer> items, int[][] table) {}
static Result full(int[] weights, int[] values, int capacity) {
    int[][] dp = new int[weights.length+1][capacity+1];
    for (int i = 1; i <= weights.length; i++) {
        for (int c = 0; c <= capacity; c++) {
            dp[i][c] = dp[i-1][c]; // Не брать предмет i-1.
            if (weights[i-1] <= c) {
                int take = Math.addExact(dp[i-1][c-weights[i-1]], values[i-1]);
                dp[i][c] = Math.max(dp[i][c], take); // Брать из ПРЕДЫДУЩЕЙ строки.
            }
        }
    }
    List<Integer> items = new ArrayList<>();
    int c = capacity;
    for (int i = weights.length; i > 0; i--) {
        if (dp[i][c] == dp[i-1][c]) continue; // При равенстве предпочитаем не брать.
        items.add(i-1);
        c -= weights[i-1];
    }
    Collections.reverse(items);
    return new Result(dp[weights.length][capacity], items, dp);
}

Полная таблица позволяет идти назад по i: равенство соседних строк означает, что предмет можно пропустить без потери ценности. Иначе он взят, уменьшаем ёмкость. При равенстве есть несколько оптимальных наборов, правило выбирает один. Наивный массив parent только по ёмкости в сжатом DP может вести в уже переписанное состояние другой строки; для безопасного восстановления нужны слои, отдельная история решений или повторный расчёт.

Нулём инициализирована любая ёмкость, потому что пустой набор допустим при весе не больше c. При требовании набрать ровно c база другая: достижим только нулевой вес, остальные клетки получают признак невозможности. Тот же ноль уже не подходит. Это нужно уточнить до написания перехода.

Два префикса сохраняют относительный порядок элементов

В двух журналах этапы отмечены строками ABCD и BACD. Нужно найти самую длинную общую последовательность, допускающую пропуски. Наборы букв одинаковы, но порядок A и B конфликтует: все четыре буквы в общую последовательность не войдут. Состояние должно описывать по одному префиксу каждого журнала.

Для LCS, longest common subsequence, dp[i][j] — длина общей подпоследовательности первых i символов a и первых j символов b. Если последние символы равны, завершаем ответ ими и берём dp[i−1][j−1]+1: более ранний равный экземпляр не даёт преимущества перед последними позициями. Если различаются, общий ответ не может использовать оба как своё последнее совпадение. Один последний символ пропускается, поэтому берём max(dp[i−1][j],dp[i][j−1]).

Пустой префикс даёт длину 0, значит строка и колонка ноль — базы. При заполнении слева направо и сверху вниз все зависимости готовы. LcsDemo.java, запуск java examples/dp/LcsDemo.java; строки ASCII, индексы относятся к char:

static int[][] table(String a, String b) {
    int[][] dp = new int[a.length()+1][b.length()+1];
    for (int i = 1; i <= a.length(); i++) {
        for (int j = 1; j <= b.length(); j++) {
            if (a.charAt(i-1) == b.charAt(j-1)) dp[i][j] = dp[i-1][j-1] + 1;
            else dp[i][j] = Math.max(dp[i-1][j], dp[i][j-1]);
        }
    }
    return dp;
}
static String restore(String a, String b, int[][] dp) {
    StringBuilder result = new StringBuilder();
    int i = a.length(), j = b.length();
    while (i > 0 && j > 0) {
        if (a.charAt(i-1) == b.charAt(j-1)) {
            result.append(a.charAt(i-1));
            i--; j--;
        } else if (dp[i-1][j] >= dp[i][j-1]) i--; // Правило выбора при равной длине.
        else j--;
    }
    return result.reverse().toString();
}

System.out.println("table=" + Arrays.deepToString(dp));
System.out.println("length=" + dp[a.length()][b.length()] + " subsequence=" + restore(a, b, dp));

Для самой длинной общей подстроки несовпадение обрывает текущий непрерывный участок, и переход другой. Здесь общая подстрока CD имеет длину 2, а LCS — 3.

Если нужна только длина, хватит одной строки. До обновления dp[j] означает верхнюю ячейку старой строки, dp[j−1] уже означает левую ячейку новой. Диагональ нужно сохранить отдельно до перезаписи. Иначе один символ a будет совпадать несколько раз внутри одной строки.

static int rolling(String a, String b, boolean wrongDiagonal) {
    int[] dp = new int[b.length()+1];
    for (int i = 1; i <= a.length(); i++) {
        int diagonal = 0;
        for (int j = 1; j <= b.length(); j++) {
            int oldUp = dp[j]; // Значение dp[i-1][j] до перезаписи.
            if (a.charAt(i-1) == b.charAt(j-1)) dp[j] = diagonal + 1;
            else dp[j] = Math.max(dp[j], dp[j-1]);
            diagonal = wrongDiagonal ? dp[j] : oldUp; // Ошибка хранит новую строку вместо старой.
        }
    }
    return dp[b.length()];
}

Повторные символы — разные позиции, их порядок сохраняется переходами по префиксам. Null не входит в условие. Если нужны Unicode code points или видимые символы, сначала выбери единицу последовательности; char в Java — кодовая единица UTF-16. Смысл DP сохраняется, но индексы и равенство элементов должны соответствовать этой единице.

Ключ состояния должен описывать все доступные продолжения

DP начинается до таблицы. Сначала сформулируй словами, что означает одна ячейка. Для лестницы это число способов закончить остаток, для монет — минимум для точной суммы, для рюкзака — максимум на слое доступных предметов, для LCS — длина на паре префиксов. Формула только связывает эти значения; она не исправит неполное определение.

ВопросОперация объединенияБаза / отсутствие ответа

При подсчёте нужно проверить, не пересекаются ли группы переходов. В лестнице они разделены первым шагом; в монетах внешняя сумма разделяет последовательности последней монетой, а внешний номинал фиксирует типы набора. Два пути к одному варианту не безвредны: сложение посчитает его дважды. При min и max повторный одинаковый кандидат значения не изменяет.

История прихода может исчезнуть из ключа только когда она не меняет будущие действия и их цену. В сумме с одноразовыми кандидатами один remaining без индекса потеряет доступность предметов. В выборе с лимитом ключ добавляет оставшийся лимит. Мемоизация всего path сохранит разные истории вместо объединения одинаковых задач и быстро вырастет до памяти перебора.

Сложность считай как число вычисленных состояний × цена переходов, отдельно добавляя восстановление ответа. У монет O(A) состояний и c кандидатов; у LCS O(n·m) состояний с O(1) переходом. Sparse-map полезна, когда большая часть пространства не достигается; плотные массивы проще и обычно требуют меньше объектов. Bottom-up может всё равно заполнить недостижимые клетки, если порядок задан по всему диапазону.

Top-down требует завершения зависимостей: уменьшения остатка, движения по префиксу или другого порядка без циклов. Ready, выставленный только после расчёта, не разрешит цикл рекурсии; выставленный при входе вернёт ещё не вычисленный ответ. Для циклических зависимостей нужны отдельная постановка и алгоритм, например релаксации или добавление слоя по числу шагов. Причина экономии у DP — готовые повторно используемые ответы, а не сам факт рекурсии.

Жадный выбор требует доказательства, а таблица требует бюджета состояний

Жадный алгоритм выбирает один следующий шаг и больше не возвращается к альтернативам. DP сравнивает возможные переходы через уже решённые состояния. На монетах 1,3,4 жадный выбор проиграл: это конкретный контрпример обещанию «самый большой номинал всегда лучший». Чтобы перейти к жадному решению, докажи, что локальный выбор можно включить в некоторый оптимальный ответ, например обменом без ухудшения.

У выбора непересекающихся интервалов такое доказательство опирается на самое раннее окончание: замена первого интервала на более ранний не уменьшает место для остальных. У произвольных монет аналогичное утверждение про наибольший номинал неверно. Название задачи не выбирает технику: если ограничений хватает для доказанного жадного шага, таблица может быть лишней; иначе перебираются переходы.

O(n·C) рюкзака и O(c·A) монет называют псевдополиномиальными: они зависят от числовой ёмкости и суммы, а не от числа бит в их записи. Значение C=10⁹ записывается коротко, но массив по всем ёмкостям уже огромен. Для маленькой суммарной ценности можно перевернуть состояние рюкзака и хранить минимальный вес для ценности; для малого числа предметов полезны другие способы перебора. Выбор зависит от размеров всех осей.

Сжатие строк помогает памяти, но цену заполнения всех клеток не меняет. Для LCS двух строк длины 10⁵ стандартная таблица всё равно означает 10¹⁰ состояний. А при требовании вывести все решения даже короткая DP-таблица не устраняет экспоненциальный вывод. Один оптимальный ответ, число ответов и все ответы — разные требования, как в Backtracking.

В прикладном коде держи memo в границах одного входа либо включай идентичность входа в ключ: ответ для n при одном наборе монет не годится для другого. Отдельно проверь арифметику, sentinel и право менять массивы. Статический кэш без политики очистки переносит проблему алгоритма в рост памяти и смешивание задач.

На собеседовании сначала назови состояние и базу, затем раздели все решения последним или первым выбором и выведи переход. Покажи, почему зависимости готовы в выбранном порядке. Только после этого сжимай память и оцени размеры. Прогони ноль, недостижимое состояние, повторное использование предмета и равные символы: эти случаи проверяют смысл таблицы лучше длинного обычного примера.

  • Состояние объединяет истории с одинаковыми продолжениями. Неполный ключ ускоряет неправильный ответ.
  • Мемоизация и таблица используют одну формулу, но разный порядок. Стек top-down и размеры значений тоже входят в стоимость.
  • Начальная база зависит от вопроса: пустой способ имеет количество 1, пустая стоимость 0, а невозможность хранится отдельно.
  • При сжатии рюкзака спуск читает предыдущий слой, подъём разрешает повтор. У LCS отдельно сохраняется старая диагональ.
  • Minimum, count и все решения — разные задачи. Жадный выбор требует своего доказательства, а DP — оценки количества состояний и арифметики.

Решение

Две непересекающиеся группы дают сумму способов. Не нужно хранить весь маршрут или все предыдущие значения. Math.addExact сохраняет точность при случайном выходе за заданный числовой диапазон.

static long solve(int n) {
    long previous = 1, current = 1;
    for (int i = 2; i <= n; i++) {
        long next = Math.addExact(previous, current);
        previous = current;
        current = next;
    }
    return current;
}

Подсказка 2

Инициализируй остальное sentinel amount+1. Перебери последнюю монету, но пропускай недостижимый остаток до сложения.

Решение

Положительный номинал оставляет меньшую сумму, поэтому подъём по sum — корректный порядок зависимостей. Повторные одинаковые переходы через min не меняют ответ; сортировать номиналы не требуется.

static int solve(int[] coins, int amount) {
    int infinity = amount + 1;
    int[] dp = new int[amount+1];
    Arrays.fill(dp, infinity);
    dp[0] = 0;
    for (int sum = 1; sum <= amount; sum++) {
        for (int coin : coins) {
            if (coin > sum || dp[sum-coin] == infinity) continue;
            dp[sum] = Math.min(dp[sum], dp[sum-coin] + 1);
        }
    }
    return dp[amount] == infinity ? -1 : dp[amount];
}

Подсказка 2

В одной строке остаток должен принадлежать старому слою. Обновляй c от capacity вниз до веса текущего предмета.

Решение

Проход вниз гарантирует, что меньшая ёмкость ещё не обновлена этим предметом. Пустой набор помещается при любой верхней границе веса, поэтому начальные нули правильны. Повторные веса — разные предметы и могут оба войти в ответ.

static int solve(int[] weights, int[] values, int capacity) {
    int[] dp = new int[capacity+1];
    for (int i = 0; i < weights.length; i++) {
        for (int c = capacity; c >= weights[i]; c--) {
            dp[c] = Math.max(dp[c], Math.addExact(dp[c-weights[i]], values[i]));
        }
    }
    return dp[capacity];
}

a="A", b="AA" → 1
a="AXBYC", b="ABC" → 3
a="", b="ABC" → 0

Подсказка 1

Состояние — ответ для двух префиксов. Совпадение последних символов использует диагональ, несовпадение — максимум сверху и слева.

Подсказка 2

Храни одну строку для более короткого входа. До перезаписи dp[j] сохрани старую верхнюю ячейку: она станет диагональю следующего шага.

Решение

В одном массиве dp[j] ещё старая верхняя клетка, а dp[j−1] уже новая левая. Отдельный diagonal сохраняет третью зависимость. Перестановка двух входных строк не меняет LCS и уменьшает ширину строки.

static int solve(String a, String b) {
    if (b.length() > a.length()) { // Симметричность LCS позволяет хранить более короткую строку.
        String swap = a; a = b; b = swap;
    }
    if (b.isEmpty()) return 0;
    int[] dp = new int[b.length()+1];
    for (int i = 1; i <= a.length(); i++) {
        int diagonal = 0;
        for (int j = 1; j <= b.length(); j++) {
            int oldUp = dp[j];
            if (a.charAt(i-1) == b.charAt(j-1)) dp[j] = diagonal + 1;
            else dp[j] = Math.max(dp[j], dp[j-1]);
            diagonal = oldUp; // Для следующего j это dp[i-1][j-1], не новое dp[i][j-1].
        }
    }
    return dp[b.length()];
}

После обновления поставили diagonal=dp[j]. На каком коротком тесте видно ошибку?

Для a="A", b="AA" первая клетка станет 1, а вторая возьмёт это новое значение за диагональ и станет 2. Один символ первой строки использован повторно. Diagonal должен получить oldUp, то есть значение dp[j] до перезаписи.
