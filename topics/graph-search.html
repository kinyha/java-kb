Graph Search

Поиск по графу становится коротким, когда можно забыть лишние истории прихода. На карте одна отметка объединяет клетки в остров, а очередь закрепляет минимальное число переходов. В зависимостях платёжных этапов вместо расстояния нужен счётчик оставшихся предпосылок. Для цикла важна ещё одна граница: вершина сейчас в нашей цепочке или её ветка уже закончилась. Сначала выбери, что считается состоянием, затем реши, когда повторный приход можно отбросить.

Один старт размечает целую область, а не одну клетку

Платёжный сервис выгружает карту доступности терминалов: 1 — работает, 0 — недоступен. Хочется посчитать отдельные области работающих терминалов. Если с каждой единицы заново искать всех достижимых соседей, большая область будет пройдена много раз. При A клетках суши один такой поиск стоит до O(A), а A стартов дают O(A²).

Оставим общую отметку на весь проход. Сканируем матрицу; если увидели сушу без отметки, начинаем новую компоненту и обходим всю связанную с ней сушу. Следующая единица той же области уже отмечена и нового старта не создаёт. Количество стартов и есть количество островов.

Здесь граф задан не списками рёбер. Вершина — координата клетки; соседей вычисляем четырьмя сдвигами. За границей матрицы и на воде вершины для нашего обхода нет. Восемь направлений задают другой граф: касание углами тоже соединит области.

Фрагмент IslandsDemo.java; запуск java examples/graph-search/IslandsDemo.java на JDK 21. Матрица прямоугольная, значения только 0/1. Исходный массив сохраняем, а labels одновременно хранит отметку и номер компоненты:

static final int[][] FOUR = {{0,1},{1,0},{0,-1},{-1,0}};
record Cell(int row, int col) {}
record Regions(int[][] labels, List<Integer> sizes) {}
static Regions label(int[][] grid, int[][] directions) {
    int rows = grid.length, cols = rows == 0 ? 0 : grid[0].length;
    int[][] labels = new int[rows][cols];
    List<Integer> sizes = new ArrayList<>();
    for (int r = 0; r < rows; r++) {
        for (int c = 0; c < cols; c++) {
            if (grid[r][c] == 0 || labels[r][c] != 0) continue;
            int id = sizes.size() + 1, size = 0; // Один новый старт — одна компонента.
            ArrayDeque<Cell> queue = new ArrayDeque<>();
            labels[r][c] = id;                 // Отмечаем до добавления в очередь.
            queue.addLast(new Cell(r, c));
            while (!queue.isEmpty()) {
                Cell cell = queue.removeFirst();
                size++;
                for (int[] d : directions) {
                    int nr = cell.row() + d[0], nc = cell.col() + d[1];
                    if (nr < 0 || nr >= rows || nc < 0 || nc >= cols) continue;
                    if (grid[nr][nc] == 0 || labels[nr][nc] != 0) continue;
                    labels[nr][nc] = id;        // Другой сосед уже не добавит эту клетку.
                    queue.addLast(new Cell(nr, nc));
                }
            }
            sizes.add(size);
        }
    }
    return new Regions(labels, sizes);
}

Отметка при добавлении сохраняет одну запись на вершину

Очередь содержит обнаруженные клетки, чьи соседи ещё не проверены. Это отдельный этап между «не видели» и «закончили». Если помечать только при извлечении, два соседа успеют добавить одну и ту же клетку. На сетке такой ромб возникает вокруг квадрата, а в зависимостях — когда два этапа ведут к одному.

Инвариант простой: как только вершина попала в очередь, отметка уже стоит. Значит, второй путь к ней ничего не добавит. Одна вершина занимает не больше одной записи в очереди за весь обход. В нашей разметке эту роль выполняет ненулевой labels.

Сравним два варианта на рёбрах 0 → 1, 0 → 2, 1 → 3, 2 → 3. У позднего варианта проверка при извлечении пропускает повторную обработку соседей, но само повторное извлечение остаётся. Этот опыт показывает именно содержимое очереди, а не число уникальных вершин:

static List<Integer> diamond(boolean early) {
    int[][] edges = {{1,2},{3},{3},{}}; // Два разных пути сходятся в 3.
    boolean[] seen = new boolean[4];
    ArrayDeque<Integer> queue = new ArrayDeque<>();
    List<Integer> popped = new ArrayList<>();
    queue.addLast(0);
    if (early) seen[0] = true;
    while (!queue.isEmpty()) {
        int v = queue.removeFirst();
        popped.add(v);                  // Считаем все извлечения, включая повторные.
        if (!early) {
            if (seen[v]) continue;      // Поздняя отметка спасает обработку, но не очередь.
            seen[v] = true;
        }
        for (int w : edges[v]) {
            if (seen[w]) continue;
            if (early) seen[w] = true;
            queue.addLast(w);
        }
    }
    return popped;
}

Волна BFS закрепляет расстояние при первом обнаружении

Теперь карта задаёт проходы: 0 — можно идти, 1 — препятствие. Нужен кратчайший маршрут от (0,0) к (2,3), каждый переход стоит один шаг. Перебор всех простых путей долго хранит альтернативные истории; даже без циклов число путей может расти экспоненциально. Нам достаточно одного лучшего расстояния на клетку.

FIFO-очередь обрабатывает вершины слоями: сначала расстояние 0, затем 1, затем 2. При обработке клетки с расстоянием d новый сосед получает d+1. Путь короче уже пришёл бы с одного из предыдущих слоёв, а они обработаны. Поэтому первое записанное расстояние окончательно, повторный путь к той же клетке можно отбросить.

Фрагмент GridPathsDemo.java, команда java examples/graph-search/GridPathsDemo.java. dist=-1 объединяет ещё не достигнутые клетки и препятствия; тип клетки отдельно виден в grid. Для самого маршрута сохраняем родителя при первом открытии:

static final int[][] FOUR = {{0,1},{1,0},{0,-1},{-1,0}};
record Cell(int row, int col) {
    public String toString() { return "(" + row + "," + col + ")"; }
}
record Search(int[][] dist, Cell[][] parent) {}
static Search bfs(int[][] grid, Cell source, int[][] directions, boolean trace) {
    int rows = grid.length, cols = rows == 0 ? 0 : grid[0].length;
    int[][] dist = new int[rows][cols];
    for (int[] row : dist) Arrays.fill(row, -1);
    Cell[][] parent = new Cell[rows][cols];
    if (rows == 0 || cols == 0 || grid[source.row()][source.col()] != 0)
        return new Search(dist, parent);
    ArrayDeque<Cell> queue = new ArrayDeque<>();
    dist[source.row()][source.col()] = 0; // Расстояние в рёбрах: до самого себя ноль.
    queue.addLast(source);
    int level = 0;
    while (!queue.isEmpty()) {
        int width = queue.size();         // В этой порции только клетки одного уровня.
        if (trace) System.out.println("level=" + level + " queue=" + queue);
        for (int i = 0; i < width; i++) {
            Cell v = queue.removeFirst();
            for (int[] d : directions) {
                int nr = v.row() + d[0], nc = v.col() + d[1];
                if (nr < 0 || nr >= rows || nc < 0 || nc >= cols) continue;
                if (grid[nr][nc] != 0 || dist[nr][nc] != -1) continue;
                dist[nr][nc] = dist[v.row()][v.col()] + 1;
                parent[nr][nc] = v;        // Первый путь уже кратчайший: не перезаписываем.
                queue.addLast(new Cell(nr, nc));
            }
        }
        level++;
    }
    return new Search(dist, parent);
}
static List<Cell> path(Search search, Cell target) {
    if (search.dist()[target.row()][target.col()] == -1) return List.of();
    List<Cell> result = new ArrayList<>();
    for (Cell v = target; v != null; v = search.parent()[v.row()][v.col()]) result.add(v);
    Collections.reverse(result); // Родители ведут от цели к старту.
    return result;
}

Задача становится готовой после последней предпосылки

У платежа другая карта: reserve и fraud должны завершиться до capture; после capture идут receipt и ledger; report ждёт обе. Обычная достижимость отвечает, что связано с reserve, но игнорирует вторую предпосылку capture. Порядок должен учитывать все входящие рёбра.

Алгоритм Кана хранит need[v], число ещё не снятых предпосылок. В очередь попадают все вершины с need=0, включая отдельные компоненты. Снимаем одну готовую вершину, добавляем её в результат и уменьшаем счётчики зависимых. Сосед становится готовым только при переходе счётчика в ноль.

В DependenciesDemo.java ребро [u,v] означает «u перед v». Не перепутай его с [курс, предпосылка] в задачах Course Schedule: там пару нужно развернуть при построении графа. Команда java examples/graph-search/DependenciesDemo.java:

record Order(List<Integer> removed, List<Integer> blocked) {}
static List<List<Integer>> graph(int n, int[][] edges) {
    List<List<Integer>> next = new ArrayList<>();
    for (int v = 0; v < n; v++) next.add(new ArrayList<>());
    for (int[] e : edges) next.get(e[0]).add(e[1]); // Предпосылка -> зависимая задача.
    return next;
}
static Order kahn(int n, int[][] edges, boolean trace) {
    List<List<Integer>> next = graph(n, edges);
    int[] need = new int[n];
    for (int[] e : edges) need[e[1]]++;
    ArrayDeque<Integer> ready = new ArrayDeque<>();
    for (int v = 0; v < n; v++) if (need[v] == 0) ready.addLast(v);
    List<Integer> order = new ArrayList<>();
    if (trace) System.out.println("start ready=" + ready + " need=" + Arrays.toString(need));
    while (!ready.isEmpty()) {
        int v = ready.removeFirst();
        order.add(v);
        for (int w : next.get(v)) {
            if (--need[w] == 0) ready.addLast(w); // Только последняя предпосылка открывает w.
        }
        if (trace) System.out.println("remove=" + v + " ready=" + ready + " need=" + Arrays.toString(need));
    }
    List<Integer> blocked = new ArrayList<>();
    for (int v = 0; v < n; v++) if (need[v] != 0) blocked.add(v);
    return new Order(order, blocked); // Остаток включает потомков цикла, а не только сам цикл.
}

Почему результат корректен: когда снимаем v, каждая её предпосылка уже стоит в результате. Поэтому все рёбра направлены вперёд по порядку. Если очередь опустела раньше, в оставшемся конечном графе каждая вершина имеет входящее ребро. Следуя по предпосылкам назад, обязательно повторим вершину — значит, существует цикл. И наоборот, вершины цикла никогда не потеряют последнюю предпосылку друг от друга.

Для списков соседей время O(V+E), дополнительное состояние O(V), сама построенная структура O(V+E). Независимые вершины допускают разные правильные порядки. Нужен минимальный по номеру доступный шаг — замени FIFO на min-heap; время станет O(E+V log(V+1)). В задаче ниже проверяется свойство порядка, а не совпадение с одним эталонным массивом.

В работающем планировщике снять вершину означает получить успешное завершение, а не только отправить задачу на исполнение. Один успех должен уменьшать счётчик ровно один раз. Повторное событие без защиты может открыть report слишком рано; ошибка capture требует отдельного решения о зависимых задачах. Топологический порядок сам по себе не задаёт поведение при ошибках и повторных запусках.

Цикл замыкается на активную ветку, а не на любую посещённую вершину

Кан сообщил, что полного порядка нет. Хочется назвать ошибочную цепочку и показать её владельцу. Но список blocked — это не список вершин цикла. Если report ждёт capture, которая попала в цикл, report тоже останется заблокированной, хотя пути из report обратно в capture нет.

Для конкретного цикла пройдём DFS с тремя состояниями. 0 — ещё не начинали, 1 — вершина в текущей цепочке вызовов, 2 — её исходящие рёбра проверены. Ребро v → w к состоянию 1 замыкает путь w → … → v из стека. Ребро к состоянию 2 ведёт в завершённую ветку и само по себе цикл не доказывает.

Рекурсию заменим кадрами Frame. Кадр хранит вершину и индекс следующего ребра. Простого стека всех соседей недостаточно для этой модели: сосед уже обнаружен, но ещё не обязательно находится на текущем пути DFS. Состояние 2 ставится только когда кадр действительно заканчивает перебор рёбер:

static final class Frame {
    final int vertex;
    int nextEdge;
    Frame(int vertex) { this.vertex = vertex; }
}
static List<Integer> cycle(int n, int[][] edges) {
    List<List<Integer>> next = graph(n, edges);
    int[] color = new int[n], parent = new int[n];
    Arrays.fill(parent, -1);
    for (int start = 0; start < n; start++) {
        if (color[start] != 0) continue; // Проверяем и отдельные компоненты.
        ArrayDeque<Frame> stack = new ArrayDeque<>();
        color[start] = 1;
        stack.push(new Frame(start));
        while (!stack.isEmpty()) {
            Frame frame = stack.peek();
            int v = frame.vertex;
            if (frame.nextEdge == next.get(v).size()) {
                color[v] = 2;          // Все рёбра проверены: ветка действительно завершена.
                stack.pop();
                continue;
            }
            int w = next.get(v).get(frame.nextEdge++); // Сохраняем место возврата в v.
            if (color[w] == 1) {
                List<Integer> found = new ArrayList<>();
                for (int x = v; x != w; x = parent[x]) found.add(x);
                found.add(w);
                Collections.reverse(found);
                found.add(w);          // Последнее ребро v -> w замыкает путь.
                return found;
            }
            if (color[w] == 0) {
                parent[w] = v;
                color[w] = 1;
                stack.push(new Frame(w));
            }                         // color=2: уже завершённая ветка, цикла не доказывает.
        }
    }
    return List.of();
}

Метод использует graph из предыдущего шага. Родители ведут от текущей вершины v к активному предку w; разворачиваем этот участок и дописываем w, чтобы последняя дуга явно закрыла цикл. Один кадр и один цвет на вершину дают O(V) состояния; со структурой графа общий объём O(V+E), время O(V+E).

Петля v → v — цикл длины в одно ребро. Две параллельные дуги 0 → 1 ориентированного цикла не создают. В Кане их нужно учитывать согласованно: два прибавления к need и два уменьшения. Внешний проход по всем вершинам нужен и здесь: обход только из 0 пропустит цикл в другой компоненте.

Почему правило для неориентированного графа другое

У неориентированного ребра u—v есть запись в обоих списках соседей. Возврат v → u к родителю не является новым циклом, поэтому его пропускают. В мультиграфе нельзя пропускать все рёбра к вершине-родителю: второе параллельное ребро образует цикл длины 2. Тогда хранят идентификатор ребра и пропускают только ребро, по которому пришли. Наши примеры ниже ориентированные; правило трёх цветов применяется к ним напрямую.

Обход можно сокращать, только если отметка описывает всё состояние

Все решения выше отбрасывают повторный путь к уже обнаруженному состоянию. Для острова состояние — координата. Для обычного кратчайшего пути — та же координата, потому что будущие переходы не зависят от истории прихода. Для DFS цикла к номеру вершины добавляется этап обработки, а кадр хранит место возврата.

Если можно один раз разрушить стену, попадание в клетку с ещё доступным разрушением отличается от попадания без него. Одно seen[r][c] потеряет полезный вариант. Состоянием станет (r,c,оставшийся лимит), а отметки потребуют O(R·C·(K+1)) мест при лимите K. Ключи, маска уже выполненных действий и направление последнего движения расширяют состояние по той же причине.

Ближайший из нескольких терминалов ищется одной волной: пометь все старты расстоянием 0 и положи их в общую очередь до начала обработки. Это multi-source BFS, минимальное расстояние до любого старта. Отдельный полный обход от каждого из S стартов стоил бы O(S·(V+E)); общий — O(V+E). Для сетки соседей вычисляй на месте, без создания объектов для каждого возможного ребра.

При разных стоимостях переходов первое обнаружение уже не закрепляет лучший путь. Для весов 0/1 нужен 0-1 BFS с релаксацией; для неотрицательных весов — Дейкстра. Их выбор и представление графа разобраны в Graphs. Если нужно перечислить все допустимые пути, глобальная отметка подавит разные решения; там появится состояние текущего пути и откат — Backtracking.

Рекурсивный DFS хранит глубину в стеке вызовов: длинная цепочка зависит от доступного размера стека. Явные кадры помещают её в heap и убирают это ограничение, но не стоимость O(V) памяти. Матрица visited и массив дистанций тоже имеют цену: при миллионах клеток используй компактные массивы и храни только данные, которые нужны ответу. Меняющийся граф требует согласованного снимка либо протокола обновлений: счётчики, рассчитанные по старым рёбрам, не описывают новые зависимости.

На собеседовании начни с модели: что является вершиной, какие переходы разрешены, что считается длиной. Затем назови инвариант отметки, покажи момент её изменения и прогони ромб, отдельную компоненту, пустой вход и отсутствие ответа. Оценку сложности обоснуй числом обработок каждой вершины и каждого ребра. Так объяснение выдержит изменение условия, а не только знакомый тест.

  • На матрице граф можно обходить без хранения рёбер: соседей задают разрешённые сдвиги.
  • Отметка при постановке даёт одну запись в очереди на вершину; общая отметка на все старты даёт компоненты.
  • BFS закрепляет кратчайшее расстояние при первом обнаружении для одинаковой цены перехода. Число клеток отличается от числа рёбер на один.
  • Кан разрешает шаг после последней предпосылки. Неполный результат доказывает цикл, но его остаток включает и зависимые от цикла вершины.
  • Ориентированный цикл выдаёт ребро к активному предку DFS. Явный кадр хранит индекс следующего ребра и честно отмечает завершение.

Подсказка 2

Одного visited хватает на все старты. Помечай клетку до добавления в очередь; соседей получай четырьмя сдвигами.

Решение

Каждый старт забирает всю ещё не обнаруженную компоненту. Внешний проход гарантирует, что ни одна отдельная область не пропущена. Отметку храним отдельно, поэтому второй вызов на той же матрице увидит тот же вход.

static int solve(int[][] grid) {
    int rows = grid.length, cols = rows == 0 ? 0 : grid[0].length;
    boolean[][] seen = new boolean[rows][cols];
    int[][] directions = {{0,1},{1,0},{0,-1},{-1,0}};
    int count = 0;
    for (int r = 0; r < rows; r++) {
        for (int c = 0; c < cols; c++) {
            if (grid[r][c] == 0 || seen[r][c]) continue;
            count++;                   // Считаем старт компоненты, а не каждую клетку.
            ArrayDeque<int[]> queue = new ArrayDeque<>();
            seen[r][c] = true;
            queue.addLast(new int[]{r,c});
            while (!queue.isEmpty()) {
                int[] v = queue.removeFirst();
                for (int[] d : directions) {
                    int nr = v[0] + d[0], nc = v[1] + d[1];
                    if (nr < 0 || nr >= rows || nc < 0 || nc >= cols) continue;
                    if (grid[nr][nc] == 0 || seen[nr][nc]) continue;
                    seen[nr][nc] = true; // Один раз ставим в очередь, без изменения grid.
                    queue.addLast(new int[]{nr,nc});
                }
            }
        }
    }
    return count;
}

Решение

dist одновременно хранит длину пути и отметку обнаружения. Внутренние сдвиги −1..1 дают восемь соседей после пропуска (0,0). При извлечении цели расстояние окончательно; можно закончить раньше, чем очередь опустеет.

static int solve(int[][] grid) {
    int n = grid.length;
    if (n == 0 || grid[0][0] != 0 || grid[n-1][n-1] != 0) return -1;
    int[][] dist = new int[n][n];
    for (int[] row : dist) Arrays.fill(row, -1);
    ArrayDeque<int[]> queue = new ArrayDeque<>();
    dist[0][0] = 1;                   // Здесь длина в клетках: старт тоже входит в путь.
    queue.addLast(new int[]{0,0});
    while (!queue.isEmpty()) {
        int[] v = queue.removeFirst();
        if (v[0] == n-1 && v[1] == n-1) return dist[v[0]][v[1]];
        for (int dr = -1; dr <= 1; dr++) {
            for (int dc = -1; dc <= 1; dc++) {
                if (dr == 0 && dc == 0) continue;
                int r = v[0] + dr, c = v[1] + dc;
                if (r < 0 || r >= n || c < 0 || c >= n) continue;
                if (grid[r][c] != 0 || dist[r][c] != -1) continue;
                dist[r][c] = dist[v[0]][v[1]] + 1; // Отметка одновременно с расстоянием.
                queue.addLast(new int[]{r,c});
            }
        }
    }
    return -1;
}

Снятие вершины уменьшает счётчик каждого её соседа. В конце сравни размер результата с n.

Решение

Кан выдаёт полный порядок тогда и только тогда, когда сняты все вершины. Повторные рёбра сохранены в списке и в счётчике: каждое снимается один раз. Проверка в заготовке принимает любой правильный порядок, но отсекает пропущенные и повторные вершины.

static int[] solve(int n, int[][] edges) {
    List<List<Integer>> next = new ArrayList<>();
    for (int v = 0; v < n; v++) next.add(new ArrayList<>());
    int[] need = new int[n];
    for (int[] e : edges) {
        next.get(e[0]).add(e[1]);     // e[0] надо выполнить до e[1].
        need[e[1]]++;
    }
    ArrayDeque<Integer> ready = new ArrayDeque<>();
    for (int v = 0; v < n; v++) if (need[v] == 0) ready.addLast(v);
    int[] order = new int[n];
    int size = 0;
    while (!ready.isEmpty()) {
        int v = ready.removeFirst();
        order[size++] = v;
        for (int w : next.get(v)) if (--need[w] == 0) ready.addLast(w);
    }
    return size == n ? order : new int[0]; // Частичный порядок не решает всю задачу.
}

Подсказка 1

visited не отличает завершённую ветку от текущей. Введи цвета 0,1,2.

Подсказка 2

Верхний кадр хранит следующий индекс ребра. Ребро к цвету 1 — цикл; цвет 2 ставится только после исчерпания соседей.

Решение

Кадры повторяют состояние рекурсивного вызова. В каждый момент вершины цвета 1 образуют текущую цепочку DFS. Внешний проход начинает новую цепочку только из цвета 0, поэтому цикл в отдельной компоненте тоже найдётся. Проверка с 20 000 вершинами подтверждает работу на длинном пути.

static boolean solve(int n, int[][] edges) {
    List<List<Integer>> next = new ArrayList<>();
    for (int v = 0; v < n; v++) next.add(new ArrayList<>());
    for (int[] e : edges) next.get(e[0]).add(e[1]);
    int[] color = new int[n];
    for (int start = 0; start < n; start++) {
        if (color[start] != 0) continue;
        ArrayDeque<Frame> stack = new ArrayDeque<>();
        color[start] = 1;
        stack.push(new Frame(start));
        while (!stack.isEmpty()) {
            Frame frame = stack.peek();
            int v = frame.vertex;
            if (frame.nextEdge == next.get(v).size()) {
                color[v] = 2;               // Завершение только после последнего ребра.
                stack.pop();
                continue;
            }
            int w = next.get(v).get(frame.nextEdge++);
            if (color[w] == 1) return true;  // Путь по стеку w ... v замыкается ребром v -> w.
            if (color[w] == 0) {
                color[w] = 1;
                stack.push(new Frame(w));
            }
        }
    }
    return false;
}

Требование без рекурсии убрали. Можно просто заменить рекурсию стеком всех соседей?

Для достижимости такой стек подходит, но цвет 1 должен означать активный путь, а не все обнаруженные вершины. Если заранее покрасить соседей, два ещё не обработанных соседа могут ошибочно выглядеть предками друг друга. Сохраняй кадр возврата или используй события входа и выхода, которые воспроизводят последовательность DFS.
