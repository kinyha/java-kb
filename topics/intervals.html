Intervals

Отрезок задаёт занятую часть одной оси. Если упорядочить его границы, можно закончить работу с прошлым и больше к нему не возвращаться. Для слияния достаточно последнего расширяемого компонента; для пересечений двух списков — их текущих голов; для количества слотов — всех ещё не закончившихся окон. Сначала реши, входит ли правая граница: одно равенство меняет и пересечение, и порядок освобождения ресурсов.

Равные границы дают разные ответы при разных правилах занятости

Платёжный сервис получил окна доступности банковского шлюза. Их нужно объединить в расписание, найти общие окна двух банков или понять, сколько обработчиков нужно для всех платежей. Проверка каждого окна с каждым стоит O(n²): при 100 000 интервалов это почти пять миллиардов неупорядоченных пар. Но задача о покрытии обычно не требует перечислять все конфликтующие пары.

Для пары A и B общая часть начинается в max(A.start, B.start) и заканчивается в min(A.end, B.end). Это следствие двух требований: точка должна быть не раньше обоих начал и не позже обоих концов. Сама формула границ ещё не говорит, является ли результат непустым.

Закрытый [left,right] включает обе границы. При left = right он содержит одну точку. Полуоткрытый [start,end) включает начало и исключает конец; [t,t) пуст. Для расписания удобно считать, что обработчик освободился в end и сразу может взять работу, начинающуюся в этот момент.

Все опыты — самостоятельные файлы JDK 21, без зависимостей: examples/intervals, запуск java MergeDemo.java и аналогично для остальных. Фрагмент MergeDemo.java сравнивает одинаковые числа с двумя правилами:

static boolean overlaps(int[] a, int[] b, boolean closed) {
    int left = Math.max(a[0], b[0]), right = Math.min(a[1], b[1]);
    return closed ? left <= right : left < right;
}

Для закрытых границ общая часть существует при left ≤ right. Для полуоткрытых — при left < right. В уроке merge, insert и пересечения работают с закрытыми интервалами. Занятость слотов работает с полуоткрытыми окнами положительной длины. Это разные условия входа, их нельзя незаметно смешать.

Достаточно заменить ≤ на < во всех задачах про время.

Сначала назови нужный результат. У [1,3) и [3,5) нет одновременной занятости, но их объединение всё равно можно записать одним [1,5). Слияние соседнего покрытия и подсчёт пересечений — разные вопросы.

Сортировка по началу позволяет расширять только последний компонент

Окна [8,10], [2,3], [1,7], [6,9] пришли без порядка. Отсортируем по start: [1,7], [2,3], [6,9], [8,10]. Держим готовые непересекающиеся компоненты и последний current. Для каждого next достаточно сравнить его начало с правой границей current.

Если next.start ≤ current.end, окна имеют общую точку. Их объединение начинается в current.start и заканчивается в max(current.end, next.end). Если next.start > current.end, между ними есть разрыв. Старый компонент готов: все последующие начала будут ещё правее, поэтому расширить его они уже не смогут.

Инвариант после обработки префикса: результат в точности покрывает обработанные окна, компоненты упорядочены и не пересекаются. У всех, кроме последнего, конец окончательный. При новом разрыве окончательным становится и последний. Это объясняет один проход после сортировки и необходимость сравнивать с накопленным концом, а не с концом предыдущего входного интервала.

Фрагменты MergeDemo.java. Каждый компонент результата получает свою строку массива. Сортируем копию внешнего массива, чтобы сохранить исходный порядок:

static int[][] merge(int[][] input, boolean trace) {
    int[][] sorted = input.clone(); // Копируем порядок ссылок; строки ниже только читаем.
    Arrays.sort(sorted, Comparator.comparingInt(a -> a[0]));
    List<int[]> result = new ArrayList<>();
    for (int[] next : sorted) {
        if (result.isEmpty() || next[0] > result.getLast()[1]) {
            result.add(next.clone()); // Новый компонент; ответ не разделяет строки со входом.
        } else {
            int[] current = result.getLast();
            current[1] = Math.max(current[1], next[1]); // Вложенный интервал не сокращает конец.
        }
        if (trace) System.out.println("next=" + Arrays.toString(next) + " result=" + Arrays.deepToString(result.toArray()));
    }
    return result.toArray(int[][]::new);
}

static int[][] wrongMerge(int[][] input) {
    int[][] sorted = input.clone(); Arrays.sort(sorted, Comparator.comparingInt(a -> a[0]));
    List<int[]> result = new ArrayList<>();
    for (int[] next : sorted) {
        if (result.isEmpty() || next[0] > result.getLast()[1]) result.add(next.clone());
        else result.getLast()[1] = next[1]; // Ошибка: вложение отодвигает конец влево.
    }
    return result.toArray(int[][]::new);
}

Копирование порядка и копирование границ решают разные задачи

System.out.println("shallow source=" + Arrays.deepToString(source));

У int[][] внешний clone копирует ссылки на строки. Запись shallow[0][1] меняет ту же строку во входе. В merge эти строки только читаются, а в result добавляются next.clone(), поэтому последующая запись в ответ не меняет fresh. Время O(n log n) из-за сортировки, проход O(n). В этом Java-коде дополнительная память O(n): копия порядка и служебная память сортировки; сам ответ занимает O(k) строк для k компонентов.

Если вход уже отсортирован, проход занимает O(n). Если разрешена перезапись входа, можно складывать компоненты в его префикс и вернуть число действительных строк. Оценка памяти зависит от такого API; показанный вариант намеренно сохраняет вход и создаёт самостоятельный ответ.

Вставка проходит левый префикс, расширяемое окно и правый суффикс

Теперь расписание уже упорядочено, и его закрытые интервалы попарно не пересекаются. Добавляем [4,8] в [1,2], [3,5], [6,7], [8,10], [12,16]. Новая сортировка не нужна: ответ собирается из трёх последовательных зон за O(n).

Сначала копируем интервалы, чей end строго меньше нового left. Они заканчиваются раньше вставки и её не коснутся. Затем поглощаем каждый интервал, чей start ≤ текущего right: расширяем left через min, right через max. Правый конец обновляется во время прохода, поэтому следующий интервал сравнивается с новым окном.

В нашем примере [3,5] расширит начало до 3, [6,7] останется внутри, [8,10] расширит конец до 10. Как только следующий start больше right, добавляем накопленное окно и копируем остаток. Поскольку исходные компоненты отдельны, дальше все начала ещё правее; нового пересечения уже не будет.

Фрагменты PairDemo.java. В added границы не меняем: локальные left и right позволяют сохранить вход:

static int[][] insert(int[][] input, int[] added, boolean trace) {
    List<int[]> result = new ArrayList<>();
    int i = 0, left = added[0], right = added[1];
    while (i < input.length && input[i][1] < left) {
        result.add(input[i++].clone()); // Левый префикс уже не пересечётся с добавленным.
    }
    while (i < input.length && input[i][0] <= right) {
        left = Math.min(left, input[i][0]);
        right = Math.max(right, input[i][1]); // Расширенный конец влияет на следующий шаг.
        if (trace) System.out.println("absorb=" + Arrays.toString(input[i]) + " pending=[" + left + ", " + right + "]");
        i++;
    }
    result.add(new int[]{left, right});
    while (i < input.length) result.add(input[i++].clone()); // Правый суффикс не затронут.
    return result.toArray(int[][]::new);
}

Если исходные окна пересекаются между собой или идут без порядка, три зоны такого доказательства не имеют: сначала нормализуй их слиянием.

При пересечении двух расписаний продвигается раньше закончившийся интервал

Банк A доступен в [0,2], [5,10], [13,16], банк B — в [1,5], [8,12], [15,18]. Внутри каждого списка интервалы уже упорядочены и попарно не пересекаются. Перебор всех пар стоил бы O(mn); два индекса i и j позволяют отбросить пару так, чтобы к ней больше не возвращаться.

Для текущих A[i] и B[j] вычисляем max начала и min конца. Непустую общую часть добавляем. Затем двигаем индекс меньшего конца. Если A закончился раньше B, следующий интервал B начнётся строго после конца текущего B, а значит, и после конца A. Этот A больше никогда не даст нового пересечения с B.

Тот же аргумент работает, если общая часть пустая: более ранний конец уже позади другого интервала. При равных концах можно продвинуть оба индекса. Все будущие интервалы каждого списка лежат строго дальше этой координаты. За итерацию продвигается хотя бы один индекс, поэтому суммарно их не больше m + n.

static int[][] intersect(int[][] a, int[][] b, boolean trace) {
    List<int[]> result = new ArrayList<>();
    int i = 0, j = 0;
    while (i < a.length && j < b.length) {
        int left = Math.max(a[i][0], b[j][0]);
        int right = Math.min(a[i][1], b[j][1]);
        if (left <= right) result.add(new int[]{left, right}); // Для закрытых границ точка тоже ответ.
        if (trace) System.out.println("i=" + i + " j=" + j + " candidate=[" + left + ", " + right + "] add=" + (left <= right));
        if (a[i][1] < b[j][1]) i++; // Раньше закончившийся уже не встретит следующий из другого списка.
        else if (a[i][1] > b[j][1]) j++;
        else { i++; j++; } // Оба конца исчерпаны.
    }
    return result.toArray(int[][]::new);
}

Число слотов определяется пиком занятости, который слияние стирает

Платежи [0,5), [1,3), [2,4), [5,7) уже имеют заданные начала и окончания. Их нельзя переносить или пропускать. Нужно минимальное число одинаковых слотов, чтобы обработать все. В момент 2 активны первые три платежа, поэтому меньше трёх слотов заведомо недостаточно.

Сортируем по start и храним в min-heap окончания активных окон. Перед очередным стартом удаляем все окончания ≤ start: эти слоты уже свободны. Добавляем новый end и обновляем исторический максимум размера heap. Окончания будущих платежей ещё не входят в heap; исчезнувшие не возвращаются.

Это число одновременно активных окон. Его хватает: когда есть свободный слот, новый платёж занимает его; если свободного нет, приходится добавить ровно один. В момент добавления все ранее выделенные слоты заняты, поэтому нижняя граница одновременности тоже выросла. Так получаем и необходимость, и достаточность максимума.

Фрагменты RoomsDemo.java. Heap здесь хранит только активные окончания, а не по одному окончанию всех когда-либо выделенных слотов. Для читаемой трассы сортируем отдельную копию элементов heap:

static int rooms(int[][] input, boolean trace) {
    int[][] sorted = input.clone();
    Arrays.sort(sorted, Comparator.comparingInt(a -> a[0]));
    PriorityQueue<Integer> ends = new PriorityQueue<>();
    int best = 0;
    for (int[] interval : sorted) {
        while (!ends.isEmpty() && ends.peek() <= interval[0]) ends.remove(); // [start,end): конец освобождает слот.
        ends.add(interval[1]);
        best = Math.max(best, ends.size()); // Размер после последнего старта не хранит прошлый пик.
        if (trace) {
            List<Integer> ordered = new ArrayList<>(ends); Collections.sort(ordered);
            System.out.println("start=" + interval[0] + " activeEnds=" + ordered + " best=" + best);
        }
    }
    if (trace) System.out.println("final active=" + ends.size());
    return best;
}

События дают тот же пик, если освобождение идёт раньше нового старта

Вместо heap можно создать два события на окно: +1 в start и −1 в end. Сортируем по времени; при равном времени для [start,end) сначала идут −1. После каждого события обновляем active и best. Это проход по границам — sweep line: состояние меняется только там, где окно началось или закончилось.

static int events(int[][] input, boolean startsFirst, boolean trace) {
    List<int[]> events = new ArrayList<>();
    for (int[] interval : input) {
        events.add(new int[]{interval[0], 1});
        events.add(new int[]{interval[1], -1});
    }
    events.sort((a, b) -> {
        int order = Integer.compare(a[0], b[0]);
        if (order != 0) return order;
        return startsFirst ? Integer.compare(b[1], a[1]) : Integer.compare(a[1], b[1]);
    }); // Для [start,end) события -1 стоят раньше +1 при одном времени.
    int active = 0, best = 0;
    for (int[] event : events) {
        active += event[1]; best = Math.max(best, active);
        if (trace) System.out.println("t=" + event[0] + " delta=" + event[1] + " active=" + active + " best=" + best);
    }
    return best;
}

Нужное состояние выбирается по вопросу, а не по слову «интервал»

У похожих данных разные ответы. Для покрытия достаточно конца текущего компонента. Для общих окон нужны две текущие головы. Для вместимости ресурса требуется количество активных окон. На собеседовании сначала произнеси смысл ответа, правила границ и порядок входа, затем объясни, почему выбранное прошлое можно забыть.

Выбрать максимум непересекающихся работ — другая цель

Здесь разрешается отбрасывать работы и нужен максимум их числа в одном слоте. Жадный выбор с самым ранним окончанием оптимален: первую работу любого оптимального расписания можно заменить на раньше заканчивающуюся без потери остальных. Затем повторяем аргумент на оставшемся хвосте. Сортировка по началу такого свойства не даёт: [0,10) закроет путь коротким [1,2), [2,3), [3,4).

Если у работ разная ценность, замена может потерять сумму: раннее окончание само по себе больше не оптимально. Нужна другая постановка и, например, динамическое программирование. Meeting rooms решает задачу «разместить все», а этот выбор — «оставить часть».

В сервисе числовая ось должна иметь одну единицу, точность и систему отсчёта. Сравнение местного времени двух зон не задаёт порядок мгновений; сначала приведи границы к общей шкале, например Instant. Потеря долей секунды при округлении способна превратить разрыв в касание. Затем реши, как считаются отменённые и пустые окна, и только после этого переноси алгоритм.

Проверки ниже специально включают вложение, касание, одинаковые начала, отсутствие пересечений и крайние int. Сохраняем вход и проверяем, что строки ответа с ним не разделяются. Одного обычного примера с двумя частично пересекающимися окнами недостаточно: он не обнаружит ни сокращение конца, ни путаницу пика с конечным размером heap.

  • Правила границ решают, является ли касание пересечением и когда освобождается ресурс.
  • После сортировки по началу слияние хранит последний компонент; его конец обновляется через max.
  • Вставка проходит три зоны без сортировки. Пересечения двух списков отбрасывают меньший конец.
  • Объединённое покрытие теряет кратность. Минимум слотов равен максимальной одновременности исходных окон.
  • Учитывай сохранение входа, память сортировки и результата. Сравнение границ и вычисление расстояния — разные операции.

Подсказка 2

Если следующее начало не дальше конца последнего компонента, обнови конец через max. Иначе создай новый компонент. Clone внешнего массива сохраняет порядок, clone каждой строки ответа сохраняет независимость.

Решение

Сортируем копию ссылок по start. В ответе готовые компоненты и один расширяемый последний. Вложение не должно сокращать его конец; новый разрыв завершает компонент навсегда.

static int[][] solve(int[][] input) {
    int[][] sorted = input.clone(); // Копируем порядок ссылок; строки ниже только читаем.
    Arrays.sort(sorted, Comparator.comparingInt(a -> a[0]));
    List<int[]> result = new ArrayList<>();
    for (int[] next : sorted) {
        if (result.isEmpty() || next[0] > result.getLast()[1]) {
            result.add(next.clone()); // Новый компонент; ответ не разделяет строки со входом.
        } else {
            int[] current = result.getLast();
            current[1] = Math.max(current[1], next[1]); // Вложенный интервал не сокращает конец.
        }
    }
    return result.toArray(int[][]::new);
}

Подсказка 2

Левый префикс заканчивается строго раньше left. В середине проверяй start ≤ текущего right и обновляй обе границы. Как только start > right, добавь накопленное окно и остаток.

Решение

Порядок и отдельность входных компонентов позволяют пройти три зоны один раз. Сравнение в средней зоне использует уже расширенный right; это включает цепочку пересечений.

static int[][] solve(int[][] input, int[] added) {
    List<int[]> result = new ArrayList<>();
    int i = 0, left = added[0], right = added[1];
    while (i < input.length && input[i][1] < left) {
        result.add(input[i++].clone()); // Левый префикс уже не пересечётся с добавленным.
    }
    while (i < input.length && input[i][0] <= right) {
        left = Math.min(left, input[i][0]);
        right = Math.max(right, input[i][1]); // Расширенный конец влияет на следующий шаг.
        i++;
    }
    result.add(new int[]{left, right});
    while (i < input.length) result.add(input[i++].clone()); // Правый суффикс не затронут.
    return result.toArray(int[][]::new);
}

Решение

Более ранний конец ограничивает общую часть и делает свой интервал бесполезным для будущих окон другого списка. Проверка left ≤ right сохраняет даже точечное пересечение.

static int[][] solve(int[][] a, int[][] b) {
    List<int[]> result = new ArrayList<>();
    int i = 0, j = 0;
    while (i < a.length && j < b.length) {
        int left = Math.max(a[i][0], b[j][0]);
        int right = Math.min(a[i][1], b[j][1]);
        if (left <= right) result.add(new int[]{left, right}); // Для закрытых границ точка тоже ответ.
        if (a[i][1] < b[j][1]) i++; // Раньше закончившийся уже не встретит следующий из другого списка.
        else if (a[i][1] > b[j][1]) j++;
        else { i++; j++; } // Оба конца исчерпаны.
    }
    return result.toArray(int[][]::new);
}

    static void checkFresh(int[][] result, int[][] input) {
        for (int[] row : result) for (int[] old : input)
            if (row == old) throw new AssertionError("shared row");
    }
    static void check(int[][] input, int want) {
        int[][] before = copy(input); int got = solve(input);
        if (got != want) throw new AssertionError("got=" + got + " want=" + want);
        checkInput(before, input);
        System.out.println("OK rooms=" + got + " input=" + Arrays.deepToString(input));
    }
}
Подсказка 1

Нужен максимум одновременности, а не число объединённых интервалов. Перед новым стартом важно найти все уже освободившиеся окончания.

Подсказка 2

Сортируй по start и храни активные end в min-heap. Удали все end ≤ start, добавь новый end, обнови best. Верни исторический best, не размер heap после последней итерации.

Решение

Каждый активный платёж требует свой слот. Проход по стартам с удалением закончившихся окон вычисляет максимум этого количества. Он и необходим, и достаточен для размещения всех платежей.

static int solve(int[][] input) {
    int[][] sorted = input.clone();
    Arrays.sort(sorted, Comparator.comparingInt(a -> a[0]));
    PriorityQueue<Integer> ends = new PriorityQueue<>();
    int best = 0;
    for (int[] interval : sorted) {
        while (!ends.isEmpty() && ends.peek() <= interval[0]) ends.remove(); // [start,end): конец освобождает слот.
        ends.add(interval[1]);
        best = Math.max(best, ends.size()); // Размер после последнего старта не хранит прошлый пик.

    }
    return best;
}

O(n log n) времени и O(n) дополнительной памяти: копия порядка, сортировка и heap. Один вложенный while не делает проход квадратичным — каждое окончание удаляется один раз.

Можно заменить heap двумя отсортированными массивами начал и концов либо событиями. При одинаковой координате для полуоткрытых окон сначала освобождай. Не смешивай heap активных окончаний с вариантом, который хранит по одному окончанию каждого выделенного слота: у второго другая трактовка размера и повторного использования.
