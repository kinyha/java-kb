Linked List

В связном списке порядок задают поля next у отдельных узлов. Передвинуть локальную ссылку и изменить next — разные действия: первое выбирает другой узел, второе меняет маршрут для всех, кто видит тот же объект. Алгоритм должен удержать необработанный остаток до перезаписи ссылок. При смене первого узла он возвращает новую голову. Два указателя помогают найти нужное место, но их скорости и точка остановки требуют своего объяснения.

Передвижение ссылки не меняет список, запись next меняет его для всех

Очередь платежей хранит A:10 → B:20 → C:30 → null. В задаче нужно поменять порядок операций, сохранив сами объекты. Можно собрать значения в массив, развернуть его и создать новые узлы: O(n) времени и памяти, но внешние ссылки останутся на старых объектах. Если нужен именно тот же набор узлов, работать придётся с их связями.

head — ссылка на первый узел; пустой список задаётся null. У узла есть значение и ссылка next. Последний next равен null. Это наш собственный односвязный Node, а не внутренний узел java.util.LinkedList. Буква id нужна для наблюдения личности объекта: два узла с одним value остаются разными операциями.

Для опытов используем один и тот же Node и вспомогательные методы. nodes создаёт небольшую цепочку A, B, C; show печатает путь и отмечает повторное посещение объекта, чтобы демо цикла не зависло. Память печати не входит в оценку памяти алгоритмов. Полные файлы лежат в examples/linked-list, запускаются java ИмяDemo.java на JDK 21:

static final class Node {
    final String id; // Имя объекта для трассы; совпадение value не означает один объект.
    final int value;
    Node next;
    Node(String id, int value) { this.id = id; this.value = value; }
}

static Node[] nodes(int... values) {
    Node[] result = new Node[values.length];
    for (int i = 0; i < values.length; i++) {
        result[i] = new Node(i < 26 ? String.valueOf((char) ('A' + i)) : "N" + i, values[i]);
        if (i > 0) result[i - 1].next = result[i];
    }
    return result;
}

static Node head(Node[] values) { return values.length == 0 ? null : values[0]; }

static String id(Node n) { return n == null ? "null" : n.id; }

static String show(Node n) {
    List<String> result = new ArrayList<>();
    Set<Node> seen = Collections.newSetFromMap(new IdentityHashMap<>());
    while (n != null) {
        if (!seen.add(n)) { result.add("cycle(" + n.id + ")"); break; }
        result.add(n.id + ":" + n.value);
        n = n.next;
    }
    return result.toString(); // Только печать использует O(n) память, не алгоритм.
}

Присваивание cursor = cursor.next оставляет прежние поля next нетронутыми. Присваивание локальному параметру head тоже не переименовывает переменную у вызывающего: Java передаёт копию ссылки. А head.next = null меняет общий объект A и обрывает путь через него:

static void reset(Node head) { head = null; }

static void cut(Node head) { head.next = null; }

Внешняя голова осталась A после reset. Но после cut из неё виден только A. Сохранённая ссылка на B всё ещё даёт B→C: эти узлы не исчезли от одной записи в другом объекте. Изменился путь, по которому их можно найти.

Проход по m узлам стоит O(m), доступ к i-му узлу от головы — O(i). Одна запись next стоит O(1), если нужный узел уже найден. У односвязного узла нет ссылки назад: для удаления узла из цепочки обычно нужен его предшественник. Полезно заранее сказать, что алгоритм получает и какие ссылки ему приходится искать.

Разворот сохраняет продолжение, затем переносит узел в обратную цепочку

Для ациклического списка обойдёмся тремя ссылками: prev, current и сохранённым next. Перед итерацией prev ведёт в уже развёрнутый префикс, current — в ещё не обработанную часть исходного порядка. Эти две части содержат все исходные узлы, не пересекаются и заканчиваются null. В начале первая часть пустая.

Чтобы перенести current, сначала сохрани current.next. Затем запиши current.next = prev. Только после этого сдвигай prev на current, а current на сохранённое продолжение. Запись поля разрушает старое ребро, но next удерживает остаток. В конце current пуст, а prev содержит весь список в обратном порядке.

Фрагменты ReverseDemo.java. Трасса показывает сохранение продолжения, смену ребра и восстановление инварианта:

static Node reverse(Node head, boolean trace) {
    Node prev = null, current = head;
    while (current != null) {
        Node next = current.next; // Сохраняем продолжение до перезаписи поля.
        if (trace) System.out.println("save current=" + id(current) + " next=" + id(next));
        current.next = prev; // Один узел переходит в развёрнутую часть.
        if (trace) System.out.println("link " + id(current) + ".next=" + id(prev));
        prev = current;
        current = next;
        if (trace) System.out.println("prev=" + id(prev) + " current=" + id(current));
    }
    return prev; // Новая голова — последний обработанный узел.
}

Память O(1): постоянное число ссылок, новых узлов нет. Время O(n): каждый узел переносится ровно один раз. У рекурсивного разворота останутся O(n) кадров стека, а допустимая глубина зависит от стека потока. Возврат головы должен быть использован вызывающим: head = reverse(head). Старая head сама не начнёт указывать на C.

Ацикличность здесь — часть условия: при повторном посещении узла доказательство «каждый переносится один раз» исчезает. Циклическую структуру сначала распознай, а не передавай в этот разворот.

Относительная скорость находит середину и цикл, но встреча ещё не даёт вход

Если длина заранее неизвестна, slow идёт по одному ребру, fast по двум. В ациклической цепочке, когда fast достиг конца, slow прошёл примерно половину пути. Проверка fast != null && fast.next != null защищает обе операции fast.next.next; short-circuit не даёт читать next у null.

Фрагменты RunnerDemo.java. В этом соглашении оба начинаются в голове, а при чётной длине возвращается вторая середина:

static Node middle(Node head) {
    Node slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
    }
    return slow; // При чётной длине — вторая из двух середин.
}

У цикла проверяем совпадение ссылок после движения. Пока slow ещё до входа, повторения там нет. Когда оба внутри, fast за итерацию сокращает отставание по кругу на одно ребро и за не больше чем длину цикла догонит slow. Само начальное slow = fast = head ничего не доказывает — оно есть и у обычной цепочки.

static Node entry(Node head, boolean trace) {
    Node slow = head, fast = head;
    int step = 0;
    while (fast != null && fast.next != null) { // Проверки защищают оба перехода fast.
        slow = slow.next;
        fast = fast.next.next;
        if (trace) System.out.println("step=" + ++step + " slow=" + id(slow) + " fast=" + id(fast));
        if (slow == fast) { // Сравниваем ссылки, не суммы платежей.
            Node finder = head;
            if (trace) System.out.println("reset finder=" + id(finder) + " meet=" + id(slow));
            while (finder != slow) {
                finder = finder.next;
                slow = slow.next;
                if (trace) System.out.println("finder=" + id(finder) + " meet=" + id(slow));
            }
            return finder;
        }
    }
    return null;
}

static boolean wrongValueCycle(Node head) {
    Node slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (fast != null && slow.value == fast.value) return true; // Ошибка: разные объекты имеют одинаковые value.
    }
    return false;
}

Почему возврат одного указателя в голову даёт вход

Обозначим μ — число рёбер от головы до входа, λ — длину цикла. До встречи slow сделал t шагов, fast — 2t. Их разность t кратна λ, иначе они стояли бы в разных местах круга. Если x — смещение места встречи от входа, то x ≡ t − μ по модулю λ. Получается μ + x ≡ 0 по модулю λ.

Теперь finder из головы идёт по одному ребру, второй указатель идёт по одному от встречи. Через μ шагов первый достигнет входа. Второй за это время сместится из x на μ и тоже попадёт во вход. До этого finder стоит вне цикла, поэтому встреча раньше невозможна. В примере μ = 2, λ = 3, встреча D имеет x = 1: μ + x = 3.

Первый проход занимает O(μ + λ), второй O(μ), память O(1). Если нужен только факт цикла, второй проход не нужен. Если нужна длина цикла, от места встречи можно пройти один круг и сосчитать рёбра. Для стабильной структуры понятия входа и длины однозначны; при параллельной перезаписи next это доказательство уже не описывает один неизменный граф.

Служебная голова и хвост собирают слияние из исходных узлов

Пришли две очереди, отсортированные по приоритету: A1:1→A3:3→A5:5 и B2:2→B3:3→B6:6. Они ациклические и не имеют общих узлов. Нужно собрать одну отсортированную цепочку из тех же объектов. Самый маленький ещё не выбранный элемент находится в голове одной из очередей: глубже по ней меньшего уже не будет.

Без служебного узла первый выбранный элемент потребовал бы отдельной ветки для головы. Создадим dummy, tail сначала указывает на него. Каждый шаг выбирает меньшую голову, сдвигает соответствующий вход, записывает tail.next и двигает tail. Возвращаем dummy.next; значение служебного узла не сравнивается с платежами.

Инвариант: цепочка от dummy.next до tail содержит уже выбранные узлы в отсортированном порядке, а a и b задают головы оставшихся входов. Поле tail.next ещё может указывать в необработанный остаток выбранного списка. Следующая запись его заменит. Доказательство использует границу tail, а не требует null после каждого шага.

Фрагменты MergeDemo.java. На равных выбираем из первого списка через ≤ — это сохраняет порядок внутри каждого входа и ставит равные узлы первого раньше равных узлов второго:

static Node merge(Node a, Node b, boolean trace) {
    Node dummy = new Node("DUMMY", 0), tail = dummy;
    while (a != null && b != null) {
        Node chosen;
        if (a.value <= b.value) { chosen = a; a = a.next; } // При равенстве первый список идёт раньше.
        else { chosen = b; b = b.next; }
        tail.next = chosen; // Присоединяем исходный объект, не копируем его value.
        tail = chosen;
        if (trace) System.out.println("take=" + id(chosen) + " a=" + id(a) + " b=" + id(b) + " tail=" + id(tail));
    }
    tail.next = a != null ? a : b; // Оставшаяся цепочка уже отсортирована.
    if (trace) System.out.println("append=" + id(tail.next) + " tail=" + id(tail));
    return dummy.next; // Сам служебный узел не входит в результат.
}

Когда один вход закончился, другой остаток уже отсортирован и не меньше выбранного хвоста. Его присоединяем одной записью. Время O(m + n), дополнительная память O(1), включая один dummy. Копирование только значений в новые узлы означало бы другой результат и O(m + n) дополнительной памяти. Оно подходит, когда старые очереди должны остаться прежними. Выбор между переносом и копированием следует из владения объектами, а не из желания показать более короткий код.

Фиксированный отрыв оставляет медленный указатель перед удаляемым узлом

Нужно убрать n-й узел с конца за один проход, причём n допустимо: 1 ≤ n ≤ длина. Поле предшественника должно начать указывать на следующий после удаляемого узел. Самой голове предшественник тоже нужен, поэтому перед ней ставим dummy.

slow и fast начинаются в dummy. Сначала fast делает n + 1 переходов. Затем оба двигаются по одному, сохраняя этот отрыв, пока fast не станет null. Нумеруем настоящие узлы с нуля; у dummy позиция −1. Для цепочки из L узлов slow остановится на позиции L − n − 1. Его следующий узел — как раз позиция L − n, то есть n-й с конца. Для удаления головы slow останется в dummy.

static Node remove(Node head, int n, boolean trace) {
    Node dummy = new Node("DUMMY", 0);
    dummy.next = head;
    Node slow = dummy, fast = dummy;
    for (int i = 0; i <= n; i++) {
        if (fast == null) throw new IllegalArgumentException("n exceeds length");
        fast = fast.next; // n+1 переходов: slow в конце окажется перед нужным узлом.
    }
    if (trace) System.out.println("gap=" + (n + 1) + " slow=" + id(slow) + " fast=" + id(fast));
    while (fast != null) {
        slow = slow.next;
        fast = fast.next;
        if (trace) System.out.println("slow=" + id(slow) + " fast=" + id(fast));
    }
    if (trace) System.out.println("bypass=" + id(slow.next));
    slow.next = slow.next.next; // Меняем входящую ссылку, value узлов не трогаем.
    return dummy.next;
}

В показанном варианте fast идёт до null и отрыв n + 1 оставляет slow на предшественнике. Другой вариант допускает отрыв n, но останавливается на fast.next == null. Смешение оставит slow на удаляемом узле или рядом с ним. Проверь удаление единственного, первого и последнего узла.

Правильные значения ещё не доказывают правильность связей

На собеседовании уточни, разрешено ли менять вход, существуют ли внешние ссылки на узлы и могут ли списки пересекаться. Разворот и слияние здесь меняют исходные next. Поиск входа в цикл только читает их. Слияние принимает отдельные цепочки, а не просто две разные переменные head.

Это существенное условие. В последнем фрагменте MergeDemo головы A и B различны, но обе ведут в один S. Обычное слияние при встрече одинаковых ссылок выберет S из одного входа и затем присоединит тот же S как остаток второго:

Простая подмена сравнения ≤ на < не устраняет проблему одного общего объекта.

Проверяй структуру вместе со значениями. В задачах ниже каждый результат сравнивается с исходными узлами через ==, затем проверяется отсутствие лишнего хвоста. Это ловит новые копии, потерю узлов и циклы. Для CycleEntry дополнительно сохранены все next до вызова: после него связи должны остаться прежними. Одинаковые value включены в проверки, чтобы сравнение значений не маскировало ошибку личности.

Локальная перенастройка ребра быстрая, но поиск предшественника часто доминирует. «Удаление O(1)» без указания уже известного узла и нужных ссылок — неполная оценка. В двусвязном списке доступен prev, но появляются дополнительные поля и ещё связи, которые нужно поддержать. В Java LinkedList это внутренняя структура, публичный API собственные узлы не выдаёт.

Для частого доступа по индексу, компактного хранения и последовательного чтения чаще удобнее массив или ArrayList. У списка отдельные объекты и переходы по ссылкам; O(n) прохода не означает такое же реальное время, как у массива. Условия выбора и стандартные коллекции разобраны в Arrays & Lists. Для обычной очереди задач без необходимости держать узлы начни с подходящей стандартной коллекции.

Эти алгоритмы требуют стабильной структуры и разрешённого доступа к next. Параллельное изменение нескольких рёбер требует согласованного протокола, отдельные volatile-поля не делают разворот атомарным. Постоянная память также не означает неизменяемый вход. Перед кодом назови инвариант, после каждой записи объясни, какая ссылка теперь удерживает остаток, а в конце проверь и голову, и хвост.

  • Локальная ссылка выбирает узел, поле next задаёт маршрут. Внешние ссылки на те же объекты видят изменения маршрута.
  • При развороте сохрани продолжение до перезаписи next. Возвращаемая голова отличается от старой ссылки у вызывающего.
  • Fast/slow сравниваются по личности. Встреча доказывает цикл; второй проход с равными скоростями находит вход.
  • Dummy задаёт предшественника первого узла. Tail отделяет уже собранный префикс от остатка, даже если его next ещё не null.
  • Проверяй владение, отдельность списков и целостность графа: правильный набор значений может скрывать копии, потери и циклы.

Решение

static Node solve(Node head) {
    Node prev = null, current = head;
    while (current != null) {
        Node next = current.next; // До перенаправления сохраняем необработанный остаток.
        current.next = prev;
        prev = current;
        current = next;
    }
    return prev;
}

Подсказка 2

После встречи поставь один указатель в голову. Оба теперь движутся по одному ребру. Следующая встреча — вход в цикл; возвращай узел, а не его value.

Решение

Встреча доказывает цикл, но обычно находится глубже входа. Число шагов slow до встречи кратно длине цикла. Поэтому расстояние от головы до входа компенсирует смещение места встречи: сброс одного указателя в голову и равные скорости сводят их во входе.

static Node solve(Node head) {
    Node slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next; fast = fast.next.next;
        if (slow == fast) {
            Node finder = head;
            while (finder != slow) { finder = finder.next; slow = slow.next; }
            return finder; // Это сам узел входа, а не его value.
        }
    }
    return null;
}

При a.value ≤ b.value присоединяй a и сдвигай a. Иначе присоединяй b. После каждого выбора двигай tail; после завершения одного входа присоедини второй остаток целиком.

Решение

Tail ограничивает уже выбранный отсортированный префикс, головы входов ограничивают остатки. Выбираем минимальную голову, сохраняя порядок, и переставляем ребро предыдущего хвоста. При завершении одного входа весь второй остаток уже подходит.

static Node solve(Node a, Node b) {
    Node dummy = new Node("DUMMY", 0), tail = dummy;
    while (a != null && b != null) {
        if (a.value <= b.value) { tail.next = a; a = a.next; }
        else { tail.next = b; b = b.next; }
        tail = tail.next; // Готовый префикс растёт на один исходный узел.
    }
    tail.next = a != null ? a : b;
    return dummy.next;
}

Слияние изменяет доступные через старые головы пути, поэтому входы нельзя считать прежними независимыми списками. Общий хвост нарушает условие: обычный алгоритм способен создать самопетлю. Если исходные структуры должны сохраниться, копируй узлы; если пересечения допустимы, сначала определи, как должен выглядеть один общий объект в результате.

Подсказка 1

Чтобы обойти удаляемый узел, нужна ссылка на его предшественника. Dummy даёт такого предшественника даже первой настоящей голове.

Подсказка 2

Начни оба указателя с dummy. Fast сделает n + 1 переходов, затем оба идут по одному до fast == null. Теперь slow.next — удаляемый узел.

Решение

Фиксированный отрыв превращает достижение конца одним указателем в известное положение другого. Отрыв n + 1 и остановка на null оставляют slow перед n-м с конца. Одна запись next обходит узел, возврат dummy.next покрывает удаление головы.

static Node solve(Node head, int n) {
    Node dummy = new Node("DUMMY", 0); dummy.next = head;
    Node slow = dummy, fast = dummy;
    for (int i = 0; i <= n; i++) fast = fast.next; // n+1 переходов, n допустимо по условию.
    while (fast != null) { slow = slow.next; fast = fast.next; }
    slow.next = slow.next.next; // slow — предшественник, включая dummy для удаления головы.
    return dummy.next;
}

Если API принимает произвольное n, вначале проверь положительность и при создании отрыва отвергни выход за длину.
