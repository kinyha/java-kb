Quick Sort

Чтобы упорядочить платежи по сумме, можно сначала разложить их относительно одного выбранного значения: меньшие слева, большие справа. После этого части сортируются независимо. Quick sort строится вокруг такого разбиения. Хорошее разбиение сокращает следующую работу, а плохое снова оставляет почти весь массив. От выбора опоры, обработки повторов и границ вызовов зависят и скорость, и глубина стека.

Одно разбиение ставит опору на место, но ещё не сортирует части

Для отчёта нужно отсортировать массив сумм платежей. Перебирать все пары и менять их местами дорого; сортировка вставками на обратном порядке тоже двигает всё больше элементов. В merge sort мы сначала получали отсортированные половины и затем соединяли их. Здесь попробуем сделать полезную работу до рекурсии: разделим значения по отношению к опоре.

Pivot — выбранное значение сравнения, а partition — проход, переставляющий элементы относительно него. В первом варианте возьмём последнюю сумму 300. Пройдем все остальные элементы: меньшие 300 перенесём в начало. Указатель place обозначает следующую позицию этой левой области. В конце поставим выбранную опору на place.

static long visits; // счётчик итераций для опыта следующего шага
static int partition2(int[] a, int lo, int hi) { // диапазон [lo, hi), hi не включён
    int pivot = a[hi - 1], place = lo;
    for (int j = lo; j < hi - 1; j++) {
        visits++;
        if (a[j] < pivot) swap(a, place++, j); // расширяем область меньших
    }
    swap(a, place, hi - 1);                   // опора в окончательной позиции
    return place;
}
static void swap(int[] a, int x, int y) {
    int t = a[x]; a[x] = a[y]; a[y] = t;
}
// Фрагмент QuickSortDemo.main.
int[] a = {400, 200, 500, 100, 300};
int q = partition2(a, 0, a.length);
System.out.println(Arrays.toString(a) + " pivot-index=" + q);
[200, 100, 300, 400, 500] pivot-index=2

Число 300 уже находится на допустимом месте в отсортированном массиве: слева только меньшие значения, справа — не меньшие. Но 200 стоит перед 100. Partition установил отношение между областями; порядок внутри левой области ещё предстоит получить. Поэтому следующие вызовы сортируют [lo, q) и [q + 1, hi), исключая уже установленную опору.

Доказательство опирается на инвариант прохода. Перед каждой проверкой [lo, place) содержит меньшие, [place, j) — не меньшие, [j, hi − 1) ещё неизвестны. Обмен переносит найденный меньший элемент в правильную область и расширяет её. Когда неизвестные закончились, последний обмен завершает контракт.

У разных partition разные ответы. Этот вариант Lomuto возвращает позицию опоры. Классическая схема Hoare с двумя встречными указателями возвращает границу раздела; опора не обязана стоять на ней. Для включительных границ её рекурсия обычно идёт по [lo, j] и [j + 1, hi]. Нельзя взять partition из одного варианта и диапазоны рекурсии из другого: можно потерять элемент или повторять тот же диапазон бесконечно.

Все демо — single-file Java на JDK 21. Запуск из корня: java examples/quick-sort/QuickSortDemo.java. Полный файл содержит выводы урока и счётчики; README — команды трёх задач. На странице показаны все условия, которые меняют результат, а служебные метки секций из вывода убраны.

Опора определяет, сколько прежней работы останется на следующий проход

На массиве n значений один partition работает за Θ(n). Если опора делит различные значения примерно пополам, на следующем уровне две части вместе снова содержат около n элементов, а уровней примерно log₂n. Получается Θ(n log n). Рекурсия не ускоряет сам проход: она сокращает размер следующих задач.

Теперь данные уже отсортированы, а опора всегда последняя. Она максимальна. После прохода остаётся часть размера n − 1, затем n − 2 и так далее. Работа внутреннего цикла в нашем двухстороннем варианте равна (n − 1) + (n − 2) + … + 1 = n(n − 1)/2. Идеальный вход для чтения оказывается худшим входом для этого выбора опоры.

То же происходит на одинаковых значениях с нашим строгим сравнением a[j] < pivot: ни один элемент не попадает слева, опора ставится в начало, а остальные снова уходят в правую часть. Замена на <= меняет сторону большой части, но сохраняет цепочку. Это недостаток конкретной схемы обработки равных, а не любой реализации quick sort.

// QuickSortDemo: extremeWork проходит цепочку крайних опор циклом,
// чтобы измерить работу без тысячи вложенных вызовов.
static long extremeWork(int[] a) {
    visits = 0;
    int lo = 0, hi = a.length;
    while (hi - lo > 1) {
        int q = partition2(a, lo, hi); // visits++ на каждой итерации j
        if (q == lo) lo = q + 1;
        else if (q == hi - 1) hi = q;
        else throw new AssertionError("fixture must pick an extreme");
    }
    return visits;
}
int[] increasing = new int[1000], equal = new int[1000];
for (int j = 0; j < increasing.length; j++) increasing[j] = j;
Arrays.fill(equal, 7);
System.out.println("last-pivot / increasing = " + extremeWork(increasing));
System.out.println("last-pivot / equal = " + extremeWork(equal));

last-pivot / equal = 499500

Счётчик показывает число итераций основного цикла, а не миллисекунды и не все машинные инструкции. Квадратичная цепочка подтверждается числом 1000 × 999 / 2. Для миллиона строк уже нельзя считать плохую опору мелкой постоянной в алгоритме с ожидаемым n log n.

Можно один раз случайно перемешать вход, затем брать фиксированную позицию. Можно выбирать случайную позицию при каждом partition. В учебном коде ниже второй вариант использует SplittableRandom(42): фиксированный seed нужен для воспроизводимости вывода. Ожидаемая оценка относится к случайному выбору, а один известный seed не превращается в защиту от специально подобранного входа.

Случайный выбор и обработка повторов решают разные проблемы. Если все значения равны, любая позиция даст ту же опору. Следующий шаг уберёт равные из дальнейшей рекурсии сразу целой группой.

Трёхстороннее разбиение сразу завершает работу над равными значениями

В платёжном журнале много одинаковых сумм: фиксированный тариф, одна стоимость подписки, несколько популярных цен. Переставлять их снова на каждом уровне бессмысленно. Разделим текущий диапазон на четыре области: меньшие опоры, равные, ещё не проверенные и большие. В конце неизвестная область исчезнет, а равные уже займут все свои места между внешними частями.

Границы хранят три указателя. [lo, lt) меньше pivot, [lt, i) равно pivot, [i, gt + 1) ещё неизвестно, [gt + 1, hi) больше pivot. Проверяем a[i]. При меньшем переносим его к lt и двигаем оба указателя; при равном двигаем только i. При большем меняем с a[gt] и уменьшаем gt, сохраняя i: с правого края пришло ещё не проверенное значение.

record Band(int first, int afterLast) {} // полуинтервал всех равных опоре
static Band partition3(int[] a, int lo, int hi, int pivot, boolean trace) {
    int lt = lo, i = lo, gt = hi - 1;
    if (trace) show(a, lt, i, gt);
    while (i <= gt) {
        visits++;                             // одна проверка неизвестного элемента
        if (a[i] < pivot) swap(a, lt++, i++); // с позиции lt пришёл уже известный равный
        else if (a[i] > pivot) swap(a, i, gt--); // новый a[i] ещё нужно проверить
        else i++;
        if (trace) show(a, lt, i, gt);
    }
    return new Band(lt, gt + 1);
}
static void show(int[] a, int lt, int i, int gt) {
    System.out.println(Arrays.toString(a) + " lt=" + lt + " i=" + i + " gt=" + gt);
}
partition3(new int[]{4, 2, 5, 1, 4}, 0, 5, 4, true); // трассировка границ

После переноса 5 вправо индекс i остался равен 2. Там появилась 4, и следующий проход поместил её в равную область. В конце i = gt + 1, неизвестных больше нет. Меньшие 2 и 1 ещё не отсортированы, зато обе 4 исключаются из рекурсии. На каждой итерации число неизвестных уменьшается ровно на один, поэтому сам проход линейный.

int[] equal = new int[1000];
Arrays.fill(equal, 7);
visits = 0;
Band b = partition3(equal, 0, equal.length, 7, false); // перегрузка полного демо
System.out.println("three-way / equal = " + visits + " band=" + b.first + ".." + b.afterLast);
three-way / equal = 1000 band=0..1000

Все тысяча значений оказались в [0, 1000) равных. Слева и справа пусто: сортировка закончена одним partition. Это Θ(n) для данного входа вместо 499 500 проверок старой схемы. На разных значениях по-прежнему остаются внешние части; трёхсторонний проход не даёт общей гарантии линейной сортировки.

Равные элементы не меняются друг с другом, значит сортировка стабильна.

Другие обмены могут развернуть их порядок. Для A:4, B:2, C:4, D:1 перенос D в левую область меняет его с A, и равные оказываются C перед A. Три области сохраняют отношение ключей, а не исходный порядок записей с одним ключом.

record Payment(String id, int amount) {
    @Override public String toString() { return id + ":" + amount; }
}
static void sortPayments(Payment[] a, int lo, int hi) {
    if (hi - lo < 2) return;
    int pivot = a[lo].amount, lt = lo, i = lo, gt = hi - 1;
    while (i <= gt) {
        if (a[i].amount < pivot) swap(a, lt++, i++);
        else if (a[i].amount > pivot) swap(a, i, gt--);
        else i++;
    }
    sortPayments(a, lo, lt);
    sortPayments(a, gt + 1, hi);
}
static void swap(Payment[] a, int x, int y) {
    Payment t = a[x]; a[x] = a[y]; a[y] = t;
}
Payment[] payments = {new Payment("A", 4), new Payment("B", 2),
        new Payment("C", 4), new Payment("D", 1)};
sortPayments(payments, 0, payments.length);
System.out.println(Arrays.toString(payments));
[D:1, B:2, C:4, A:4]

Платёж A раньше C во входе, а после сортировки — позже. Если порядок равных важен, выбери стабильный алгоритм или включи исходную позицию в ключ, осознавая изменение сравнения. Контракт сортировки объектов и работа Comparator разобраны в Sorting Basics; конкретные реализации JDK — в Sorting in Java.

Меньшую часть можно передать в рекурсию, большую — обработать циклом

Самая простая версия вызывает sort для обеих внешних частей. При ровном делении глубина стека O(log n), но при цепочке крайних опор она достигает O(n). Тогда вместе с квадратичной работой приходит риск StackOverflowError. Фраза «quick sort не требует дополнительного массива» не отменяет кадры вызовов.

Глубину можно ограничить независимо от качества опоры. После partition выбираем меньшую внешнюю часть для рекурсивного вызова. Когда он вернулся, продолжаем сортировку большей части в том же кадре, меняя lo или hi в цикле. Каждая новая вложенность получает не больше половины элементов текущего диапазона, поэтому одновременно живых кадров O(log n) даже при плохом делении.

static void sort(int[] a) {
    sort(a, 0, a.length, new SplittableRandom(42), 1);
}
static void sort(int[] a, int lo, int hi, SplittableRandom random, int depth) {
    maxDepth = Math.max(maxDepth, depth);      // учебный счётчик глубины sort
    while (hi - lo > 1) {
        int pivot = a[random.nextInt(lo, hi)]; // значение есть в текущем диапазоне
        Band equal = partition3(a, lo, hi, pivot, false);
        if (equal.first - lo < hi - equal.afterLast) {
            sort(a, lo, equal.first, random, depth + 1); // меньшая слева
            lo = equal.afterLast;              // большая справа в прежнем кадре
        } else {
            sort(a, equal.afterLast, hi, random, depth + 1);
            hi = equal.first;
        }
    }
}
int[] input = {4, 2, 5, 1, 4};
maxDepth = 0; sort(input);
System.out.println(Arrays.toString(input));
int[] manyEqual = new int[100_000]; Arrays.fill(manyEqual, 7);
maxDepth = 0; sort(manyEqual);
System.out.println("equal n=100000 maxDepth=" + maxDepth);
[1, 2, 4, 4, 5]
equal n=100000 maxDepth=2

В счётчике учтён и пустой вызов меньшей части, поэтому у одинаковых значений глубина 2: внешний кадр и один сразу возвращающийся пустой. Это глубина нашего метода sort, а не всех методов JVM. Равная полоса непуста, поскольку pivot выбран из диапазона; после её исключения работа обязательно сокращается.

Лимит стека не меняет число проверок плохой опоры. Если вместо случайного выбора всегда получать минимум, цикл всё ещё пройдёт части n, n − 1, n − 2. Память останется O(log n), время — O(n²). Java не обязана превращать хвостовой рекурсивный вызов в цикл: мы сделали это явно в коде.

Небольшие диапазоны часто заканчивают сортировкой вставками: у неё короткий цикл и малая цена запуска на маленьком входе. Гибрид может ограничить глубину разбиений и перейти на heap sort, получив верхнюю границу O(n log n). Это уже introsort, а не обещание обычного quick sort. Порог и детали гибрида выбирают по реализации и измерениям; универсального числа для всех массивов и процессоров нет.

In-place у quick sort обычно означает отсутствие второго массива длины n. Это не строгая O(1) всей вспомогательной памяти при наличии стека. Если нужна жёсткая O(1) память и O(n log n) время, рассмотрение heap sort начинается именно с этих требований, а не с названия алгоритма.

Для k-го значения после разбиения достаточно продолжить одну часть

В отчёте нужна вторая по величине сумма, а не полный порядок журнала. Полная сортировка решит задачу, но выполнит работу над обеими сторонами. После partition известно, где стоят все равные pivot. Если нужный индекс слева этой полосы, справа продолжать бессмысленно. Если справа — отбрасываем левую часть. Если внутри — ответ уже найден.

Это quickselect. Для k-го по убыванию с нумерацией от 1 искомая позиция в возрастающем порядке равна n − k. Повторы считаются отдельными элементами: в [5, 5, 2] второе значение — 5. «Вторая различная сумма» требует другого условия и предварительного решения, как учитывать равенства.

static int kthLargest(int[] input, int k) {
    if (k < 1 || k > input.length) throw new IllegalArgumentException("k out of range");
    int[] a = input.clone();                 // сохраняем порядок исходного журнала
    int target = a.length - k, lo = 0, hi = a.length;
    var random = new SplittableRandom(42);
    while (true) {
        int pivot = a[random.nextInt(lo, hi)];
        Band equal = partition3(a, lo, hi, pivot, false);
        if (target < equal.first) hi = equal.first;
        else if (target >= equal.afterLast) lo = equal.afterLast;
        else return pivot;                  // target попал в полосу равных
    }
}
int[] journal = {3, 2, 1, 5, 6, 4};
System.out.println("k=2: " + kthLargest(journal, 2));
System.out.println("journal: " + Arrays.toString(journal));
System.out.println("repeated maximum, k=2: " + kthLargest(new int[]{5, 5, 2}, 2));
k=2: 5
journal: [3, 2, 1, 5, 6, 4]

Target остаётся абсолютным индексом массива, потому что lo и hi ограничивают области внутри того же массива. Если бы ты копировал выбранную часть в новый массив, индекс пришлось бы пересчитать. Именно смешение этих двух моделей даёт частую ошибку «k нужно уменьшать после каждого прохода».

При случайном выборе опоры ожидаемая работа O(n): вместо двух рекурсивных ветвей остаётся одна, и размеры проходов в среднем быстро уменьшаются. Худший случай O(n²) сохраняется. Итеративный выбор внутри изменяемого массива требует O(1) дополнительной памяти; наш публичный метод намеренно делает clone и поэтому использует O(n). Эта копия защищает контракт вызывающего, а не необходима алгоритму.

Quickselect не сортирует оставшиеся части. Чтобы выдать top-k в порядке, придётся отдельно упорядочить выбранные элементы. Для маленького k в непрерывном потоке удобнее куча размера k: она не требует всех данных сразу. Для стабильной полной сортировки выбирай другой контракт. В рабочем Java-коде начни с библиотечной сортировки и измерений; собственная реализация нужна здесь для понимания разбиения и задач на интервью.

  • Partition устанавливает порядок между областями, а не внутри каждой. Его ответ определяет границы дальнейших вызовов.
  • Крайняя опора оставляет почти весь прежний диапазон и даёт квадратичную цепочку. Случайный выбор улучшает ожидаемое время.
  • Трёхсторонний проход исключает все равные значения из рекурсии, но не сохраняет исходный порядок равных записей.
  • Рекурсия меньшей части ограничивает стек O(log n), сохраняя возможность O(n²) времени.
  • Quickselect продолжает только область с нужным индексом. Повторы, мутация входа и порядок top-k требуют явных решений.

Задачи

Сгруппировать три значения одним проходом

Дан массив, каждый элемент которого равен 0, 1 или 2. Переставь его на месте так, чтобы сначала стояли все 0, затем все 1, затем все 2. Нужны O(n) времени и O(1) дополнительной памяти. Значения входа гарантированы условием; вызов библиотечного sort не используй.

[2,0,2,1,1,0] → [0,0,1,1,2,2]
[1,2,0] → [0,1,2]
[] → []

Подсказка 1

Пусть слева готова область 0, справа — область 2. Между ними держи проверенные 1 и неизвестные.

Подсказка 2

При переносе 2 вправо пришедшее значение нужно снова проверить. Проверки в main включают случай [1,2,0], который ломается при лишнем i++.

Решение

Это трёхсторонний partition вокруг 1. После него внешние области тоже уже упорядочены: все значения каждой области одинаковы. Рекурсия не нужна.

    static void group(int[] a) {
        int lo = 0, i = 0, hi = a.length - 1;
        while (i <= hi) {
            if (a[i] == 0) swap(a, lo++, i++);
            else if (a[i] == 2) swap(a, i, hi--);
            else i++;
        }
    }

OK [0, 2]
OK [1, 1, 1]
OK [2]
OK []

Каждая итерация уменьшает неизвестную область на один элемент. Время Θ(n), память O(1), вход меняется. Одних проверок на [2,0] мало: там ошибочное продвижение i после обмена может случайно дать верный результат.

Найти k-ю по величине сумму и сохранить исходный журнал

Верни k-й элемент по убыванию, считая повторные значения отдельно. k начинается с 1. Исходный массив нельзя менять. При k вне диапазона 1..n брось IllegalArgumentException, включая пустой вход. Требуется ожидаемое O(n) время; учти память, которую требует запрет мутации.

[3,2,1,5,6,4], k=2 → 5
[5,5,2], k=2 → 5
[-3,-1,-2], k=1 → -1
[], k=1 → IllegalArgumentException

Подсказка 1

Позиция ответа в возрастающем порядке равна n−k. Разбиение сообщает, находится ли она слева, справа или в группе равных.

Подсказка 2

Сначала проверь k, затем работай с копией. target — абсолютный индекс этой копии; сдвиг lo не требует уменьшить target.

Решение

Копируем вход один раз и выбираем случайную опору текущего диапазона. Равная полоса позволяет сразу завершить поиск, в том числе на повторных максимумах.

    static int select(int[] input, int k) {
        if (k < 1 || k > input.length) throw new IllegalArgumentException("k out of range");
        int[] a = input.clone();
        int target = a.length - k, lo = 0, hi = a.length;
        var random = new SplittableRandom(42);
        while (true) {
            int pivot = a[random.nextInt(lo, hi)];
            int lt = lo, i = lo, gt = hi - 1;
            while (i <= gt) {
                if (a[i] < pivot) swap(a, lt++, i++);
                else if (a[i] > pivot) swap(a, i, gt--);
                else i++;
            }
            if (target < lt) hi = lt;
            else if (target > gt) lo = gt + 1;
            else return pivot;
        }
    }

Ожидаемое время O(n), худшее O(n²). Стек O(1), но clone требует O(n) памяти по условию. Сравниваем числа операциями < и >, а не вычитанием: проверка MIN_VALUE / MAX_VALUE ловит переполнение ошибочного сравнения. main также сравнивает вход с сохранённой копией.

Отсортировать только диапазон, сохранив внешние элементы

Реализуй sortRange(a, lo, hi) для полуинтервала [lo, hi). Остальные позиции должны остаться прежними. Используй данный helper partition, равномерный случайный pivot и рекурсию только меньшей стороны; большая сторона обрабатывается циклом. При lo<0, hi>a.length или lo>hi брось IllegalArgumentException. Пустой диапазон допустим.

[3,2,1], lo=1, hi=1 → [3,2,1]

import java.util.SplittableRandom;

public class SubrangeSortDemo {
    record Band(int first, int afterLast) {}

    static void sortRange(int[] a, int lo, int hi) {

    static void sort(int[] a, int lo, int hi, SplittableRandom random) {

    static Band partition(int[] a, int lo, int hi, int pivot) {
        int lt = lo, i = lo, gt = hi - 1;
        while (i <= gt) {
            if (a[i] < pivot) swap(a, lt++, i++);
            else if (a[i] > pivot) swap(a, i, gt--);

Подсказка 1

После partition исключи всю равную полосу. Она уже имеет верное положение относительно обеих внешних частей.

Подсказка 2

Сравни длины внешних частей. Рекурсивно обработай меньшую, затем измени lo или hi, чтобы цикл продолжил большую. Базовое условие: hi−lo меньше 2.

Решение

Публичный метод проверяет границы один раз. Внутренний sort повторно разбивает только свою область; все обмены helper ограничены текущим диапазоном.

    static void sortRange(int[] a, int lo, int hi) {
        if (lo < 0 || hi > a.length || lo > hi) throw new IllegalArgumentException("bad range");
        sort(a, lo, hi, new SplittableRandom(42));
    }
    static void sort(int[] a, int lo, int hi, SplittableRandom random) {
        while (hi - lo > 1) {
            int pivot = a[random.nextInt(lo, hi)];
            Band b = partition(a, lo, hi, pivot);
            if (b.first - lo < hi - b.afterLast) {
                sort(a, lo, b.first, random);
                lo = b.afterLast;
            } else {
                sort(a, b.afterLast, hi, random);
                hi = b.first;
            }
        }
    }
