Binary Search

Бинарный поиск полезен, когда одна проверка позволяет окончательно исключить половину ещё возможных ответов. В отсортированных суммах сравнение с серединой показывает, где искать дальше. В задаче о вместимости проверка показывает, какие меньшие ответы уже не подойдут. Главная работа — доказать этот порядок, выбрать смысл обеих границ и сохранить возможный ответ при их движении. После этого цикл становится коротким, а ошибки на пустом входе и повторах — объяснимыми.

Сравнение с серединой исключает половину возможных позиций

Сверка получила отсортированные суммы платежей [10, 20, 30, 30, 30, 50, 80]. Нужно найти операцию на 80. Линейный поиск проверяет все семь позиций. Сортировка уже сообщает больше: если в середине 30, все значения левее тоже не больше 30 и точно не равны 80.

Храним область [left, right], оба края включены. Инвариант: если target вообще есть, хотя бы одна его копия остаётся внутри этой области. В середине меньше target — исключаем всё до middle включительно. Больше — исключаем всё от middle включительно. Равенство даёт готовый ответ, но пока не обещает первую копию.

Фрагменты SortedDemo.java, JDK 21. Счётчик считает сравнения с серединой, диагностическая печать не входит в оценку времени:

record Search(int index, int checks) {}

static Search linear(int[] values, int target) {
    int checks = 0;
    for (int i = 0; i < values.length; i++) {
        checks++;
        if (values[i] == target) return new Search(i, checks);
    }
    return new Search(-1, checks);
}

static Search exact(int[] values, int target, boolean trace) {
    int left = 0, right = values.length - 1, checks = 0;
    while (left <= right) { // Оба края входят в область ещё возможного ответа.
        int middle = left + (right - left) / 2;
        checks++;
        if (trace) System.out.println("exact [" + left + ", " + right + "] middle=" + middle + " value=" + values[middle]);
        if (values[middle] == target) return new Search(middle, checks);
        if (values[middle] < target) left = middle + 1; // middle уже проверен, исключаем его тоже.
        else right = middle - 1;
    }
    return new Search(-1, checks);
}

После неуспешной проверки осталось не больше половины прежних элементов. Для непустого массива максимум ⌊log₂ n⌋ + 1 проверок: в нашем входе три вместо семи. Память O(1). Пустой массив задаёт right = −1, цикл не начинается и возвращается −1.

Середина должна остаться внутри области

Формула (left + right) / 2 сначала складывает int. Сумма может переполниться ещё до деления. Для неотрицательных индексов left ≤ right безопасно left + (right − left) / 2: разность помещается, а результат не больше right. Сам массив для демонстрации ошибки не нужен:

System.out.println("== middle can overflow without an array ==");
int left = 1_600_000_000, right = 2_000_000_000;
System.out.println("naive middle=" + ((left + right) / 2));
System.out.println("safe middle=" + (left + (right - left) / 2));

naive middle=-347483648
safe middle=1800000000

Отрицательная середина не просто меняет точность поиска: чтение по такому индексу упадёт. Формула через разность безопасна здесь благодаря диапазону индексов. Если числовые границы могут пересекать весь диапазон отрицательных и положительных long, разность тоже требует проверки или более широкого представления.

При слишком маленьком значении достаточно left = middle.

middle уже не является ответом. Если осталось два элемента, нижняя середина равна left; такая запись оставит область прежней и цикл зависнет. Исключение middle через +1 или −1 следует из доказательства, а не из привычки.

Первую и последнюю копию находят через две границы

Для суммы 30 простое равенство может вернуть индекс 3, хотя первая копия имеет индекс 2. Поиск соседних равных после первого совпадения превращается в O(n) на длинной серии дублей. Вместо этого ищем переход между «ещё меньше 30» и «уже не меньше 30».

Lower bound — первая позиция со значением ≥ target. Upper bound — первая позиция со значением > target. Их ответ находится среди n + 1 позиций, включая позицию после последнего элемента. Равные значения занимают полуинтервал [lower, upper), их число upper − lower. Если обе границы совпали, target отсутствует.

Для lower bound храним ещё не классифицированные элементы в [left, right). Перед итерацией все индексы меньше left имеют значения < target, а все индексы от right — значения ≥ target. Проверка середины расширяет одну из этих доказанных частей. Когда неизвестная часть пуста, left = right разделяет их.

static int firstAtLeast(int[] values, int target, boolean trace) {
    int left = 0, right = values.length;
    while (left < right) { // Неисследованные элементы находятся в [left, right).
        int middle = left + (right - left) / 2;
        if (trace) System.out.println("lower [" + left + ", " + right + ") middle=" + middle + " value=" + values[middle]);
        if (values[middle] < target) left = middle + 1;
        else right = middle; // Равный элемент может быть первым: сохраняем его как границу.
    }
    return left; // Может оказаться n — это позиция, а не читаемый элемент.
}

static int firstGreater(int[] values, int target) {
    int left = 0, right = values.length;
    while (left < right) {
        int middle = left + (right - left) / 2;
        if (values[middle] <= target) left = middle + 1; // Проходим всю серию равных.
        else right = middle;
    }
    return left;
}

При равенстве lower bound двигает right в middle: эта позиция ещё может стать первой подходящей. Сам middle больше не входит в неизвестные элементы, но остаётся возможной позицией границы. Upper bound пропускает равенства через left = middle + 1. Смысл правого края отличается от точного поиска: здесь right начинается с n, а цикл использует left < right.

Найденная позиция вставки не означает наличие target. Для 25 вернулся индекс 2, но там лежит 30. Для 90 вернулся n = 7, который вообще нельзя читать. Чтобы проверить наличие, сначала сравни границу с длиной, затем значение с target; порядок этих проверок защищает выход за массив.

Upper bound можно получить как lower bound от target + 1.

В полном диапазоне int это ломается на Integer.MAX_VALUE: +1 превращается в Integer.MIN_VALUE. В демо правильная верхняя граница равна 2, а такой обходной путь возвращает 0. Сравнение ≤ target сохраняет смысл без арифметического преобразования цели.

Arrays.binarySearch возвращает другой результат

При наличии дублей Arrays.binarySearch возвращает индекс одной найденной копии; выбор первой или последней не гарантирован. При отсутствии он возвращает −(insertionPoint + 1). Поэтому −1 означает позицию вставки 0, а не единственный код «не найдено». В перегрузке с диапазоном fromIndex включён, toIndex исключён, найденный или декодированный индекс относится ко всему исходному массиву:

Для диапазона [2, 5) вставка 20 оказалась в абсолютной позиции 2. При равенстве компаратора у объектов поиск тоже не обязан совпадать с equals: сортировка и поиск должны использовать один порядок.

Достаточно монотонной проверки, сам вход сортировать не нужно

Сервис отправляет пакеты данных в порядке [7, 2, 5, 10, 8]. За один день канал выдерживает не больше C единиц, завершить передачу нужно максимум за два дня. Пакеты нельзя дробить или переставлять. Какую минимальную дневную вместимость выбрать? Возможных значений много, но допустимость упорядочена: если C уже хватает, любое большее значение тоже хватит.

Это поиск по ответу. Предикат fits(C) сначала false, после некоторой границы становится true и больше не меняется обратно. Условие «ровно два дня» не нужно: если хватило одного, это тоже допустимо. Веса пакетов не отсортированы; упорядоченным является пространство вместимостей.

Проверяем C одним проходом. Добавляем очередной пакет в текущий день, пока он помещается. При превышении открываем следующий день. Неотрицательные веса позволяют жадно брать максимально длинный префикс: любое допустимое решение за первый день возьмёт не больше такого префикса, значит, жадная граница не отстаёт. По той же причине на каждом следующем дне жадный способ использует минимальное число дней для выбранного C.

Фрагменты CapacityDemo.java. −1 из daysNeeded означает, что даже отдельный пакет не помещается:

static int daysNeeded(int[] weights, long capacity) {
    if (weights.length == 0) return 0;
    int used = 1;
    long load = 0;
    for (int weight : weights) {
        if (weight > capacity) return -1; // Даже отдельный пакет не помещается.
        if (load + weight > capacity) { used++; load = 0; }
        load += weight; // Порядок пакетов сохраняется, ничего не переставляем.
    }
    return used;
}

System.out.println("== capacity predicate ==");
int[] weights = {7, 2, 5, 10, 8};
for (long capacity : new long[]{10, 15, 17, 18, 21, 32}) {
    int used = daysNeeded(weights, capacity);
    System.out.println("capacity=" + capacity + " days=" + used + " fits in 2=" + (used >= 0 && used <= 2));
}

Нижняя граница — максимальный вес пакета, верхняя — сумма всех весов. Верхняя точно допустима: все пакеты можно передать за один день. Теперь минимальный ответ лежит в включённом числовом диапазоне [left, right]. Это не диапазон элементов массива из прошлого шага. Допустимая середина остаётся возможным ответом, недопустимая исключается вместе со всеми меньшими.

static long minimum(int[] weights, int days, boolean trace) {
    if (days < 1) throw new IllegalArgumentException("days must be positive");
    long left = 0, right = 0;
    for (int weight : weights) {
        if (weight < 0) throw new IllegalArgumentException("negative weight");
        left = Math.max(left, weight); // Меньше самого большого пакета нельзя.
        right += weight; // Всё помещается за один день, значит, эта граница допустима.
    }
    while (left < right) { // Минимальный допустимый ответ лежит в [left, right].
        long middle = left + (right - left) / 2;
        int used = daysNeeded(weights, middle);
        boolean fits = used >= 0 && used <= days;
        if (trace) System.out.println("[" + left + ", " + right + "] middle=" + middle + " days=" + used + " fits=" + fits);
        if (fits) right = middle; // Допустимый middle остаётся возможным минимумом.
        else left = middle + 1;
    }
    return left;
}

Границы, текущая нагрузка и ответ считаются в long: сумма двух максимальных int уже больше int. Пустому входу нужна вместимость 0; нулевые веса допустимы и не ломают монотонность. Отрицательные веса изменили бы смысл проверки: максимальный префикс мог бы сначала превысить вместимость, а потом уменьшиться. В этой задаче они исключены.

Если верхняя граница не известна как допустимая, её нужно получить до поиска. Например, последовательно удваивать пробную величину до первого true с контролем переполнения и конечного предела. Иначе цикл может вернуть верхнюю границу, хотя подходящего ответа в рассматриваемом диапазоне вообще нет.

В повёрнутом массиве порядок нужно доказать для одной половины

Отсортированный массив циклически сдвинут: [40, 50, 60, 70, 10, 20, 30]. Обычное сравнение target с серединой уже не указывает сторону поиска: 10 меньше 70, но находится справа. При различных значениях внутри области есть не больше одного разрыва порядка. Поэтому хотя бы одна из половин [left, middle] или [middle, right] отсортирована.

Если a[left] ≤ a[middle], левая половина отсортирована. Проверяем не только сравнение с серединой, а принадлежность цели всему её диапазону. Цель в [a[left], a[middle]) — оставляем левую часть без уже проверенной середины. Иначе исключаем левую половину. Если она не отсортирована, симметрично проверяем (a[middle], a[right]] справа.

Фрагменты RotatedDemo.java. Предусловие distinct — все значения различны, массив получен одним циклическим сдвигом возрастающего массива:

static int distinct(int[] values, int target, boolean trace) {
    int left = 0, right = values.length - 1;
    while (left <= right) {
        int middle = left + (right - left) / 2;
        if (trace) System.out.println("[" + left + ", " + right + "] middle=" + middle + " value=" + values[middle]);
        if (values[middle] == target) return middle;
        if (values[left] <= values[middle]) { // Левая половина отсортирована.
            if (values[left] <= target && target < values[middle]) right = middle - 1;
            else left = middle + 1;
        } else { // Отсортирована правая половина.
            if (values[middle] < target && target <= values[right]) left = middle + 1;
            else right = middle - 1;
        }
    }
    return -1;
}

Равенство a[left] = a[middle] здесь означает половину из одного элемента, поэтому ≤ важно и для массива из двух элементов. До проверки порядка сначала проверяем сам middle на target. За итерацию исключаем половину области: O(log n) времени и O(1) памяти. Исходные позиции сохраняются.

Одинаковые края могут скрыть место разрыва

Для [1, 0, 1, 1, 1] середина и оба края равны 1. Из этого нельзя заключить, что левая половина [1, 0, 1] отсортирована. Если цель не равна середине, одинаковые края точно не являются ответом; их можно убрать по одному. Это сохраняет корректность, но больше не сокращает область вдвое.

record Search(int index, int checks) {}

static Search withDuplicates(int[] values, int target) {
    int left = 0, right = values.length - 1, checks = 0;
    while (left <= right) {
        int middle = left + (right - left) / 2;
        checks++;
        if (values[middle] == target) return new Search(middle, checks);
        if (values[left] == values[middle] && values[middle] == values[right]) {
            left++; right--; // Края точно не target, но сторону разрыва различить нельзя.
        } else if (values[left] <= values[middle]) {
            if (values[left] <= target && target < values[middle]) right = middle - 1;
            else left = middle + 1;
        } else {
            if (values[middle] < target && target <= values[right]) left = middle + 1;
            else right = middle - 1;
        }
    }
    return new Search(-1, checks);
}

System.out.println("== duplicates hide the sorted half ==");
int[] repeated = {1, 0, 1, 1, 1};
System.out.println("distinct-only on duplicates=" + distinct(repeated, 0, false));
Search correct = withDuplicates(repeated, 0);
System.out.println("duplicate-aware index=" + correct.index());
Search same = withDuplicates(new int[]{1, 1, 1, 1, 1, 1, 1, 1, 1}, 0);
System.out.println("all equal, absent index=" + same.index() + " checks=" + same.checks());

Версия только для различных значений пропустила существующий 0. Версия с обработкой неоднозначности нашла индекс 1. Для девяти одинаковых единиц и отсутствующего 0 она сделала пять проверок, снимая по два края. В общем случае худшая оценка O(n): единственное отличающееся значение может скрываться в ещё не проверенной части среди повторов. Обещать O(log n) для такого входа нельзя.

Другой путь при различных значениях — сначала найти место разрыва, затем искать в одной отсортированной части. Асимптотика останется O(log n). Выбор реализации зависит от того, нужен ли сам индекс минимального элемента для дальнейших операций; для одного поиска достаточно разобранной проверки половин.

Сначала объясни границы и цену проверки, затем обещай логарифм

На собеседовании начни с пространства ответов. Для позиции это массив, для вместимости — числа от максимального пакета до общей суммы. Скажи, почему одна проверка упорядочивает остальные варианты. Затем выбери, ищешь ли точное равенство, первый true или последний допустимый ответ. Это определит, какая середина сохраняется и какой край возвращается.

ВариантСмысл границДействие на совпадении
Точное значение[left, right] — возможные элементыВернуть middle; первая копия не обещана
Lower bound[left, right) — неизвестные элементы; позиция границы в [left, right]right = middle, продолжаем влево
Upper boundСлева значения ≤ target, справа > targetleft = middle + 1, продолжаем вправо
Минимальный допустимый ответ[left, right] — числовые ответы; right уже допустимПри true сохраняем middle как правую границу

Докажи, что ответ остаётся внутри, а область строго уменьшается. В полуинтервале при left < right середина всегда меньше right. Поэтому right = middle уменьшает правый край, left = middle + 1 увеличивает левый. При попытке искать последний true с left = middle нужна верхняя середина или иной шаблон, иначе короткая область перестанет уменьшаться. Шаблоны можно выбирать разные; их границы и обновления должны принадлежать одному доказательству.

Число проверок O(log n) ещё не означает такое же время. У массива чтение a[middle] стоит O(1). У связного списка поиск middle может сам идти по узлам. В поиске по ответу проверка часто проходит все данные, как в задаче о вместимости. У запроса к внешнему сервису сравнение может ждать сеть; к тому же меняющаяся во время поиска проверка нарушит устойчивость раздела false/true.

Перед циклом сортировать вход ради единственного запроса стоит O(n log n), а линейный поиск стоил бы O(n). Для множества запросов сортировка или подходящий индекс могут окупиться. Если исходные позиции важны, сортируй пары «значение, исходный индекс» или используй другую структуру: найденная позиция в отсортированной копии не является номером исходной операции.

Пустой вход, одна позиция, два соседних значения, все равные, цель меньше минимума и больше максимума проверяют края цикла. Границы int проверяют арифметику середины, суммы и преобразования цели. Для бинарного предиката отдельно проверь случаи «всё false» и «всё true», а также обоснование допустимой верхней границы. Для поиска по вещественным числам понадобятся заданная точность и правило завершения; int-обновления через ±1 к ним не относятся.

В проде полезно сначала проверить стабильность порядка: одним компаратором ли сортируется и ищется, сохраняется ли содержимое во время поиска, действительно ли предикат меняется в нужную сторону. Бинарный поиск ускоряет уже доказанную структуру задачи. Для произвольного порядка и немонотонного условия половину пространства исключать нечем.

  • Одна проверка должна окончательно исключать половину области; сортировка или монотонность дают это доказательство.
  • Точное равенство и граница — разные результаты. Равные значения занимают [lower, upper), но позиция вставки ещё не доказывает наличие.
  • Не смешивай включённый диапазон и полуинтервал. Правило сохранения middle следует из смысла ответа.
  • Поиск по ответу использует монотонную допустимость числовых ответов. Его время включает цену каждой проверки.
  • Повторы в повёрнутом массиве могут скрыть упорядоченную половину и ухудшить поиск до O(n).

static int solve(int value) {
    long left = 0, right = (long) value + 1; // Граница может не поместиться в int.
    while (left < right) {
        long middle = left + (right - left) / 2;
        if (middle * middle > value) right = middle; // Первый недопустимый квадрат.
        else left = middle + 1;
    }
    return (int) (left - 1); // Предыдущая позиция — последний допустимый корень.
}

Решение

Первый проход находит lower, где значения перестают быть меньше target. Если там нет target, ответа нет. Второй проход находит upper, где значения становятся строго больше. Равные значения лежат между этими границами, последний включённый индекс равен upper − 1.

static int[] solve(int[] values, int target) {
    int first = boundary(values, target, false);
    if (first == values.length || values[first] != target) return new int[]{-1, -1};
    return new int[]{first, boundary(values, target, true) - 1}; // Последний индекс включён.
}

static int boundary(int[] values, int target, boolean upper) {
    int left = 0, right = values.length;
    while (left < right) {
        int middle = left + (right - left) / 2;
        // Только upper пропускает равные значения: ищет первый строго больший элемент.
        if (values[middle] < target || (upper && values[middle] == target)) left = middle + 1;
        else right = middle;
    }
    return left;
}

Сначала проверь middle. Если values[left] ≤ values[middle], проверь, входит ли target в [values[left], values[middle]). Иначе проверь правый диапазон (values[middle], values[right]].

Массив имеет не больше одного разрыва порядка. Проверка концов левой половины позволяет определить отсортированную сторону. Принадлежность цели её диапазону сохраняет ровно одну половину с возможным ответом.

static int solve(int[] values, int target) {
    int left = 0, right = values.length - 1;
    while (left <= right) {
        int middle = left + (right - left) / 2;
        if (values[middle] == target) return middle;
        if (values[left] <= values[middle]) { // Левая половина упорядочена, включая один элемент.
            if (values[left] <= target && target < values[middle]) right = middle - 1;
            else left = middle + 1;
        } else { // Правая половина упорядочена; ищем цель в её диапазоне.
            if (values[middle] < target && target <= values[right]) left = middle + 1;
            else right = middle - 1;
        }
    }
    return -1;
}

Решение

Жадная проверка при выбранной вместимости не оставляет места, куда ещё поместился бы следующий пакет. Поэтому она использует минимальное число дней. Бинарный поиск выбирает первую вместимость, для которой это число не больше лимита; успешная середина остаётся возможным минимумом.

static long solve(int[] weights, int days) {
    long left = 0, right = 0;
    for (int weight : weights) {
        left = Math.max(left, weight);
        right += weight; // Верхняя граница допустима: всё уйдёт за один день.
    }
    while (left < right) {
        long middle = left + (right - left) / 2;
        if (canShip(weights, days, middle)) right = middle; // Успешная середина ещё может быть минимумом.
        else left = middle + 1;
    }
    return left;
}

static boolean canShip(int[] weights, int days, long capacity) {
    int used = 1;
    long load = 0;
    for (int weight : weights) {
        if (weight > capacity) return false;
        if (load + weight > capacity) {
            used++;
            load = 0; // Следующий пакет начинает новый день, порядок сохраняется.
            if (used > days) return false;
        }
        load += weight;
    }
    return true;
}
