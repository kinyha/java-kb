Скользящее окно

Перебор считает одно и то же много раз

Задача для разгона: дан массив и число k, найди максимальную сумму k подряд идущих элементов. Первое, что приходит в голову, — перебрать все начала и для каждого сложить k чисел:

static int maxSumBrute(int[] nums, int k) {
    int best = Integer.MIN_VALUE;
    for (int i = 0; i + k <= nums.length; i++) {
        int sum = 0;
        for (int j = i; j < i + k; j++) sum += nums[j];   // k сложений на каждое начало
        best = Math.max(best, sum);
    }
    return best;
}

Это O(n·k). При n = 10⁵ и k = 5·10⁴ — миллиарды операций, и решение не пройдёт по времени. Посмотри на два соседних отрезка: [2, 1, 5] и [1, 5, 1]. У них общие 1 и 5, а перебор складывает их заново. Отличаются соседние отрезки всего двумя элементами: один ушёл слева, один пришёл справа.

Скользящее окно использует именно это. Вместо того чтобы пересчитывать отрезок с нуля, мы двигаем его границы и обновляем ответ за O(1) на каждый шаг.

Окно фиксированного размера

Считаем сумму первых k элементов, а дальше на каждом шаге прибавляем элемент, вошедший справа, и вычитаем вышедший слева. Прощёлкай шаги:

static int maxSum(int[] nums, int k) {
    int sum = 0;
    for (int i = 0; i < k; i++) sum += nums[i];     // первое окно
    int best = sum;
    for (int r = k; r < nums.length; r++) {
        sum += nums[r] - nums[r - k];               // вошёл справа, вышел слева
        best = Math.max(best, sum);
    }
    return best;
}

int[] nums = {2, 1, 5, 1, 3, 2};
System.out.println(maxSumBrute(nums, 3) + " " + maxSum(nums, 3));
9 9

Ответ тот же, но за один проход: O(n) времени и O(1) памяти. Окно фиксированного размера подходит, когда длина отрезка задана в условии: «k подряд», «подстрока длины m», «анаграмма строки p».

Окно переменной длины

Чаще длина неизвестна, и её-то и надо найти. Например: дан массив положительных чисел, найди длину самого короткого подотрезка с суммой не меньше 7. Здесь окно дышит: правая граница расширяет его, пока условие не выполнено, а левая сжимает, пока выполняется.

static int minSubArrayLen(int target, int[] nums) {
    int best = Integer.MAX_VALUE, sum = 0, l = 0;
    for (int r = 0; r < nums.length; r++) {
        sum += nums[r];                              // расширяем вправо
        while (sum >= target) {                      // условие выполнено — сжимаем слева
            best = Math.min(best, r - l + 1);
            sum -= nums[l++];
        }
    }
    return best == Integer.MAX_VALUE ? 0 : best;
}

System.out.println(minSubArrayLen(7, new int[]{2, 3, 1, 2, 4, 3}));
System.out.println(minSubArrayLen(100, new int[]{2, 3, 1}));
2
0

Почему это O(n), хотя внутри while

Вложенный цикл пугает, но посчитай, сколько раз двигается каждая граница. r проходит массив один раз. l тоже только растёт и никогда не обгоняет r, поэтому за всё время сделает не больше n шагов. Каждый элемент один раз входит в окно и не больше одного раза выходит: 2n операций, то есть O(n). Это главный аргумент, который нужно произнести на собесе.

Два вложенных цикла — всегда O(n²).

Важно, сколько раз суммарно выполняется тело внутреннего цикла. Здесь l не сбрасывается в начало на каждой итерации внешнего цикла, а только растёт, поэтому суммарно он делает не больше n шагов.

Как узнать задачу на окно

Признаки в условии:

  • Речь про непрерывный кусок: подмассив, подстрока, «подряд идущие».
  • Нужно найти самый длинный, самый короткий или посчитать количество таких кусков.
  • Условие монотонно: если окно подходит, то подходит и окно побольше (или наоборот, поменьше). Благодаря этому сжимать можно, не боясь пропустить ответ.

Меняется только то, что хранится про окно и когда оно считается «хорошим»:

Что держим про окноОкно хорошее, когдаПример задачи
Суммусумма ≥ targetСамый короткий отрезок с суммой ≥ target
Множество или последний индекс символав окне нет повторовСамая длинная подстрока без повторов
Счётчик «плохих» элементовплохих не больше kСамая длинная серия единиц, если можно перевернуть k нулей
Частоты символов, int[26]частоты совпадают с образцомВсе анаграммы строки в тексте

Когда окно не работает

Если в массиве есть отрицательные числа, монотонность ломается: добавление элемента может уменьшить сумму, и сжатие слева может пропустить ответ. Задача «сколько подотрезков с суммой ровно k» при отрицательных числах решается префиксными суммами и HashMap, а не окном. Если элементы не обязаны идти подряд, это вообще другая задача: сортировка, два указателя или динамика.

Любую задачу про подмассив с суммой можно решить окном.

Только если числа неотрицательные. Для [84, -37, 32, 40, 95] и суммы ≥ 167 код выше вернёт 5, а верный ответ 3 — [32, 40, 95]. Убрав 84, окно получило сумму 130 и остановилось, хотя следующее сжатие убрало бы −37 и сумму увеличило. Тут нужны префиксные суммы.

Как решать это на собесе

Интервьюер оценивает не только код, но и то, как ты к нему пришёл. Порядок, который хорошо работает:

  1. Уточни условие. Только положительные числа? Может ли массив быть пустым? Что вернуть, если ответа нет? Для строк: какой алфавит?
  2. Назови перебор и его сложность. «Могу перебрать все отрезки за O(n²), но соседние отрезки почти совпадают».
  3. Скажи идею. «Держу окно, расширяю правую границу, а пока условие выполнено — сжимаю левую».
  4. Назови инвариант. Что верно про окно в каждый момент: «в окне нет повторов», «в окне не больше k нулей».
  5. Напиши код и прогони пример руками. Лучше всего короткий пример, где сжатие срабатывает хотя бы раз.
  6. Оцени сложность. O(n): каждый элемент входит и выходит не больше одного раза. Память — O(1) или O(размер алфавита).
  7. Проверь крайние случаи. Пустой вход, k больше длины массива, все элементы одинаковые, ответа нет.
  • Окно — это отрезок [l..r], который двигается вправо и обновляет ответ за O(1) на шаг вместо пересчёта с нуля.
  • Фиксированная длина: элемент входит справа и выходит слева на каждом шаге.
  • Переменная длина: расширяй правую границу, а пока условие выполнено — сжимай левую.
  • O(n), потому что каждая граница только растёт: элемент входит и выходит один раз.
  • Признаки: непрерывный кусок, «самый длинный или короткий», монотонное условие. Отрицательные числа в сумме — повод взять префиксные суммы.

Подсказка 1

Подстрока — непрерывный кусок, ищем самый длинный: это окно переменной длины. Инвариант окна — «все символы в нём разные».

Подсказка 2

Храни для каждого символа индекс, где он встречался последний раз. Пришёл символ, который уже есть в окне, — перенеси левую границу сразу за его прошлую позицию.

Подсказка 3

Левая граница никогда не двигается назад. Проверь решение на "abba": когда придёт вторая a, её прошлая позиция уже левее окна.

Решение

Окно [l..r] без повторов. Для каждого символа помним последний индекс. Если символ уже встречался внутри окна, то есть его индекс ≥ l, сдвигаем l за него. Проверка prev >= l нужна для случая "abba": без неё вторая a вернула бы l назад, и ответ получился бы 3.

static int lengthOfLongestSubstring(String s) {
    Map<Character, Integer> last = new HashMap<>();   // символ → где видели последний раз
    int best = 0, l = 0;
    for (int r = 0; r < s.length(); r++) {
        char c = s.charAt(r);
        Integer prev = last.get(c);
        if (prev != null && prev >= l) l = prev + 1;  // повтор внутри окна — левую границу за него
        last.put(c, r);
        best = Math.max(best, r - l + 1);
    }
    return best;
}

Время O(n): каждый символ обрабатывается один раз, а l прыгает только вперёд. Память O(min(n, размер алфавита)).

Что изменится, если известно, что в строке только ASCII-символы?

HashMap можно заменить массивом int[128] с последними индексами: без упаковки Character и без хеширования, это заметно быстрее. Массив заполняют -1, чтобы отличать «не встречался» от индекса 0.

А если нужно вернуть саму подстроку, а не длину?

Вместе с best запоминай, где начиналось лучшее окно: при обновлении максимума сохрани bestL = l. В конце верни s.substring(bestL, bestL + best). Сложность не меняется.

Считай нули в окне. Пока их больше k, сдвигай левую границу и уменьшай счётчик, когда уходит ноль.

Решение

Окно хорошее, пока в нём не больше k нулей: их все можно перевернуть. Храним только счётчик нулей.

static int longestOnes(int[] nums, int k) {
    int best = 0, zeros = 0, l = 0;
    for (int r = 0; r < nums.length; r++) {
        if (nums[r] == 0) zeros++;
        while (zeros > k) {                   // нулей больше, чем можно перевернуть
            if (nums[l] == 0) zeros--;
            l++;
        }
        best = Math.max(best, r - l + 1);
    }
    return best;
}

Время O(n), память O(1).

Подсказка 2

Две строки — анаграммы, если у них одинаковые частоты букв. Держи int[26] для p и для окна; при сдвиге одна буква входит, одна выходит.

Решение 
static List<Integer> findAnagrams(String s, String p) {
    List<Integer> res = new ArrayList<>();
    int k = p.length();
    if (k > s.length()) return res;
    int[] need = new int[26], window = new int[26];
    for (int i = 0; i < k; i++) {
        need[p.charAt(i) - 'a']++;
        window[s.charAt(i) - 'a']++;
    }
    if (Arrays.equals(need, window)) res.add(0);
    for (int r = k; r < s.length(); r++) {
        window[s.charAt(r) - 'a']++;          // вошёл справа
        window[s.charAt(r - k) - 'a']--;      // вышел слева
        if (Arrays.equals(need, window)) res.add(r - k + 1);
    }
    return res;
}

Время O(26·n) = O(n): сравнение двух массивов по 26 элементов — константа. Память O(1).

Как проверять совпадение за O(1) на сдвиг, без сравнения массивов?

Держи счётчик букв, у которых частота в окне совпадает с частотой в p. При входе и выходе буквы пересчитывай его только для этой буквы: до изменения частота совпадала — счётчик уменьшить, после изменения совпала — увеличить. Анаграмма найдена, когда счётчик равен 26.

Та же схема, что у самого короткого отрезка с суммой ≥ target: расширяй, пока окно не покроет все символы t, потом сжимай, пока покрытие сохраняется.

Подсказка 2

Храни need[c] — сколько символа c ещё не хватает — и общий счётчик missing. Окно покрывает t, когда missing == 0. Значения need могут уходить в минус: это лишние копии символа в окне.

Решение 
static String minWindow(String s, String t) {
    if (t.isEmpty() || t.length() > s.length()) return "";
    int[] need = new int[128];
    for (char c : t.toCharArray()) need[c]++;
    int missing = t.length();                 // сколько символов t ещё не покрыто окном
    int bestL = 0, bestLen = Integer.MAX_VALUE, l = 0;
    for (int r = 0; r < s.length(); r++) {
        if (need[s.charAt(r)]-- > 0) missing--;
        while (missing == 0) {                // окно покрывает t — пробуем сжать
            if (r - l + 1 < bestLen) { bestL = l; bestLen = r - l + 1; }
            if (++need[s.charAt(l++)] > 0) missing++;
        }
    }
    return bestLen == Integer.MAX_VALUE ? "" : s.substring(bestL, bestL + bestLen);
}

Когда символ входит в окно, need уменьшается. Если до этого он был положительным, символ закрыл реальную потребность, и missing уменьшается. При выходе наоборот: если need стал положительным, окно потеряло нужный символ. Время O(|s| + |t|), память O(1) — массив на 128 символов.

Почему нельзя просто проверять покрытие, сравнивая два массива частот?

Можно, и это тоже O(n) при фиксированном алфавите. Но сравнение на каждом шаге стоит 128 операций, а счётчик missing даёт ответ за O(1). На собесе обычно ждут именно счётчик: он показывает, что ты понимаешь, какое событие делает окно хорошим или плохим.
