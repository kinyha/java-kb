Stack

Стек хранит работу, которая ещё не завершена. Вложенное условие должно закрыться раньше внешнего, ожидающий индекс — получить ответ при подходящем значении, два результата подвыражений — объединиться оператором. Следующий шаг всегда начинается с вершины, потому что именно последнее незавершённое действие сейчас ближе всего к завершению. Перед выбором стека объясни, что означает один его элемент и в какой момент этот элемент можно окончательно снять.

Количество открытий не сохраняет порядок вложенности

Платёжный сервис принимает условие комиссии с несколькими вложенными группами. Перед разбором выражения нужно проверить скобки. В строках ([]) и ([)] есть по одной круглой и квадратной паре. Первая корректна, во второй круглая скобка закрывается, пока квадратная ещё открыта. Счётчик каждого вида скобок потерял именно порядок.

Для каждого закрытия важно последнее ещё незавершённое открытие. Когда встречается (, сохраняем ожидание ). Если внутри открылось [, новое ожидание ] должно завершиться раньше прежнего ). Нужна структура с правилом последним вошёл — первым вышел, LIFO. У стека доступны вершина, добавление на вершину и снятие вершины.

Фрагменты BracketDemo.java, JDK 21. Функция countsMatch специально проверяет только итоговые количества. balanced сохраняет порядок; её код ниже:

static boolean countsMatch(String input) {
    int round = 0, square = 0, curly = 0;
    for (char c : input.toCharArray()) {
        switch (c) {
            case '(' -> round++;
            case ')' -> round--;
            case '[' -> square++;
            case ']' -> square--;
            case '{' -> curly++;
            case '}' -> curly--;
            default -> throw new IllegalArgumentException("not a bracket");
        }
    }
    return round == 0 && square == 0 && curly == 0; // Теряет порядок вложенности.
}

System.out.println("== equal counts, different nesting ==");
for (String s : new String[]{"([])", "([)]", ")(", "(("}) {
    System.out.println(s + " counts=" + countsMatch(s) + " stack=" + balanced(s, false));
}

([]) counts=true stack=true
([)] counts=true stack=false
)( counts=true stack=false
(( counts=false stack=false

Даже )( имеет равные количества, хотя первое закрытие не имеет пары слева. Сравнение количеств — O(n), но решает более слабую задачу. Если искать и вырезать внутренние пары из строки по кругу, длинная вложенность вроде (((…))) потребует повторных проходов и копий. Стек завершает внутренние пары по мере чтения, без перестройки входа.

В Java договорись об одном конце Deque

Для стека здесь используем ArrayDeque: push добавляет в начало, pop снимает из начала, peek смотрит туда же. Альтернатива — addLast/removeLast/peekLast на другом конце. Смешение push и addLast меняет порядок обработки. Итерирование и toString у ArrayDeque идут от начала, поэтому при push вывод начинается с вершины.

System.out.println("== one end for both operations ==");
var mixed = new ArrayDeque<Integer>();
mixed.push(10);
mixed.addLast(20); // Другой конец: эта пара операций уже не даёт LIFO.
System.out.println("mixed pop=" + mixed.pop());
var stack = new ArrayDeque<Integer>();
stack.push(10);
stack.push(20);
System.out.println("stack pop=" + stack.pop());
System.out.println("peek=" + stack.peek() + " size=" + stack.size());
stack.pop();
System.out.println("empty peek=" + stack.peek());
try { stack.pop(); }
catch (NoSuchElementException e) { System.out.println("empty pop=" + e.getClass().getSimpleName()); }

peek не снимает элемент. На пустом стеке он возвращает null, а pop выбрасывает NoSuchElementException. Перед снятием проверяем isEmpty или используем заранее доказанный размер. ArrayDeque не принимает null, поэтому null однозначно обозначает отсутствие элемента. Локальный стек конкретного запроса не требует общей синхронизации; сам ArrayDeque не рассчитан на одновременную работу разных потоков.

Добавление и снятие с концов стоят амортизированное O(1): иногда внутренний массив расширяется, но серия добавлений остаётся линейной. Размер стека определяет дополнительную память. В алгоритмической задаче это отдельный объект в heap; он не является стеком вызовов Java. Рекурсивный обход хранит ожидания в кадрах вызовов, а явный стек позволяет выбрать, какие сведения нужны, и контролировать его размер.

Каждое закрытие должно совпасть с последним ожиданием

Перед очередным символом стек содержит ожидаемые закрытия всех открытых и ещё не закрытых групп. Сверху лежит ожидание для самой внутренней группы. Открытие добавляет новое ожидание. Закрытие обязано совпасть с вершиной; пустой стек или другой символ означает ошибку сразу.

Мы проверяем строку только из шести скобочных символов. Для реального выражения сначала нужны правила токенизации: скобка внутри строкового литерала не начинает группу. Этот метод не разбирает JSON, кавычки и экранирование:

static boolean balanced(String input, boolean trace) {
    var pending = new ArrayDeque<Character>();
    for (int i = 0; i < input.length(); i++) {
        char c = input.charAt(i);
        switch (c) {
            case '(' -> pending.push(')'); // Храним ожидаемый закрывающий символ.
            case '[' -> pending.push(']');
            case '{' -> pending.push('}');
            case ')', ']', '}' -> {
                if (pending.isEmpty() || pending.pop() != c) return false;
            }
            default -> throw new IllegalArgumentException("not a bracket");
        }
        if (trace) System.out.println("char=" + c + " expected(top first)=" + pending.stream().map(ch -> "'" + ch + "'").toList());
    }
    return pending.isEmpty(); // Оставшиеся ожидания означают незакрытые скобки.
}

System.out.println("balanced=" + balanced("{[()]}", true));
System.out.println("empty=" + balanced("", false));

Для ([)] на вершине находится ], а пришло ). Совпадения нет, последующие символы уже не могут исправить это нарушение. Для (( локальных ошибок закрытия вообще не было, но ожидания остались. Поэтому проверка пустоты в конце обязательна. Пустая строка не содержит незавершённых групп и корректна в этой задаче.

Каждый символ читается один раз, каждое ожидание добавляется и снимается не более одного раза: O(n) времени. Дополнительная память O(d), где d — максимальная глубина вложенности; в худшем случае d = n. Если требуется назвать место ошибки, вместо одного символа храни пару «ожидаемое закрытие, индекс открытия». Тогда вершина объяснит, какое открытие не завершилось.

Для единственного вида скобок (()()) достаточно одного счётчика глубины: при закрытии он не должен уходить ниже нуля, а в конце должен стать нулём. Для разных типов одинаковая глубина уже не определяет, какую скобку закрывать. Возвращаемся к стеку, потому что нужен порядок типов.

Новое большее значение завершает старые ожидания

В мониторинге шлюза есть задержки по последовательным запросам [70, 70, 65, 80]. Для каждой позиции нужно найти первый запрос справа с большей задержкой. Важен ближайший подходящий индекс, а не самое большое значение всего хвоста. Полный перебор для каждой позиции начинает поиск справа заново: O(n²) в худшем случае.

Можно прочитать массив один раз и сохранить индексы, которые ещё ждут большего значения. Перед обработкой i они идут в стеке по возрастанию индекса от дна к вершине. Их значения идут невозрастающе: последнее ожидание имеет самую маленькую или равную задержку. Так маленькие ожидания всегда доступны сверху.

Если текущее values[i] больше вершины, для неё найден ответ. Почему первый? Этот индекс всё ещё ждал, значит, ни один ранее прочитанный элемент справа его не завершил. Снимаем вершину и записываем i. То же текущее значение может завершить следующую вершину. Когда вершина достаточно велика или стек пуст, добавляем сам i: он тоже ждёт будущего большего значения.

Фрагменты MonotonicDemo.java. Сохраняем индексы, чтобы отличать равные задержки, записывать ответы по исходным позициям и при необходимости вычислять расстояние. Диагностическая печать стека в оценку времени не включена:

record Search(int[] next, int checks) {}

static Search brute(int[] values) {
    int[] next = new int[values.length];
    Arrays.fill(next, -1);
    int checks = 0;
    for (int i = 0; i < values.length; i++) {
        for (int j = i + 1; j < values.length; j++) {
            checks++;
            if (values[j] > values[i]) { next[i] = j; break; }
        }
    }
    return new Search(next, checks);
}

record Scan(int[] next, int pushes, int pops) {}

static Scan nextGreater(int[] values, boolean trace) {
    int[] next = new int[values.length];
    Arrays.fill(next, -1); // -1 обозначает отсутствие ИНДЕКСА, не значения.
    var pending = new ArrayDeque<Integer>();
    int pushes = 0, pops = 0;
    for (int i = 0; i < values.length; i++) {
        while (!pending.isEmpty() && values[pending.peek()] < values[i]) {
            int earlier = pending.pop(); // Текущее значение завершает ожидание earlier.
            next[earlier] = i;
            pops++;
            if (trace) System.out.println("pop=" + earlier + " next=" + i + " pending(top first)=" + pending);
        }
        pending.push(i); // Сам i ждёт будущего большего значения.
        pushes++;
        if (trace) System.out.println("push=" + i + " pending(top first)=" + pending);
    }
    return new Scan(next, pushes, pops);
}

System.out.println("brute=" + Arrays.toString(slow.next()) + " checks=" + slow.checks());
Scan scan = nextGreater(values, true);
System.out.println("next indices=" + Arrays.toString(scan.next()));
System.out.println("pushes=" + scan.pushes() + " pops=" + scan.pops());

Вложенный while расходует запас, а не начинает поиск заново

Каждый индекс добавляется один раз и снимается не более одного раза. На одну итерацию может прийтись много снятий, но на весь вход их не больше n. Плюс один последний неуспешный тест условия while на каждую итерацию: тоже O(n). Итог O(n) времени и O(n) памяти, включая стек ожиданий; массив ответа занимает ещё O(n).

System.out.println("== total work ==");
int[] descending = {4, 3, 2, 1};
Scan desc = nextGreater(descending, false);
System.out.println("descending checks=" + brute(descending).checks() + " pushes=" + desc.pushes() + " pops=" + desc.pops());
Scan asc = nextGreater(new int[]{1, 2, 3, 4}, false);
System.out.println("ascending pushes=" + asc.pushes() + " pops=" + asc.pops());

== total work ==
descending checks=6 pushes=4 pops=0
ascending pushes=4 pops=3

На убывающем входе ожидания накапливаются: стек имеет максимальный размер, снятий нет. На возрастающем почти каждое новое значение снимает прошлое: стек мал, снятий много. Оба входа остаются линейными. Поэтому обещание «каждый запрос обработается за O(1)» слишком сильное: одна новая точка может завершить весь накопленный стек, линейна именно общая работа.

Проход с другой стороны меняет смысл вершины и знак сравнения

При движении слева направо равная задержка не завершает ожидание, поэтому в while стоит <. Если заменить на ≤, в [70, 70] первое значение получит неправильный ответ 1. Для поиска «больше или равно» такое снятие, наоборот, соответствует условию.

При проходе справа налево стек хранит уже прочитанные возможные ответы. Для текущего значения выбрасываем меньшие и равные: они не годятся как строго большие. Кроме того, более близкое текущее значение заменяет эти дальние значения для всех будущих позиций слева. После удалений вершина содержит ближайший подходящий индекс:

static int[] nextGreaterFromRight(int[] values) {
    int[] next = new int[values.length];
    var candidates = new ArrayDeque<Integer>();
    for (int i = values.length - 1; i >= 0; i--) {
        while (!candidates.isEmpty() && values[candidates.peek()] <= values[i]) {
            candidates.pop(); // Равный или меньший справа не годится как строго больший.
        }
        next[i] = candidates.isEmpty() ? -1 : candidates.peek();
        candidates.push(i); // Более близкое значение заменяет слабых дальних.
    }
    return next;
}

System.out.println("backward equal=" + Arrays.toString(nextGreaterFromRight(equal)));
System.out.println("negative values=" + Arrays.toString(nextGreater(new int[]{-2, -1, -3}, false).next()));
System.out.println("backward same input=" + Arrays.toString(nextGreaterFromRight(values)));

Условия < при прямом проходе и ≤ при обратном дают один ответ, потому что стеки означают разное. Поэтому готовый шаблон «убирать всё меньше текущего» без определения содержимого стека опасен. Метка −1 в примере означает отсутствие индекса; реальное значение −1 в массиве остаётся обычными данными.

Оператор забирает два завершённых подвыражения

Правило комиссии (8 − 3) × 2 можно записать как 8 3 − 2 ×: оператор идёт после своих операндов. Это постфиксная, или обратная польская запись. Скобки уже не нужны: порядок действий закодирован положением операторов. Числа и промежуточные результаты лежат в стеке, пока не придёт оператор, который их объединит.

Перед очередным токеном стек содержит результаты завершённых подвыражений, которые ещё не объединены. Число добавляет один результат. Бинарный оператор снимает два последних результата и возвращает один. Последним добавлен правый операнд, поэтому сначала снимаем right, затем left. Вычисляем left op right.

Фрагменты ExpressionDemo.java. В этой версии операнды и результат каждой операции должны помещаться в int. Вычисление сначала идёт в long, затем проверяется диапазон:

static boolean operator(String token) {
    return token.equals("+") || token.equals("-") || token.equals("*") || token.equals("/");
}

static int apply(String op, int left, int right) {
    long result = switch (op) {
        case "+" -> (long) left + right;
        case "-" -> (long) left - right;
        case "*" -> (long) left * right;
        case "/" -> (long) left / right; // Деление к нулю; нулевой right даст ArithmeticException.
        default -> throw new IllegalArgumentException("unknown operator");
    };
    return Math.toIntExact(result); // Переполнение не превращается в другую сумму.
}

static int evaluate(String[] tokens, boolean trace) {
    var values = new ArrayDeque<Integer>();
    for (String token : tokens) {
        if (operator(token)) {
            if (values.size() < 2) throw new IllegalArgumentException("missing operand");
            int right = values.pop(); // Последним пришёл ПРАВЫЙ операнд.
            int left = values.pop();
            values.push(apply(token, left, right));
        } else values.push(Integer.parseInt(token)); // "-11" — число, "-" — оператор.
        if (trace) System.out.println("token=" + token + " values(top first)=" + values);
    }
    if (values.size() != 1) throw new IllegalArgumentException("not one result");
    return values.pop();
}

Проверяем форму выражения и арифметику отдельно

Перед бинарным оператором нужны минимум два значения. В конце должен остаться ровно один результат. Только проверка пустоты этого не обеспечивает: 8 3 оставляет два несвязанных числа. Числовой токен −11 отличается от оператора −; проверка оператора идёт по целому токену, а не по его первому символу.

static void showFailure(String[] tokens) {
    try { System.out.println(evaluate(tokens, false)); }
    catch (RuntimeException e) { System.out.println(Arrays.toString(tokens) + " -> " + e.getClass().getSimpleName()); }
}

Деление на ноль и выход результата из диапазона int считаем ошибкой арифметики. Даже MIN_VALUE / −1 требует проверки: математический результат равен 2147483648. Для денег в реальном правиле нужны отдельно заданные единицы, масштаб и округление; целочисленный учебный вычислитель не выбирает их за сервис.

Для k токенов стек выполняет O(k) добавлений и снятий, память O(k). Если токены ещё надо прочитать из строки, учитывай и число символов. Модели с BigInteger или BigDecimal сохраняют порядок обработки, но стоимость арифметики уже зависит от размера чисел.

Приоритет решает, какой ожидающий оператор выполнить раньше

Обычная запись 8 − 3 × 2 ставит оператор между операндами. Увидев минус, ещё нельзя вычислить 8 − 3: правый операнд должен сначала стать результатом умножения. Поэтому стек хранит ожидающие операторы, а числа сразу уходят в постфиксный результат.

Когда приходит новый оператор, все ожидающие операторы с большим приоритетом уже должны быть выданы. Для наших бинарных +, −, ×, / выдаём и равный приоритет: они выполняются слева направо. Иначе 8 − 3 − 2 превратится в 8 − (3 − 2). Открывающая скобка ставит границу; при закрытии выдаём операторы до неё и убираем саму скобку.

Это ядро алгоритма преобразования в постфиксную запись, известного как shunting-yard. Демо получает корректное выражение, уже разбитое на токены. Правила распознавания чисел, полная проверка грамматики и унарный минус как отдельная операция относятся к токенизации и разбору языка:

static int precedence(String op) {
    return op.equals("+") || op.equals("-") ? 1 : 2;
}

static String[] toPostfix(String[] tokens) {
    // Предусловие: корректное выражение, уже разбитое на числа, бинарные операторы и скобки.
    var output = new ArrayList<String>();
    var ops = new ArrayDeque<String>();
    for (String token : tokens) {
        if (token.equals("(")) ops.push(token);
        else if (token.equals(")")) {
            while (!ops.isEmpty() && !ops.peek().equals("(")) output.add(ops.pop());
            if (ops.isEmpty()) throw new IllegalArgumentException("unmatched close");
            ops.pop(); // Скобка задавала границу, в вычисляемую запись не попадает.
        } else if (operator(token)) {
            while (!ops.isEmpty() && !ops.peek().equals("(") && precedence(ops.peek()) >= precedence(token)) {
                output.add(ops.pop()); // Равный приоритет: эти бинарные операторы выполняются слева направо.
            }
            ops.push(token);
        } else {
            Integer.parseInt(token); // Проверяем формат числового токена.
            output.add(token);
        }
    }
    while (!ops.isEmpty()) {
        String op = ops.pop();
        if (op.equals("(")) throw new IllegalArgumentException("unmatched open");
        output.add(op);
    }
    return output.toArray(String[]::new);
}

System.out.println("== precedence and parentheses ==");
for (String text : new String[]{"8 - 3 * 2", "( 8 - 3 ) * 2", "8 - 3 - 2"}) {
    String[] postfix = toPostfix(text.split(" "));
    System.out.println(text + " -> " + Arrays.toString(postfix) + " -> " + evaluate(postfix, false));
}

( 8 - 3 ) * 2 -> [8, 3, -, 2, *] -> 10

В первом выражении умножение выдаётся перед минусом. Во втором закрытие скобки выдаёт минус ещё до появления умножения. В третьем очередной минус снимает прошлый из-за одинакового приоритета, поэтому получается (8 − 3) − 2 = 3.

Инвариант: уже выданная часть содержит числа и операции завершённых частей выражения, а стек хранит отложенные операторы текущих групп. При новом операторе с большим приоритетом он остаётся ждать; при меньшем заканчиваем более сильные операции на вершине. Операторы не должны проходить через ближайшую открывающую скобку. В конце оставшиеся операции выдаются в обратном порядке добавления.

У каждого токена оператора одно добавление и одно снятие, скобки тоже обрабатываются один раз: O(k) времени и O(k) памяти для результата и стека. Правоассоциативный оператор, например возведение в степень в некоторых языках, потребует другого условия для равного приоритета. Функции, разделители аргументов и унарные операции расширяют грамматику; их нельзя добавить одной заменой символа в этой функции.

Выбирай стек по правилу завершения, а не по названию задачи

На собеседовании сначала опиши медленный способ и повторную работу. Затем скажи, что именно не завершено: вложенная группа, индекс без ответа, подвыражение или оператор. Почему первым обрабатывается последний сохранённый элемент? Без ответа на этот вопрос стек пока просто дополнительный список.

В монотонных задачах уточни сторону поиска, строгость сравнения и вид ответа: индекс, расстояние, значение или ширина. Отдельно объясни равные элементы. Для прямоугольника под гистограммой меньшая высота завершает диапазон прежней; после снятия новая вершина задаёт левую границу. Пограничные столбцы не входят в ширину, поэтому появляется right − left − 1. Это разобрано в последней задаче.

Оценка O(n) следует из числа добавлений и снятий. Для очереди задач в сервисе, где нужен самый ранний запрос, LIFO даст другой порядок и может задерживать старую работу. Для произвольного максимума в диапазоне обычного стека недостаточно. Если старые элементы надо убирать и с начала, и с конца, потребуется другой инвариант, например монотонная очередь для максимума окна.

Вход из сети может иметь очень глубокую вложенность или длинную убывающую серию: стек тогда растёт до размера входа. В обработчике полезны явные пределы размера и глубины с понятной ошибкой. Перенос рекурсии в ArrayDeque освобождает стек вызовов, но не устраняет потребность хранить незавершённое состояние. Число элементов и размер одного состояния по-прежнему определяют память.

При проверке начни с пустого входа, одного элемента, равных значений, возрастающего и убывающего ряда. Для выражений добавь некоммутативную операцию, отрицательный результат, лишний операнд и недостаток операндов. Для скобок различай правильную вложенность, перекрещенные пары и незакрытый хвост. Эти случаи проверяют инвариант, а не только обычный пример.

  • Стек хранит незавершённое состояние; вершина должна быть следующим состоянием, которое можно завершить.
  • Для скобок нужны совпадение с вершиной и пустота в конце. Количества отдельных типов не сохраняют порядок.
  • Монотонный стек хранит индексы. Одно значение может снять много ожиданий, но каждый индекс снимается не более одного раза.
  • У строгого следующего большего < в прямом проходе и ≤ в обратном: меняется смысл содержимого стека.
  • В постфиксном вычислении сначала снимается правый операнд; приоритет и ассоциативность определяют порядок выдачи отложенных операторов.

static boolean solve(String input) {
    var pending = new ArrayDeque<Character>();
    for (int i = 0; i < input.length(); i++) {
        char c = input.charAt(i);
        switch (c) {
            case '(' -> pending.push(')');
            case '[' -> pending.push(']');
            case '{' -> pending.push('}');
            default -> {
                if (pending.isEmpty() || pending.pop() != c) return false;
            }
        }
    }
    return pending.isEmpty();
}

static int[] solve(int[] temperatures) {
    int[] days = new int[temperatures.length];
    var pending = new ArrayDeque<Integer>();
    for (int i = 0; i < temperatures.length; i++) {
        while (!pending.isEmpty() && temperatures[pending.peek()] < temperatures[i]) {
            int earlier = pending.pop();
            days[earlier] = i - earlier; // Храним расстояние до первого строго более тёплого дня.
        }
        pending.push(i);
    }
    return days; // Для оставшихся ожиданий нули уже записаны при создании массива.
}

На вершине лежат последние завершённые подвыражения. Бинарная операция сворачивает два результата в один. Проверка целого токена отличает отрицательное число от оператора, проверки размера отличают полноценное выражение от набора чисел.

static int solve(String[] tokens) {
    var values = new ArrayDeque<Integer>();
    for (String token : tokens) {
        if (token.equals("+") || token.equals("-") || token.equals("*") || token.equals("/")) {
            if (values.size() < 2) throw new IllegalArgumentException("missing operand");
            int right = values.pop(); // Порядок важен для минуса и деления.
            int left = values.pop();
            long result = switch (token) {
                case "+" -> (long) left + right;
                case "-" -> (long) left - right;
                case "*" -> (long) left * right;
                default -> (long) left / right;
            };
            values.push(Math.toIntExact(result));
        } else values.push(Integer.parseInt(token));
    }
    if (values.size() != 1) throw new IllegalArgumentException("not one result");
    return values.pop();
}

Подсказка 2

Храни индексы строго возрастающих высот. При высоте <= вершины снимай bar: right — текущий индекс, left — новая вершина или -1. Ширина right - left - 1. Виртуальный ноль в конце завершит остаток.

Решение

Перед чтением right в стеке лежат индексы со строго возрастающими высотами. Пока новый столбец не выше вершины, снимаем bar. Меньшая высота действительно закрывает диапазон справа; при равенстве передаём дальнейшее расширение новому столбцу той же высоты. После снятия новая вершина left имеет меньшую высоту, а все столбцы между left и right не ниже снятого. Уже доступная площадь высоты bar равна heights[bar] × (right − left − 1).

static long solve(int[] heights) {
    int[] pending = new int[heights.length];
    int size = 0;
    long best = 0;
    for (int right = 0; right <= heights.length; right++) {
        int current = right == heights.length ? 0 : heights[right]; // Виртуальный ноль завершает ожидания.
        while (size > 0 && heights[pending[size - 1]] >= current) {
            int bar = pending[--size];
            int left = size == 0 ? -1 : pending[size - 1];
            long area = (long) heights[bar] * (right - left - 1); // Границы не входят в прямоугольник.
            best = Math.max(best, area);
        }
        if (right < heights.length) pending[size++] = right; // Виртуальный индекс не попадает в стек.
    }
    return best;
}

O(n) времени и O(n) дополнительной памяти. Каждый индекс добавлен и снят один раз. Умножение выполняется в long до вычисления площади; физический виртуальный столбец не создаётся, индекс n в стек не кладётся.

Для [2, 2, 2] первый столбец снимется при следующем равном 2 и даст ширину 1. Новый индекс 1 затем уступит место индексу 2 и даст ширину 2. Виртуальный ноль снимет последний 2 с левой границей −1 и правой 3: ширина 3, площадь 6. Ни один равный столбец не исчезает из итогового диапазона.

При равной текущей высоте правую границу снимаем раньше реального уменьшения: старый равный столбец уже не нужен, новый позже охватит его диапазон. Так стек остаётся строго возрастающим. Использовать только > тоже возможно, но тогда равные высоты останутся в стеке, и смысл левой границы потребует отдельного объяснения.
