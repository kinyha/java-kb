Tree Traversal

Обход дерева хранит незавершённую работу: куда вернуться после ребёнка или какой узел обработать следующим. Рекурсия прячет её в стеке вызовов, итеративный DFS хранит явно, BFS ставит узлы в очередь. Порядок обработки определяет, можно ли уже использовать результат детей или гарантировать один уровень. Для проверки дерева и поиска общего предка к этому состоянию добавляются границы ключей или пути к корню.

Три момента обработки одного узла дают три порядка DFS

Платёжная группа 8 содержит группы 3 и 10; у 3 находятся операции 1 и 6. Нужно выдать все операции, вычислить итог по подгруппам или показать иерархию по уровням. Поиск одного ключа в BST мог пропустить целую ветку. Полный обход должен посетить каждый узел: его время O(n), потому что сами n результатов уже требуют обработки.

Здесь вход — конечное двоичное дерево. Каждый узел кроме корня имеет одного родителя, циклов и общих детей нет. Пустой ребёнок обозначается null. Значение и личность узла различаются: в произвольном дереве два объекта могут иметь одинаковые value. Структуру не меняем, поэтому один узел посещается по одному пути.

Модель и обвязка из examples/tree-traversal. Каждый файл запускается java ИмяDemo.java на JDK 21 без зависимостей. sample строит одно дерево, которое используется дальше:

static final class Node {
    final int value;
    Node left, right;
    Node(int value) { this.value = value; }
    public String toString() { return Integer.toString(value); } // Для трассы, не для сравнения личности.
}

static Node n(int value, Node left, Node right) {
    Node node = new Node(value); node.left = left; node.right = right; return node;
}

static Node sample() {
    return n(8, n(3, new Node(1), new Node(6)), new Node(10));
}

У одного рекурсивного вызова есть три момента для обработки node: до левого ребёнка, между детьми и после правого. Preorder выдаёт родителя до детей; inorder — после левого поддерева; postorder — после обоих. Ссылки и маршрут одинаковы, меняется только место result.add.

static void walk(Node node, String order, List<Integer> result) {
    if (node == null) return;
    if (order.equals("pre")) result.add(node.value); // Первый момент: до обоих детей.
    walk(node.left, order, result);
    if (order.equals("in")) result.add(node.value); // Второй момент: левая ветка уже обработана.
    walk(node.right, order, result);
    if (order.equals("post")) result.add(node.value); // Третий момент: результаты детей готовы.
}

Preorder подходит для действий, которым родитель нужен раньше потомков. Postorder собирает результат снизу вверх, когда оба ребёнка уже дали свои ответы. Inorder выдаёт ключи BST по возрастанию благодаря порядку всего левого и правого поддерева. У произвольного дерева результат [7,8,1] вполне корректен и не отсортирован.

Порядки и устройство BST уже показаны в Trees. Здесь важно восстановить незавершённый вызов, перенести его в явный стек и выбрать состояние для новых задач. Сам список значений одного обхода обычно не восстанавливает форму дерева: отсутствующие дети в нём не записаны.

Явный стек сохраняет место возврата после левого поддерева

В рекурсивном inorder родитель ждёт, пока закончится walk(left). В итеративном варианте эту ожидающую работу хранит stack. Сначала current движется влево, складывая узлы. Когда слева пусто, верхний узел готов к выдаче: его левая ветка уже завершена, сам он ещё не обработан.

После pop выдаём значение и ставим current в правого ребёнка. Затем снова спускаемся влево. Инвариант: stack хранит узлы, которые ждут выдачи после своих левых веток; current задаёт поддерево, в которое предстоит войти. Условие завершения требует пустоты обоих: current=null сам по себе означает только конец одного спуска.

Фрагменты OrderDemo.java. В строках stack=[1,3,8] первый элемент — верх:

static List<Integer> inorder(Node root, boolean trace) {
    List<Integer> result = new ArrayList<>();
    Deque<Node> stack = new ArrayDeque<>();
    Node current = root;
    while (current != null || !stack.isEmpty()) {
        while (current != null) {
            stack.push(current); // Запомнили возврат после левого поддерева.
            current = current.left;
            if (trace) System.out.println("push stack=" + stack + " current=" + current);
        }
        current = stack.pop();
        result.add(current.value); // Левая ветка завершена: теперь сам узел.
        current = current.right;
        if (trace) System.out.println("emit=" + result.getLast() + " stack=" + stack + " current=" + current);
    }
    return result;
}

record Action(Node node, boolean emit) {}
static List<Integer> postorder(Node root) {
    List<Integer> result = new ArrayList<>();
    Deque<Action> stack = new ArrayDeque<>();
    if (root != null) stack.push(new Action(root, false));
    while (!stack.isEmpty()) {
        Action action = stack.pop(); Node node = action.node();
        if (action.emit()) { result.add(node.value); continue; }
        stack.push(new Action(node, true)); // Обработка родителя останется под детьми.
        if (node.right != null) stack.push(new Action(node.right, false));
        if (node.left != null) stack.push(new Action(node.left, false)); // LIFO: левый ребёнок идёт последним в push.
    }
    return result;
}

Postorder требует ещё помнить момент возврата: Action(node,true) откладывает выдачу родителя под действиями детей. Стек LIFO, поэтому действия кладутся в обратном порядке исполнения: родитель, правый, левый. Первым снимается левый. Просто положить детей и сразу выдавать родителя означает preorder, а не postorder.

Каждый узел входит в stack и выходит один раз у inorder; у Action постоянное число действий на узел. Время O(n), рабочая память O(h), где h — высота в узлах. Отдельный список ответа O(n). Рекурсивный вариант тоже требует O(h), только в стеке JVM. Его допустимая глубина зависит от стека потока и кода; явный стек переносит эту память в heap.

static Node chain(int length, boolean left) {
    Node root = null;
    for (int i = length - 1; i >= 0; i--) root = left ? n(i, root, null) : n(i, null, root);
    return root;
}

Очередь хранит будущие узлы, а фиксированный размер отделяет уровни

Для интерфейса нужны группы одного уровня вместе: сначала 8, затем 3 и 10, затем 1 и 6. FIFO очередь делает это без сортировки. Берём узел из головы через removeFirst, его детей кладём в хвост через addLast. Дети окажутся после всех уже ожидающих узлов той же глубины.

Перед началом уровня фиксируем size=queue.size(). Извлекаем ровно size узлов, хотя очередь по ходу растёт от детей. Между извлечениями в ней смешаны остаток текущего уровня и начало следующего. Если каждый раз сравнивать i с новым queue.size(), граница поплывёт: часть следующего уровня попадёт в текущий либо нужный узел останется ждать.

Фрагменты BreadthDemo.java. result.size() в трассе — номер формируемого уровня, начиная с 0:

static List<List<Integer>> levels(Node root, boolean trace) {
    List<List<Integer>> result = new ArrayList<>();
    Deque<Node> queue = new ArrayDeque<>();
    if (root != null) queue.addLast(root);
    while (!queue.isEmpty()) {
        int size = queue.size(); // Фиксируем границу уровня до добавления детей.
        List<Integer> row = new ArrayList<>();
        if (trace) System.out.println("level=" + result.size() + " size=" + size + " queue=" + queue);
        for (int i = 0; i < size; i++) {
            Node node = queue.removeFirst(); row.add(node.value);
            if (node.left != null) queue.addLast(node.left);
            if (node.right != null) queue.addLast(node.right);
            if (trace) System.out.println("take=" + node.value + " remaining=" + (size - i - 1) + " queue=" + queue);
        }
        result.add(row);
    }
    return result;
}

Пустые дети не ставятся в очередь: ArrayDeque запрещает null. Для пустого корня очередь вообще не создаёт работу, ответ пуст. Каждый реальный узел добавлен и извлечён один раз: O(n) времени. Память очереди O(w), где w — максимальная ширина уровня; при переходе она может содержать части двух уровней, их суммарная ширина всё равно O(w). Ответ O(n).

Глубина собирается после детей, а пустой ребёнок не является листом

Договоримся считать глубину в узлах: пустое дерево 0, одиночный корень 1. Максимальная глубина поддерева — 1+max(глубина слева, глубина справа). Нужны оба результата детей, поэтому это postorder, даже если метод ничего не печатает. Глубина в рёбрах для непустого дерева была бы на 1 меньше; эти соглашения нужно назвать до сравнения ответов.

BFS даёт тот же максимум как количество непустых уровней. Здесь используем уже готовый levels для сравнения. Если нужен только ответ числом, сохранять списки уровней не требуется: оставь очередь, size и один счётчик глубины.

static int height(Node node) {
    if (node == null) return 0; // Считаем узлы: лист имеет глубину 1.
    int left = height(node.left), right = height(node.right);
    return 1 + Math.max(left, right); // Обработка после детей — postorder.
}

static int wrongMin(Node node) {
    if (node == null) return 0;
    return 1 + Math.min(wrongMin(node.left), wrongMin(node.right)); // Ошибка: пустая ссылка не лист.
}

static int minDepth(Node root) {
    if (root == null) return 0;
    Deque<Node> queue = new ArrayDeque<>(); queue.addLast(root);
    int depth = 0;
    while (!queue.isEmpty()) {
        int size = queue.size(); depth++;
        for (int i = 0; i < size; i++) {
            Node node = queue.removeFirst();
            if (node.left == null && node.right == null) return depth; // Первый настоящий лист.
            if (node.left != null) queue.addLast(node.left);
            if (node.right != null) queue.addLast(node.right);
        }
    }
    throw new AssertionError("unreachable for a finite tree");
}

На цепочке из трёх узлов ошибочный min вернул 1: он выбрал пустого ребёнка корня как короткий путь. Но путь должен закончиться листом, у которого пусты обе ссылки. В BFS первый найденный настоящий лист даёт минимальную глубину: более короткие пути уже обработаны на предыдущих уровнях. Рекурсивный min должен отдельно учитывать отсутствие одного ребёнка и брать непустую ветку.

Высота h и ширина w выбирают цену рабочего состояния. Цепочка имеет h=n и w=1: рекурсивный путь длинный, очередь мала. Полное двоичное дерево имеет h=O(log n), но последний уровень может занимать O(n). Привычное «у обхода память O(log n)» верно для DFS только при ограниченной высоте, а не для любого дерева или BFS.

В коде levels хранит сам ответ, поэтому его память на цепочке 10000 всё равно O(n), несмотря на очередь ширины 1. Отделяй память для незавершённой работы от того, что задача требует вернуть. Если нужны итоги по поддеревьям, размер карты результатов тоже может оказаться O(n) поверх стека O(h).

Проверка BST передаёт ограничения всех предков, а не только родителя

У строгого BST все ключи левого поддерева меньше ключа узла, все правого больше. Это условие на всех потомков. В дереве 8 с правым 10 и левым ребёнком 7 у 10 непосредственные сравнения верны:3<8, 10>8, 7<10. Но 7 лежит справа от 8 и нарушает нижнюю границу 8.

Каждое отложенное поддерево получает открытый интервал (low,high). При переходе влево high становится ключом родителя, low сохраняется. При переходе вправо low становится ключом родителя, high сохраняется. Так ограничения дальних предков продолжают действовать при следующем спуске.

Фрагменты QueriesDemo.java. Ключи int, границы long позволяют принять Integer.MIN_VALUE и Integer.MAX_VALUE без исключений и вычислений key±1:

record Bound(Node node, long low, long high) {}
static boolean valid(Node root, boolean trace) {
    Deque<Bound> stack = new ArrayDeque<>();
    if (root != null) stack.push(new Bound(root, Long.MIN_VALUE, Long.MAX_VALUE));
    while (!stack.isEmpty()) {
        Bound bound = stack.pop(); Node node = bound.node();
        boolean ok = bound.low() < node.value && node.value < bound.high();
        if (trace) System.out.println("value=" + node.value + " bounds=(" + bound.low() + "," + bound.high() + ") ok=" + ok);
        if (!ok) return false; // Граница сохраняет ограничения всех предков.
        if (node.right != null) stack.push(new Bound(node.right, node.value, bound.high()));
        if (node.left != null) stack.push(new Bound(node.left, bound.low(), node.value));
    }
    return true;
}

static boolean local(Node node) {
    if (node == null) return true;
    return (node.left == null || node.left.value < node.value)
        && (node.right == null || node.right.value > node.value)
        && local(node.left) && local(node.right); // Ошибка: ограничения предков потерялись.
}

Глобальная проверка отвергла 7 по интервалу (8,10), хотя локальная вернула true. Крайние int прошли, повтор 8 справа не прошёл: границы строгие. Время O(n) в худшем случае, стек O(h); ранний отказ сокращает фактический проход. Пустой корень считается корректным BST.

Альтернатива — inorder со сравнением каждого ключа с предыдущим: последовательность строгого BST должна строго возрастать. Предыдущий ключ хранится вместе с флагом наличия либо в более широком типе; стартовый sentinel int может совпасть с действительным минимальным ключом. Проверка «не убывает» разрешит дубли и изменит правило дерева.

Если структура специально разрешает дубли только справа или хранит счётчик дублей в одном узле, правило границ меняется вместе с моделью. Просто ослабить любое сравнение до ≤ недостаточно, чтобы проверить размещение дублей в нужной ветке. Здесь задача сохраняет строгое правило, поиск и балансировка отданы соседней теме Trees.

Общий предок определяется путями объектов и наличием обеих целей

LCA — самый глубокий узел, который является предком обеих целей. Узел считается предком самого себя: LCA(3,6)=3 и LCA(6,6)=6. В произвольном двоичном дереве идти по сравнению значений нельзя: у поддеревьев нет обещанного порядка BST, а одинаковые значения могут принадлежать разным объектам.

Короткое рекурсивное решение получает ответы детей после их обхода. Если слева и справа пришли непустые результаты, текущий узел разделяет пути целей. Если пришёл один, он передаётся выше. Встреченную цель возвращаем сразу: когда она сама предок второй, ответ уже она. Этот вариант предполагает, что обе цели присутствуют:

static Node lcaAssumingPresent(Node root, Node p, Node q) {
    if (root == null || root == p || root == q) return root;
    Node left = lcaAssumingPresent(root.left, p, q);
    Node right = lcaAssumingPresent(root.right, p, q);
    if (left != null && right != null) return root; // Цели пришли из разных веток.
    return left != null ? left : right;
}

В API такого обещания может не быть. Тогда явно докажем наличие целей: обходим дерево, записываем parent для каждого найденного объекта в IdentityHashMap. Корень тоже присутствует в карте, но его parent=null. containsKey отличает «корень с пустым родителем» от «узел не найден».

static Node lcaChecked(Node root, Node p, Node q) {
    if (root == null) return null;
    Map<Node, Node> parent = new IdentityHashMap<>();
    Deque<Node> stack = new ArrayDeque<>();
    parent.put(root, null); stack.push(root);
    while (!stack.isEmpty() && (!parent.containsKey(p) || !parent.containsKey(q))) {
        Node node = stack.pop();
        if (node.right != null) { parent.put(node.right, node); stack.push(node.right); }
        if (node.left != null) { parent.put(node.left, node); stack.push(node.left); }
    }
    if (!parent.containsKey(p) || !parent.containsKey(q)) return null; // Наличие обеих целей доказано.
    Set<Node> ancestors = Collections.newSetFromMap(new IdentityHashMap<>());
    for (Node node = p; node != null; node = parent.get(node)) ancestors.add(node);
    for (Node node = q; node != null; node = parent.get(node))
        if (ancestors.contains(node)) return node; // Первый общий по пути вверх из q — самый глубокий.
    throw new AssertionError("both nodes have the same root");
}

Карта родителей и набор предков требуют O(n) памяти в худшем случае, время O(n). Короткий рекурсивный вариант при обещании наличия обеих целей использует O(h) стека и O(n) времени. Проверку наличия можно встроить в рекурсивный postorder через результат с флагами найденных целей, но для цепочки снова остаётся глубина стека JVM. В задачах ниже используется итеративный вариант с явной проверкой.

Для BST с известным присутствием ключей LCA можно искать по разделению значений за O(h): пока оба меньше, идти влево; оба больше — вправо; иначе текущий узел разделяет пути. При множестве запросов на неизменном дереве имеет смысл предварительно подготовить глубины и переходы к предкам, например binary lifting. Это другой компромисс времени и памяти, за пределами одного обхода.

Обходы здесь опираются на стабильное дерево. Общий ребёнок превращает структуру в граф с несколькими путями, цикл разрушает завершение. Тогда нужен учёт посещённых объектов и условия отдельной задачи; это продолжает Graph Search. Подмена узлов значениями или изменение связей во время обхода может нарушить доказательство, даже когда обычный пример ещё печатается правильно.

  • Preorder, inorder и postorder отличаются моментом обработки узла относительно детей.
  • Явный stack хранит возвраты; current=null не завершает обход, пока возвраты остаются.
  • BFS фиксирует size на начало уровня. Очередь между извлечениями может смешивать два уровня.
  • DFS хранит O(h), BFS O(w) рабочей памяти. Возвращаемый результат оценивается отдельно.
  • BST проверяет ограничения всех предков. LCA сравнивает личности целей и требует обещания или проверки их наличия.

Подсказка 2

Сначала спускайся влево, складывая current. Затем pop, выдай значение и двигай current вправо. Повторяй, пока current не пуст или stack не пуст.

Решение

Стек содержит незавершённые возвраты. Узел снимается и выдаётся только после левого поддерева; правое становится новым current.

static List<Integer> solve(Node root) {
    List<Integer> result = new ArrayList<>();
    Deque<Node> stack = new ArrayDeque<>();
    Node current = root;
    while (current != null || !stack.isEmpty()) {
        while (current != null) {
            stack.push(current); // Запомнили возврат после левого поддерева.
            current = current.left;
        }
        current = stack.pop();
        result.add(current.value); // Левая ветка завершена: теперь сам узел.
        current = current.right;
    }
    return result;
}

static List<List<Integer>> solve(Node root) {
    List<List<Integer>> result = new ArrayList<>();
    Deque<Node> queue = new ArrayDeque<>();
    if (root != null) queue.addLast(root);
    while (!queue.isEmpty()) {
        int size = queue.size(); // Фиксируем границу уровня до добавления детей.
        List<Integer> row = new ArrayList<>();
        for (int i = 0; i < size; i++) {
            Node node = queue.removeFirst(); row.add(node.value);
            if (node.left != null) queue.addLast(node.left);
            if (node.right != null) queue.addLast(node.right);
        }
        result.add(row);
    }
    return result;
}

Подсказка 2

Сохраняй node вместе с открытыми low/high. Для left уменьши high до node.value, для right подними low. Границы long охватывают любой ключ int без key±1.

Решение

Вместе с поддеревом хранится допустимый интервал ключей. Каждая проверка либо принимает узел и сужает интервалы детей, либо сразу отвергает дерево.

static boolean solve(Node root) {
    Deque<Bound> stack = new ArrayDeque<>();
    if (root != null) stack.push(new Bound(root, Long.MIN_VALUE, Long.MAX_VALUE));
    while (!stack.isEmpty()) {
        Bound bound = stack.pop(); Node node = bound.node();
        boolean ok = bound.low() < node.value && node.value < bound.high();
        if (!ok) return false; // Граница сохраняет ограничения всех предков.
        if (node.right != null) stack.push(new Bound(node.right, node.value, bound.high()));
        if (node.left != null) stack.push(new Bound(node.left, bound.low(), node.value));
    }
    return true;
}

        check(root, one, new Node(6), null);
        check(root, new Node(1), new Node(6), null);
        check(null, one, six, null);
        Node left = new Node(7), right = new Node(7), repeated = n(9, left, right);
        check(repeated, left, right, repeated);
        Node deep = chain(10000, false), a = deep.right, b = a;
        while (b.right != null) b = b.right;
        check(deep, a, b, a);
    }
    record Links(Node left, Node right) {}
    static Map<Node, Links> snapshot(Node root) {
        Map<Node, Links> saved = new IdentityHashMap<>();
        Deque<Node> queue = new ArrayDeque<>(); if (root != null) queue.add(root);
        while (!queue.isEmpty()) {
            Node node = queue.removeFirst();
            if (saved.put(node, new Links(node.left, node.right)) != null) throw new AssertionError("not a tree");
            if (node.left != null) queue.addLast(node.left);
            if (node.right != null) queue.addLast(node.right);
        }
        return saved;
    }
    static void unchanged(Map<Node, Links> saved) {
        saved.forEach((node, links) -> {
            if (node.left != links.left() || node.right != links.right()) throw new AssertionError("links changed");
        });
    }
    static void check(Node root, Node p, Node q, Node want) {
        Map<Node, Links> saved = snapshot(root); Node got = solve(root, p, q);
        if (got != want) throw new AssertionError("wrong ancestor identity"); unchanged(saved);
        System.out.println("OK nodes=" + saved.size() + " p=" + p + " q=" + q + " lca=" + got);
    }
}
Подсказка 1

Сначала докажи наличие обеих целей. При обходе записывай каждого найденного объекта вместе с родителем. Корень тоже должен считаться найденным.

Подсказка 2

Собери множество объектов на пути от p к корню. Поднимай q через ту же карту: первый совпавший объект — LCA. IdentityHashMap сохраняет сравнение ссылок.

Решение

Обход строит пути через parent и проверяет, что обе цели найдены. Набор предков p позволяет вернуть первое совпадение при подъёме от q, включая сами цели.

static Node solve(Node root, Node p, Node q) {
    if (root == null) return null;
    Map<Node, Node> parent = new IdentityHashMap<>();
    Deque<Node> stack = new ArrayDeque<>();
    parent.put(root, null); stack.push(root);
    while (!stack.isEmpty() && (!parent.containsKey(p) || !parent.containsKey(q))) {
        Node node = stack.pop();
        if (node.right != null) { parent.put(node.right, node); stack.push(node.right); }
        if (node.left != null) { parent.put(node.left, node); stack.push(node.left); }
    }
    if (!parent.containsKey(p) || !parent.containsKey(q)) return null; // Наличие обеих целей доказано.
    Set<Node> ancestors = Collections.newSetFromMap(new IdentityHashMap<>());
    for (Node node = p; node != null; node = parent.get(node)) ancestors.add(node);
    for (Node node = q; node != null; node = parent.get(node))
        if (ancestors.contains(node)) return node; // Первый общий по пути вверх из q — самый глубокий.
    throw new AssertionError("both nodes have the same root");
}

O(n) времени и памяти в худшем случае. Проверки требуют ожидаемый исходный объект, а не совпавшее value; включают отсутствующую цель, p==q, одинаковые значения и цепочку 10000.

Рекурсивный возврат одного найденного узла корректен только при обещании наличия обеих целей. Для одного запроса карта родителей проста; для множества запросов на неизменном дереве выгоднее отдельная предварительная обработка. Изменения родительских связей требуют обновить или пересоздать такой индекс.
