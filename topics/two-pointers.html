Two Pointers

Выгрузку платежей можно обработать за один проход, если после каждого сравнения понятно, какую часть работы больше не нужно повторять. Два указателя отмечают эту границу: между ещё возможными парами, между готовым ответом и входом, между двумя источниками. Быстрым алгоритм делает причина движения. Она должна объяснять, почему отброшенные варианты уже не дадут ответ и почему запись сохраняет данные, которые ещё понадобятся.

Перебор пар повторяет работу, которую сортировка уже сделала

В сверке есть отсортированные суммы [10, 20, 30, 40, 70, 90]. Нужно найти две разные операции с общей суммой 60. Позиции важны: одна операция на 30 не заменяет две операции по 30. Суммы считаем целыми числами в минимальных денежных единицах, без округления.

Прямой перебор выбирает первое число, затем проверяет каждое следующее. Для n элементов всего n(n − 1)/2 пар. Когда пары нет, пройдём их все: O(n²) времени, O(1) дополнительной памяти. Перебор работает и для произвольного порядка, но на отсортированном входе он игнорирует полезное свойство данных.

Фрагменты PairDemo.java, JDK 21. Счётчик считает проверки суммы, индексы начинаются с нуля:

record Search(int[] pair, int comparisons) {}

static Search brute(int[] a, int target) {
    int checks = 0;
    for (int i = 0; i < a.length; i++) {
        for (int j = i + 1; j < a.length; j++) {
            checks++;
            if ((long) a[i] + a[j] == target) return new Search(new int[]{i, j}, checks);
        }
    }
    return new Search(new int[0], checks);
}

System.out.println("== sorted pair ==");
int[] a = {10, 20, 30, 40, 70, 90};
Search slow = brute(a, 60);
System.out.println("brute pair=" + Arrays.toString(slow.pair()) + " checks=" + slow.comparisons());

== sorted pair ==
brute pair=[1, 3] checks=7

В этом входе можно сравнить самое маленькое и самое большое оставшиеся числа. Их сумма сразу скажет, какой край больше не нужен. Если даже крайний партнёр не помогает, остальные партнёры тем более не помогут. Вместо одной неудачной пары исключим целую группу.

Одно сравнение исключает все пары с одним крайним элементом

Ставим left в начало, right в конец. Перед каждой итерацией все ещё возможные ответы находятся внутри [left, right]. За пределами этой области уже доказано, что подходящей пары нет. Это инвариант: утверждение, которое верно до и после каждого шага.

Если a[left] + a[right] меньше цели, для любого j ≤ right верно a[left] + a[j] ≤ a[left] + a[right]. Значит, left не образует ответ ни с одним оставшимся элементом. Двигаем left. Если сумма больше цели, для любого i ≥ left верно a[i] + a[right] ≥ a[left] + a[right]. Исключаем right. При равенстве ответ найден.

Функция предполагает отсортированный вход и возвращает любую найденную пару. Пустой массив означает отсутствие ответа. trace здесь нужен только для наблюдения:

static int[] pair(int[] a, int target, boolean trace) {
    int left = 0, right = a.length - 1;
    while (left < right) { // Одна позиция не может участвовать дважды.
        long sum = (long) a[left] + a[right]; // Расширяем тип ДО сложения.
        if (trace) System.out.printf("left=%d right=%d sum=%d%n", left, right, sum);
        if (sum == target) return new int[]{left, right};
        if (sum < target) left++; // Даже самый большой партнёр слишком мал.
        else right--; // Даже самый маленький партнёр слишком велик.
    }
    return new int[0];
}

System.out.println("input=" + Arrays.toString(a));

Разность right − left уменьшается на единицу после каждого неуспешного сравнения. Границы не возвращаются назад, поэтому проверок не больше n − 1: O(n) времени, O(1) дополнительной памяти. Сортировка в эту оценку не входит: мы получили уже отсортированный вход. Для произвольного порядка сортировка добавит время и изменит позиции.

Отрицательные суммы и дубли допустимы; произвольный порядок ломает доказательство

Неравенства опираются на порядок, а не на положительность чисел. Повторяющиеся суммы тоже подходят, если это разные позиции. Условие left < right сохраняет это различие даже в массиве из одного элемента. На произвольном порядке сравнение крайних значений ничего не говорит об остальных:

System.out.println("== sorting is a precondition ==");
int[] unsorted = {30, 20, 40};
System.out.println("unsorted brute=" + Arrays.toString(brute(unsorted, 60).pair()));
System.out.println("unsorted pointers=" + Arrays.toString(pair(unsorted, 60, false)));
System.out.println("single 30, target 60=" + Arrays.toString(pair(new int[]{30}, 60, false)));
System.out.println("two 30, target 60=" + Arrays.toString(pair(new int[]{30, 30}, 60, false)));
System.out.println("negative values=" + Arrays.toString(pair(new int[]{-30, -10, 20, 40}, 10, false)));

Для [30, 20, 40] сначала сравниваются 30 и 40. Алгоритм убирает 40, хотя именно оно нужно для пары 20 + 40. Далее 30 + 20 слишком мало, границы сходятся. Ошибка возникает из-за нарушенного предусловия, а не из-за выбора неудачного target.

Достаточно записать сумму в long: long sum = a[left] + a[right].

Правая часть сначала вычисляется как int и уже может переполниться. Расширь хотя бы один операнд до сложения: (long) a[left] + a[right].

System.out.println("== overflow ==");
int x = Integer.MAX_VALUE;
System.out.println("int sum=" + (x + x));
System.out.println("long sum=" + ((long) x + x));

Переполнение не только создаёт ложное равенство. Оно меняет знак суммы и заставляет двигать противоположный указатель. В проде это выглядело бы как пропущенная сверка крупных сумм. Для входных long тип long уже не обеспечивает безопасность суммы двух значений: нужен отдельный способ точного сравнения, например BigInteger.

Разворот закрепляет готовые края и сужает незавершённую середину

Суммы пришли от новых платежей к старым, а отчёт нужен в обратном порядке. Создавать второй массив необязательно. Позиция i должна оказаться на n − 1 − i. Обмениваем крайние элементы и переходим к следующей паре.

Перед очередным обменом слева от left и справа от right уже стоят элементы на окончательных позициях. Внутри ещё лежит незавершённая середина. Обмен завершает две позиции, затем обе границы сдвигаются. Когда left ≥ right, середина пуста или состоит из одного элемента, который и так на месте.

Фрагменты InPlaceDemo.java. Сохранённое значение нужно, чтобы первое присваивание не уничтожило второй участник обмена:

static void reverse(int[] a) {
    for (int left = 0, right = a.length - 1; left < right; left++, right--) {
        int saved = a[left]; // Второе присваивание иначе потеряло бы прежнее a[left].
        a[left] = a[right];
        a[right] = saved;
    }
}

System.out.println("== reverse ==");
int[] reverseInput = {10, 20, 30, 40, 50};
int[] alias = reverseInput;
reverse(reverseInput);
System.out.println("array=" + Arrays.toString(reverseInput));
System.out.println("alias=" + Arrays.toString(alias));
reverse(reverseInput);
System.out.println("twice=" + Arrays.toString(reverseInput));

Всего ⌊n/2⌋ обменов: O(n) времени и O(1) дополнительной памяти. alias видит тот же результат, потому что массив изменён на месте. Второй разворот возвращает исходную последовательность. Перед такой обработкой общего буфера сервис должен понимать, кто ещё читает его через другие ссылки.

Индексы должны обозначать нужную единицу данных. Для int[] это элемент. Для char[] это кодовая единица UTF-16: простой обмен может разорвать суррогатную пару. Даже разворот кодовых точек не всегда сохраняет составной пользовательский символ. Для текста сначала выбери единицу обработки; неизменяемому String понадобится новый результат. Единицы индексации описаны в документации String, JDK 21.

Проверка палиндрома использует те же края, но сравнивает вместо обмена. Если пары совпадают, область сужается; первое несовпадение даёт ответ false. Если условие требует игнорировать пробелы или регистр, правила нормализации должны быть сформулированы до движения указателей.

Удаление дублей собирает ответ в уже прочитанной части массива

Для сверки нужен список разных сумм, а выгрузка содержит [10, 10, 20, 20, 20, 30]. В отсортированном массиве все одинаковые значения стоят рядом. Поэтому хранить множество не требуется: новое значение достаточно сравнить с последним сохранённым.

read указывает на очередной входной элемент. write — на первое свободное место в ответе. Перед итерацией префикс [0, write) содержит разные значения из уже прочитанного входа, в исходном порядке. Новое значение либо пропускаем, либо записываем в a[write] и увеличиваем write.

Перед записью write ≤ read: сохранённых элементов не может быть больше, чем прочитанных. Поэтому запись затрагивает текущую или прошлую позицию и оставляет весь будущий вход целым. Здесь это условие важнее конкретного сравнения значений.

static int unique(int[] a, boolean trace) {
    int write = 0;
    for (int read = 0; read < a.length; read++) {
        if (write == 0 || a[read] != a[write - 1]) {
            a[write++] = a[read]; // Пишем в прочитанную часть: write <= read до записи.
            if (trace) System.out.println("keep read=" + read + " write=" + write + " prefix=" + Arrays.toString(Arrays.copyOf(a, write)));
        }
    }
    return write; // Меняется логическая длина. a.length остаётся прежней.
}

System.out.println("== compact ==");
int[] amounts = {10, 10, 20, 20, 20, 30};
int length = unique(amounts, true);
System.out.println("length=" + length + " physical=" + amounts.length);
System.out.println("array=" + Arrays.toString(amounts));
System.out.println("answer=" + Arrays.toString(Arrays.copyOf(amounts, length)));

Вернулась длина 3. Она означает, что ответ занимает индексы 0, 1, 2. Массив по-прежнему содержит шесть элементов; значения дальше префикса не определены условием задачи. Arrays.copyOf в выводе создаёт отдельный массив только для печати ответа. Сам алгоритм работает за O(n) времени и O(1) памяти.

Чтобы удалить дубль, надо сдвинуть весь хвост на одну позицию влево.

Повторные сдвиги дают O(n²). Указатель write позволяет каждому нужному элементу попасть на место за одну запись. Физически уменьшить Java-массив нельзя; если вызывающей стороне нужен массив точной длины, копирование добавит память.

Оставить до k копий: сравниваем с ответом на k позиций назад

Если разрешены две копии, сравнения с последним сохранённым уже недостаточно. Пока write < k, место точно есть. Далее значение можно сохранить, только если оно отличается от a[write − k]. Равенство означает, что последние k сохранённых элементов уже равны текущему: сортировка гарантирует, что между ними нет другого значения.

static int keepAtMost(int[] a, int limit) {
    if (limit < 0) throw new IllegalArgumentException("negative limit");
    if (limit == 0) return 0;
    int write = 0;
    for (int read = 0; read < a.length; read++) {
        if (write < limit || a[read] != a[write - limit]) {
            a[write++] = a[read]; // Сравниваем с уже собранным ответом, не с прошлым входом.
        }
    }
    return write;
}

System.out.println("== keep two copies ==");
int[] repeated = {10, 10, 10, 20, 20, 20, 30};
int kept = keepAtMost(repeated, 2);
System.out.println("length=" + kept);
System.out.println("answer=" + Arrays.toString(Arrays.copyOf(repeated, kept)));
System.out.println("limit zero=" + keepAtMost(new int[]{10, 10}, 0));

== keep two copies ==
length=5
answer=[10, 10, 20, 20, 30]

Сравнение ведётся с собранным ответом. Проверка a[read − k] игнорирует смещение после пропусков. В этом примере после трёх десяток первое 20 уже перенесено в a[2]. Для второго 20, read = 4, сравнение с a[read − 2] увидит это перенесённое 20 и ошибочно пропустит допустимую вторую копию. Правильная позиция — a[write − 2], в ней ещё 10.

При k = 0 ответ сразу пуст; отрицательный предел в этой функции считается ошибкой аргумента. Если порядок произвольный, приём удалит только соседние повторы: для [10, 20, 10] обе копии 10 сохранятся. Сортировка здесь нужна, чтобы последнее сохранённое значение представляло всю серию.

Та же граница read/write подходит для стабильной фильтрации: сохраняй только элементы, которые проходят предикат. Удаление всех нулей и удаление повторов отличаются решением «сохранить», а доказательство безопасной записи одинаковое. Если требуется перенести нули в конец, после уплотнения отдельно заполни хвост нулями.

Слияние читает два начала, а общий массив заполняет с конца

Есть две выгрузки платежей, каждая отсортирована по сумме. Нужна одна отсортированная последовательность. Самые маленькие непрочитанные значения находятся в начале каждого источника. Сравниваем их, переносим меньшее в результат и двигаем только указатель выбранного источника.

i и j обозначают непрочитанные начала, k — конец готового результата. Префикс результата отсортирован и содержит ровно уже взятые элементы обоих входов. Когда один источник исчерпан, оставшийся хвост другого уже отсортирован: его можно дописать. Все указатели растут, общее число переносов равно m + n.

Фрагменты MergeDemo.java. Метки A1…B2 позволяют увидеть порядок платежей с одинаковой суммой:

record Payment(int amount, String id) {}

static Payment[] merge(Payment[] a, Payment[] b) {
    Payment[] result = new Payment[a.length + b.length];
    int i = 0, j = 0, k = 0;
    while (i < a.length && j < b.length) {
        // При равенстве платёж из левой выгрузки идёт первым: слияние устойчиво.
        result[k++] = a[i].amount() <= b[j].amount() ? a[i++] : b[j++];
    }
    while (i < a.length) result[k++] = a[i++];
    while (j < b.length) result[k++] = b[j++];
    return result;
}

System.out.println("== forward, separate result ==");
Payment[] first = {new Payment(10, "A1"), new Payment(30, "A2"), new Payment(30, "A3")};
Payment[] second = {new Payment(20, "B1"), new Payment(30, "B2")};
System.out.println("ids=" + Arrays.toString(Arrays.stream(merge(first, second)).map(Payment::id).toArray()));

== forward, separate result ==
ids=[A1, B1, A2, A3, B2]

При равенстве выбрали левый источник. Поэтому A2 и A3 остаются перед B2, а порядок внутри каждой выгрузки сохраняется. Это устойчивое слияние относительно логической последовательности «сначала a, затем b». Оно не восстанавливает порядок реальных событий между выгрузками: для этого нужен ключ вроде (время, id). Время O(m + n), память O(m + n) для нового результата.

Свободные места уже есть в a: направление меняется

Теперь первые m элементов a содержат данные, а в конце выделены ещё n мест. Если писать минимальное значение в начало a, можно затереть непрочитанный элемент этого же источника. Решение симметрично: выбираем наибольшее из последних непрочитанных значений и заполняем свободный конец.

static void mergeInto(int[] a, int m, int[] b, int n, boolean trace) {
    // Первые m и n элементов отсортированы; a != b, a.length >= m + n.
    int i = m - 1, j = n - 1, k = m + n - 1;
    while (j >= 0) {
        if (i >= 0 && a[i] > b[j]) a[k--] = a[i--];
        else a[k--] = b[j--]; // При равенстве правый идёт в конец: левый останется раньше.
        if (trace) System.out.println("i=" + i + " j=" + j + " k=" + k + " array=" + Arrays.toString(a));
    }
    // Остаток a уже лежит на своих местах. Переписывать его не нужно.
}

System.out.println("== backward, same array ==");
int[] a = {10, 30, 50, 0, 0, 0};
int[] b = {20, 40, 60};
mergeInto(a, 3, b, 3, true);
System.out.println("b=" + Arrays.toString(b));
int[] withZero = {-3, 0, 4, 0, 0};
mergeInto(withZero, 3, new int[]{0, 2}, 2, false);
System.out.println("zero is data=" + Arrays.toString(withZero));

Перед каждой итерацией k = i + j + 1. Пока j ≥ 0, имеем k > i: запись идёт правее всех непрочитанных элементов a. Поэтому источники не портятся. С каждым переносом уменьшается k и один из i, j, равенство сохраняется. При j = −1 получается k = i: оставшийся префикс a уже стоит на своих местах. Если a закончился первым, переносим остаток b.

На каждом шаге сформированный справа суффикс отсортирован и содержит самые большие уже выбранные значения. При равенстве берём b: правый источник должен оказаться правее левого. Время O(m + n), дополнительная память O(1). В примере пять записей, потому что оставшееся 10 копировать не требуется.

Нули в свободных слотах — лишь начальное содержимое памяти. Число настоящих элементов задаётся m, а не поиском первого нуля: настоящая сумма тоже может быть равна нулю. Входы должны быть разными массивами; общий буфер источника и назначения требует отдельного доказательства сохранности, этот код его не обеспечивает.

unread a[i]=1
array=[1, 4, 6, 0, 0, 0]

После первой записи вперёд значение 2 исчезло, хотя i ещё равен 0. Выбрать следующий минимальный элемент уже нельзя: вместо него читается только что записанная 1. Если заранее скопировать исходный a, движение вперёд станет безопасным, но потребует дополнительной памяти.

Сначала докажи движение границы, затем обещай линейное время

На собеседовании начни с результата и предпосылок: что возвращаем, можно ли менять вход, отсортирован ли он, важны ли исходные индексы, допускаются ли дубли. Затем покажи медленный способ. Чтобы перейти к указателям, найди участок, который одно сравнение позволяет окончательно исключить или закрепить.

Расскажи инвариант перед итерацией и объясни каждое движение. Для суммы внутри границ ещё лежат все возможные пары. Для разворота края уже окончательные. Для уплотнения префикс готов, будущие значения целы. Для слияния готовый результат отсортирован, а выбранный источник отдаёт минимум или максимум. После этого покажи, почему цикл закончится.

УсловиеЧто дают указателиОценка
Отсортированный массив, одна пара с заданной суммойКрай исключает все пары с этим элементомO(n), O(1) памяти
Разворот массиваОбмен завершает две позицииO(n), O(1)
Сохранить подмножество элементов по порядкуread читает, write собирает префиксO(n), O(1), если решение «сохранить» стоит O(1)
Два отсортированных источникаКаждый перенос расходует элемент одного источникаO(m + n); память зависит от места назначения

Два индекса ещё не означают O(n). В доказательстве надо считать суммарное движение: каждая граница проходит вход один раз. Вложенный цикл тоже может быть линейным, если внутренний указатель продолжает прошлое движение. Если же для каждого нового первого индекса второй снова идёт с начала, получается O(n²).

Три суммы: внешний перебор остаётся, внутренний становится линейным

Для тройки фиксируем первый элемент отсортированного массива. Справа от него ищем пару двумя указателями с суммой −a[fixed]. Все позиции различны, потому что fixed < left < right. Один фиксированный элемент требует O(n), а таких элементов O(n), значит, весь поиск O(n²). В задаче ниже сразу считаем сумму трёх чисел в long, чтобы не переполнить отрицание Integer.MIN_VALUE.

Чтобы выдать уникальные тройки значений, одинаковые первые элементы пропускаем. После найденной тройки пропускаем одинаковые значения на обоих концах. Разные индексы с теми же значениями не образуют новый ответ. Если условие просит все комбинации индексов, это уже другой размер результата: для длинной серии равных чисел число пар или троек само по себе квадратично или кубично.

Для несортированного входа с важными исходными индексами пара часто удобнее через хеш-таблицу. Сортировка пары (значение, исходный индекс) тоже работает, но требует O(n log n) времени и хранения связи с исходной позицией. Нельзя отсортировать суммы, найти индексы в новом массиве и вернуть их как номера исходных операций.

Оценка предполагает дешёвый доступ по индексу. Повторный get(i) у связного списка сам проходит узлы, поэтому тот же текст цикла перестаёт быть линейным. Для потоков две границы с разных концов требуют буферизации; слияние двух уже отсортированных потоков, напротив, может читать их по одному элементу. В реальном сервисе отдельно учитывай цену чтения, сравнения и владение изменяемым буфером.

Смежные паттерны используют похожие переменные с другой причиной движения. Sliding Window поддерживает свойство целого непрерывного отрезка. Быстрый и медленный указатели при обходе списка используют разную скорость, а не исключение сумм. Merge Sort многократно сливает части массива. Для этих задач важны их собственные инварианты.

  • Для пары сортировка позволяет после одного сравнения исключить все пары с крайним элементом. Отрицательные числа и дубли этому не мешают.
  • Сумму int считай с расширением операнда до сложения; одинаковые значения всё равно требуют разных позиций.
  • При уплотнении ответ — префикс [0, write). Физический хвост остаётся; write ≤ read сохраняет будущие данные.
  • В новый массив сливай с начала, в свободный конец исходного — с конца. Направление следует из сохранности источника.
  • Время определяется общим числом движений, а память — местом результата, копированием и требованием сохранить исходные индексы.

Подсказка 1

Начни с самой маленькой и самой большой доступных сумм. Что можно окончательно отбросить, если их сумма меньше цели?

Подсказка 2

Пока left < right, сравнивай сумму с target. При недостатке двигай left, при избытке right. Расширь операнд до сложения.

Решение

Для слишком маленькой суммы все пары с left уже слишком малы. Для слишком большой все пары с right слишком велики. Область ещё возможных ответов сужается до совпадения или встречи границ.

static int[] solve(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left < right) {
        long sum = (long) nums[left] + nums[right];
        if (sum == target) return new int[]{left, right};
        if (sum < target) left++;
        else right--;
    }
    return new int[0];
}

        nums[right] = saved;
    }
}

В отсортированном входе одинаковые значения идут подряд. С чем сравнить очередное значение, если ответ уже собран в начале?

Подсказка 2

read всегда движется вперёд. Если ответ пуст или nums[read] отличается от nums[write - 1], запиши его в nums[write++] и продолжай.

Решение

write задаёт первое свободное место ответа. Сравниваем с последним сохранённым элементом и пропускаем остальные копии. Перед записью write ≤ read, поэтому будущие исходные значения сохраняются.

static int solve(int[] nums) {
    int write = 0;
    for (int read = 0; read < nums.length; read++) {
        if (write == 0 || nums[read] != nums[write - 1]) nums[write++] = nums[read];
    }
    return write;
}

Подсказка 1

В начале nums ещё лежат непрочитанные данные. С какой стороны уже есть свободное место для следующего элемента?

Подсказка 2

i = m - 1, j = n - 1, write = m + n - 1. Пока j ≥ 0, переноси большее из последних доступных значений. Если i < 0, бери только other.

Решение

Заполняем ответ наибольшими значениями справа налево. Пока второй источник не исчерпан, write > i, поэтому запись не трогает непрочитанный префикс nums. Остаток первого массива уже на месте.

static void solve(int[] nums, int m, int[] other, int n) {
    int i = m - 1, j = n - 1, write = m + n - 1;
    while (j >= 0) {
        if (i >= 0 && nums[i] > other[j]) nums[write--] = nums[i--];
        else nums[write--] = other[j--];
    }
}

    static void check(List<List<Integer>> got, List<List<Integer>> want) {

Подсказка 1

Отсортируй копию, зафиксируй первый элемент и ищи пару справа от него. Для одного fixed теперь нужен линейный проход.

Подсказка 2

Пропускай одинаковые fixed. После совпадения сохрани значения обоих концов и пропусти их повторы, иначе одна тройка появится несколько раз. Суммируй все три числа в long.

Решение

fixed оставляет задачу о паре на остатке. Сортировка задаёт порядок внутри тройки. Внешний цикл выдаёт первые значения по возрастанию, левый указатель — вторые по возрастанию, поэтому результат сразу лексикографически упорядочен. Пропуски одинаковых значений убирают повторные тройки без отдельного множества.

static List<List<Integer>> solve(int[] nums) {
    int[] a = nums.clone(); // Условие требует сохранить вход.
    Arrays.sort(a);
    var result = new ArrayList<List<Integer>>();
    for (int fixed = 0; fixed < a.length - 2; fixed++) {
        if (fixed > 0 && a[fixed] == a[fixed - 1]) continue; // Этот первый элемент уже разобран.
        if (a[fixed] > 0) break; // Дальше все три числа положительные.
        int left = fixed + 1, right = a.length - 1;
        while (left < right) {
            long sum = (long) a[fixed] + a[left] + a[right];
            if (sum < 0) left++;
            else if (sum > 0) right--;
            else {
                result.add(List.of(a[fixed], a[left], a[right]));
                int low = a[left], high = a[right];
                while (left < right && a[left] == low) left++; // Пропускаем уже выданные значения.
                while (left < right && a[right] == high) right--;
            }
        }
    }
    return result;
}

O(n²) времени для n ≥ 3, сортировка копии O(n log n) укладывается в эту оценку. Копия занимает O(n) памяти; результат учитывается отдельно и в худшем случае содержит O(n²) троек. Вход не меняется.

Нельзя вычислять int target = -nums[fixed]: для Integer.MIN_VALUE отрицание переполнится. Сумма трёх int помещается в long, если расширить до первого сложения. Ранний выход при положительном fixed корректен для нулевой цели: все следующие числа тогда положительны.
